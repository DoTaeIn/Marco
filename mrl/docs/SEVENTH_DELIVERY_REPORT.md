기존 Desktop/Marco 작업, engine.py, graph_inference.py, semantic_parser.py,

## 추가된 동작

- 지역 변수에 `Horn(...)` 지식 저장소를 만들고 실행 중 사실을 추가·철회한다.
- `ledger.add(Fact(...))`는 문자열 변수/함수 결과와 극성·양태를 받는다.
  `ledger.remove(id)`는 해당 입력 근거만 제거한다.
- 중복 ID 추가와 없는 ID 삭제는 false를 반환하고 버전을 유지한다.
  성공한 변경은 로컬 version을 한 번 증가시킨다. 제거한 ID는 다시 추가할 수 있다.
- `closure(ledger, ...)`와 `closure_with_provenance(ledger, ...)`는 현재 입력을 사용한다.
  새 사실이 만드는 새 결론과 부정 사실의 추가·제거가 다음 질의에 반영된다.
- 저장소를 대입하면 독립된 복사본이 된다. 이전 질의 결과는 당시 입력·요약·버전을
  보존한다. 다른 근거가 남아 있는 결론은 한 근거를 철회해도 유지된다.
- 기존 v2/v3/v4 프로그램은 유지하며, 새 연산은 IR v5로 독립 검증한다.

[실행 예제](../examples/knowledge_updates.mrl)는 사실 추가, 부정 사실에 의한 차단,
철회 후 복원, 이전 증명 결과 보존을 보여준다. 선언은 `=`, 기존 변수 재대입은
`:=`, 상수 선언은 `dec name = ...`이다. version은 각 값에 대한 로컬 번호이며
서로 다른 저장소를 전역적으로 식별하는 번호는 아니다.

## 구현 범위와 남은 작업

질의 요약은 생성할 때 한 번 계산한다. 전체 증명 JSON을 출력할 때는 보관된 입력으로
다시 계산한다. 고정 크기 값과 하나의 출력 작업 버퍼를 사용하므로 반복 횟수만큼
결과 버퍼를 계속 보관하지 않는다. 이 작업 버퍼는 현재 단일 스레드 실행을 전제로 한다.
재귀 깊이에 따른 일반 C 스택 사용은 남아 있다.

**추론은 여전히 전체 재계산이다.** 이번 결과는 재컴파일 없이 사실을 갱신하는 언어
계약과 올바른 결과 보존을 구현한 것이다. 실제 Marco 학습→오버레이→자연어 응답을
연결하거나 증분 추론을 구현한 결과가 아니다. 새로운 속도 향상 수치는 측정하지 않았다.

소스 Horn은 입력/결과 사실 64개, 단일 전제 규칙 32개, 사실당 증명 128개로 제한된다.
초기 계획·규칙·질의 예산·목표와 Evidence는 현재 리터럴 계약을 유지한다.
지역 Horn 값의 함수 인자/반환, 외부 입력 연결, 실행 중 규칙 편집, 다중 전제 조인,
증분 평가, 일반 컬렉션·enum·Result·수치 배열 등은 남아 있다. 전체 v0.1 완성을
주장하지 않는다. 자세한 계약은 [이번 계약](SEVENTH_DELIVERY_CONTRACT.md)을 따른다.
