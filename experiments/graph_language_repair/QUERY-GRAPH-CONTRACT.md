# Query graph contract (prototype v1)

A query program is language-neutral JSON. `version` is `query-graph-v1` and `alternatives` is a nonempty array. Each alternative has an `id`, a nonempty `patterns` array of three-string triples, and a `project` array of variables. Variables begin with `?`; all other atoms are exact graph terms. Shared variables express joins; chains of triples express property paths. A projected variable must occur in a pattern. `rules` is an optional array of native Horn rules (`id`, `head`, `body`, optional `version`), subject to the existing engine's limits and validation. Pattern predicates must be constants in this prototype.

An alternative may carry `scope` (`reading` only), `coverage` (`complete` or `partial`), `unresolved` (array), and `type_status` (`known` or `unknown`). These describe the compiler's evidence and do not supply facts. Unsupported scope, operator, predicates, or malformed programs produce an explicit hold. Partial coverage, unresolved descriptors, unknown required type, incomplete reading, or incomplete native search also hold. Empty successful results mean no evidence, never logical negation. Explicit negative occurrences must be represented by actual graph terms/relations provided by the reading; absence does not establish negation.

Execution creates a fresh internal Horn goal per alternative. For longer conjunctions, deterministic auxiliary Horn rules factor connected groups of up to four patterns, carrying every variable shared with the remaining patterns or projection. Up to 32 patterns are accepted; decomposition that cannot preserve correlations within two boundary variables holds explicitly. Each native rule body remains limited to four patterns and the native rule count remains limited to 16. The final head encodes up to two projected variables. This delegates joins and unification to native search; it does not mutate the reading. The complete native world, match bindings, proof bundles and source references are retained for every alternative, including rivals. The result is evidence, not an answer-selection decision. The original patterns and rules remain available for interpreting proof paths. Native limits, including rule-body, world and support caps, remain unchanged. A query requiring more than two projected variables or nonconstant predicates is explicitly unsupported in this prototype. Unknown fixed predicates are valid and yield no evidence when absent. Unknown type and unresolved descriptors retain structural candidate matches and proofs while the overall result holds. Distinct projected bindings are all retained; no first match is selected.

An interpretation requiring a particular verification witness must tie the outcome directly to the same checking event in its declared graph patterns, alongside accepted verification and applicable source and occurrence constraints. A target-level result does not identify which check produced it. A separate check cannot bless an unrelated target. Action/result, report/actual, and known/unknown type distinctions must be encoded in graph terms and compiler metadata, never inferred by the executor.

Proof closure is checked for every match support before evidence is confirmed. A missing or cyclic bundle, invalid dependency, mismatched conclusion, missing source row, or mismatched source details produces `provenance_incomplete` and retains the conditional match and world with diagnostics. Program-supplied Horn rules are untrusted question-program rules: when one appears on a proof path the match records `query_rule_dependencies` and `value_origin: derived_program_value`, and the overall result holds with `program_rule_derivation`. Sources establish the premises, not a document assertion of the derived head. Compiler-generated auxiliary and goal rules are transport, not program rules. This prototype has no trusted-model-rule input.

All atoms beginning with `?` are reserved for variables. Literal entities with that prefix cannot be represented without ambiguity in this version and must be rejected by the compiler; typed literal transport is future work. Ground patterns can be factored with zero boundary variables. Conservative factorization may still hold on unsupported query width even when another decomposition might exist.
