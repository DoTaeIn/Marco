# Teacher example schema v2

Datasets contain `examples` and `pairs`. Each example has unique `id`, `text`, `kind` (`passage` or `question`), and `graph`. `graph.nodes` contains unique `{id,type,anchor?}` objects; IDs are local and have no semantics. `anchor` is an optional `[start,end]` Unicode code-point span over the example text, indicating provenance only, never a surface equality constraint. `graph.edges` contains `[subject_id, predicate, object]`; object is either a node ID, `{"literal":string}` (semantic constant), or `{"copy":[start,end]}` (typed input-span copy term). Copy terms expressly require the literal text at that span; use them for named values. Do not encode names as semantic constants. `graph.edge_spans` is an optional array parallel to edges; each entry is an array of exact authored `[start,end]` spans that ground that edge. Missing edge evidence prevents native admission. Use the actual utterance span only when it really grounds an edge. Do not fabricate proof records. `graph.project` is an ordered array of zero to two node IDs; passage graphs use `[]`, question graphs explicitly list answer nodes. A projected node's anchor can locate a question word and imposes no condition on passage surfaces. All other question nodes are existential variables too; fixed values require explicit literal or copy terms in edges. Predicates, types and literal strings are opaque, exactly matched symbols. Distinct nodes stay distinct graph terms. Edge object typing is mandatory; strings denote node references only. Graphs contain all intended meaning including polarity/source and no extra edge. Spans and node IDs are not linguistic productions.

`pairs` are independently authored held-out checks, disjoint from grammar input. Each pair supplies `id`, `passage_id`, `question_id`, `expected_bindings` as ordered decoded surface tuples, and `perturbations` (subset of `person`,`role`,`negation`,`source`). Expected answers never enter candidate construction. The gate predicts passage and question graphs from text, checks exact authored graph equality, translates only the predicted graphs to native facts/program, calls the existing native executor, and checks exact expected tuples and authored grounding. The grammar learner must not read pairs. Missing grounding, ambiguity, unsupported native limits or incomplete search holds admission.

A minimal ASCII example (the names and predicate labels are examples, not rules):

```json
{"examples":[
 {"id":"p","kind":"passage","text":"A sees B","graph":{"nodes":[{"id":"e","type":"event","anchor":[2,6]},{"id":"a","type":"person","anchor":[0,1]},{"id":"b","type":"person","anchor":[7,8]}],"edges":[["e","actor","a"],["e","object","b"],["a","value",{"copy":[0,1]}],["b","value",{"copy":[7,8]}]],"edge_spans":[[[0,1],[2,6]],[[2,6],[7,8]],[[0,1]],[[7,8]]],"project":[]}},
 {"id":"q","kind":"question","text":"who sees B","graph":{"nodes":[{"id":"qe","type":"event","anchor":[4,8]},{"id":"x","type":"person","anchor":[0,3]},{"id":"y","type":"person","anchor":[9,10]}],"edges":[["qe","actor","x"],["qe","object","y"],["y","value",{"copy":[9,10]}]],"edge_spans":[[[0,3],[4,8]],[[4,8],[9,10]],[[9,10]]],"project":["x"]}}
],"pairs":[{"id":"p-q","passage_id":"p","question_id":"q","expected_bindings":[["A"]],"perturbations":["person"]}]}
```

Node types are exact graph constraints. A projected node must have one unambiguous surface value via a `value` edge to a copy term in the predicted passage; the question graph need not contain that edge. A question copy term is grounded in the question's own text, never from passage IDs or expected answers. This simple pilot holds when those structural requirements are not met. Training and dev IDs and text must be disjoint. Teacher examples contain no grammar productions, regexes, rules, or suggested implementations.

## Independent contrast manifest

A separate JSON `{"contrasts":[...]}` can be passed with `--contrasts`. It does not alter frozen examples or enter learning. Each record contains `id`, `category`, `base_pair_id`, `altered_pair_id`, and `query_predicates`: a nonempty list of exact query edge labels to ablate; each label must identify exactly one question edge. Both referenced pairs must pass native execution of their predicted graphs, have different passages and different expected tuples, and share the same question text and graph. For `person`, `predicate` identifies an input-copy edge whose values differ; for `role`, `predicates` lists two role edge labels whose node-value sets swap; for `negation`, `predicate` identifies a semantic-literal edge with a change; for `source`, `predicate` identifies an edge whose node-reference, copy or literal values change. Values are compared in their subject contexts so a swap counts as a change even when the global value set is unchanged.

The verifier removes only the declared query constraint edges in a formal graph probe, prunes disconnected orphan nodes, runs each predicted passage through the native executor, and requires additional proven answer bindings on both passages. This demonstrates that the specified constraint distinguishes the competing candidates; it is a formal counterfactual and does not reinterpret the original text. Category and predicate meanings require independent teacher review; the verifier cannot infer them from opaque labels. Missing contrast records, mismatches, search holds or missing proofs block final admission. Legacy paired examples with changed questions may instead use `variant_pair_id` and crossed no-evidence controls for negation/source; no-evidence is not proof of logical negation.
