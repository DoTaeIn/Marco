# 절 경계 공통화 — 2026-09-11

기준은 [목표와 구조](목표와-구조.md)다. 이번 변경은 그 문서의 첫 단계에
해당하는 **경계 탐색과 원문 보존**이다. 전체 한국어 활용 처리나 팩 v3 이전이
완료됐다는 뜻은 아니다.

## 바뀐 경로

- `encoder.split_fragments`와 `RelationalParser.parse`가
  `hangul.clause_spans`를 함께 쓴다. `encoder._sentence_splitter`와
  `relations.json`의 `clause_pattern`은 제거했다.
- 연결어미 후보와 제한된 종결형 복원 규칙은 `styles/한국어.json`의
  `문장분리`에 있다. 호출자가 빈 언어 설정을 주면 다른 파일의 한국어 규칙을
  가져오지 않는다. 파일로 읽는 경로의 캐시는 파일 수정 시각·크기를 따른다.
- 어미는 원문에 그대로 남긴다. `크고`를 `크`로 자르지 않는다.
  사실의 근거에는 원문의 시작·끝 위치와 함께, 복원했다면 규칙 ID와 해석에
  사용한 종결형도 남긴다. 원문을 종결형으로 덮어쓰지 않는다.
- 관계 파서는 앞 절 전체가 해석될 때만 연결 경계를 채택한다. `학교 창고
  물건` 같은 이름 속 `고`는 그것만으로 경계가 되지 않는다. 미해석된 나머지를
  버리고 아는 부분만으로 답하지 않는다.
- `꺼내고`를 위한 무조건적인 `고` 삭제는 하지 않는다. 그러면 `크다고`까지
  사실이 되는 문제가 검증에서 드러났다. 어간형으로 주석된 예제에만 생략형
  규칙을 적용한다. 평서형·질문·조건·인용을 서로 같은 것으로 처리하지 않는다.
- 잘린 예제 `하루는 모래보다 키가 크`를 제거했다. 예제는 43→42개다.
  새 이름·숫자나 연결형마다 예제를 추가하지 않았다. 새로 배운 서술어도 기존
  어미 규칙을 적용받는 전이 검사를 추가했다.

`hangul.verb_ends`는 확인 결과 문장 분리기가 아니라 `engine._looks_noun`의
명사 후보 제거용 휴리스틱이다. 이름을 바꿔 같은 함수로 묶으면 역할이 달라진다.
이번에는 그대로 두었다. `input_understanding.split_segments`의 입력 목적 분리도
별도로 남아 있다. 모든 언어 처리가 통합됐다고 주장하지 않는다.

## 아직 남은 것

1. 자모 규칙에 기반한 활용 처리. `있었는데`의 경계를 찾는 것과 그 과거형을
   이해하는 것은 다르다. 현재 `사과가 23개 있었는데 8개를 꺼냈어`는 분리
   후보를 찾지만 전체 의미 해석은 못 한다. 어순·조사·시제 문제도 함께 남는다.
2. 검색 조각의 문맥 손실과 명사/서술어 구별. 접미사나 자모만으로 문법적
   역할·조건·인용을 확정해서는 안 된다.
3. 언어·공리·지식의 팩 이전 및 실제 대화 경로의 주입. 새 절 설정은 언어팩
   파일에 있지만, UI는 아직 로컬 기본 설정을 읽으며 기존 관계 자료·말로 쓴
   식·출력 지시는 코드 옆에 남아 있다. **팩 하나로 완결되는 상태는 아니다.**
4. 공리팩 배치, 웹 전환 정책, 두 추론 경로 통합은 사용자가 아직 정하지 않은
   설계 선택이다. 이번 변경에서 확정하지 않았다.
