# 양방향 포함도 점수 변경

2026-09-09. 사용자 승인에 따라 `engine.match`와 `_sparse_score`에 같은 별칭의
양방향 포함도 기하평균을 적용했다. 부호 해시의 음수 겹침은 0으로 자른 후 곱한다.
별칭마다 결합하고 그 최댓값을 취한다. 서로 다른 별칭의 최고점을 곱하지 않는다.
문턱값과 고정 평가 문항은 변경하지 않았다.

## 고정 잣대 결과

현재 작업트리에서 HEAD 엔진과 변경 엔진을 각각 실행해 비교했다.
`data/benchmarks/고정물음.json` SHA-256:
`f25996e58cc726a8172636026f519a39c24c635b663578902eb9aab5f5fcf436`.

| 라우팅 대조 | 368/400 | 375/400 |
| 라우팅 뺀 별칭 | 86/400 (21.5%) | 124/400 (31.0%) |
| 라우팅 뺀 별칭 상위 3개 | 150/400 | 201/400 |
| 노드 대조 | 395/400 | 399/400 |

| 밖 거절 | 23/24 | 24/24 |

초기 기하평균만 적용한 실험의 라우팅 126/400과 구분한다. 표는 회귀 보완까지
반영한 최종 구현의 재측정이다. 끝에서 끝까지 답변 정확도를 이 표로 주장하지 않는다.

## 메모리와 호환성

- 라우터는 이미 보유한 역방향 희소 벡터를 재사용한다.
- 새로 만든 역방향 존재 벡터는 값이 -1, 0, 1이므로 정확한 int8로 저장한다.
  역방향 노드 행렬은 float32 대비 25% 공간을 쓴다. 전체 프로세스 메모리의
  75%가 줄어든다는 의미는 아니다.
- 기존 캐시와 kgbin 형식은 그대로 읽는다. 기존 파일의 저장 형식은 자동으로
  다시 압축하지 않는다. 역방향이 없는 설명 색인은 기존 단방향 점수를 유지한다.
- 노드 행렬이 교체되면 역방향 캐시도 갱신한다. 신경망의 대칭 코사인 경로는 유지한다.
- 역방향 내적은 질문 벡터의 0이 아닌 열만 계산해, 전체 int8 행렬을 매번
  float32로 펼치는 비용을 줄인다.

## 함께 확인한 회귀

점수 변경으로 자체 검사의 두 경계가 드러났다.

1. 목표와 닮은 정도를 검사하기 전에 명시적 증거의 근거 연결을 먼저 처리한다.
   근거가 없는 목표 주장에는 기존 단방향 덮임 요건도 유지한다. 문턱은 동일하다.
2. 색인에 문자 그대로 등장하는 대문자 약어는 명칭 조회로 처리한다. 어떤 약어가
   있는지는 색인에서 읽으며 DNS·HTTP 같은 개별 단어를 조건문에 넣지 않는다.

검사: `tests/test_geometric_matching.py` 7개 통과, `engine.py --regress` 6/6,
`kgbin.py --자가검사` 통과. 수학적 양방향 점수 일치, 빈 희소 행, 부호 충돌,
벡터 교체, kgbin 왕복, 증거 있는 긴 질문과 범위 밖 질문을 검사한다.

자체 검사의 반격 대사 항목은 별도 조정했다. 이전에는 임계값을 0.40/0.50으로
강제로 바꾸고 특정 바꿔 말하기를 통과시켜 반격을 검사했다. 점수 방식에 종속된
이 준비 과정을 없애고 노드의 원문 별칭으로 반격 기능을 검사한다. 실제 판정의
임계값과 고정 잣대는 바꾸지 않았다. 원래 바꿔 말한 그 문장은 변경 후 되묻기(A)가
될 수 있다는 제한도 남긴다.
