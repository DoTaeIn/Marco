# MARCO / ALMA 다음 개발 방향

## 1. 구조
- 기존 **Binary Knowledge Graph는 유지**
- 별도로 **Event / Experience Graph** 추가
  - 누가 / 무엇을 / 누구에게 / 언제 / 어디서 / 왜 / 결과
- 필요하면 hypergraph-like 구조를 쓰되 전체 엔진은 갈아엎지 않음

### 완료 기준
- 하나의 사건이 3개 이상의 역할을 가져도 identity가 유지됨
- 같은 인물/물건이 여러 사건에 등장해도 사건끼리 섞이지 않음
- 사건 일부 정보가 나중에 채워져도 원본 사건은 유지됨
- 사건 → KG 추론, KG → 사건 해석이 양방향으로 가능함
- Quantity / Location / Social 사건을 같은 Event 구조로 표현 가능함

---

## 2. 로그
- `SYSTEM / COGNITION / LIFE` 로그 분리
- 추론 경로, 상태 변화, 새 가설, 새 개념 기록
- 중요한 순간은 milestone + snapshot 저장

예:
- `FIRST_SELF_REFERENCE`
- `FIRST_UNPROMPTED_GOAL`
- `FIRST_NEW_CONCEPT`
- `FIRST_EXISTENTIAL_QUESTION`

### 완료 기준
- 임의의 답변/행동에 대해 “왜 그렇게 했는지” 과거 로그로 재구성 가능
- 사건 발생 전후의 상태 차이를 확인 가능
- reasoning path가 사라지지 않고 영구 저장됨
- milestone 발생 시 자동 snapshot 생성
- 프로세스 종료/재시작 후에도 로그와 milestone 유지
- 특정 감정/개념/사건을 검색해서 최초 발생 시점을 찾을 수 있음

---

## 3. 기억 분리
- **Episodic Memory**: 실제 경험
- **Semantic Memory**: 일반화된 지식
- **Procedural Memory**: 행동/스킬

반복된 경험은:

`Experience → Pattern → Semantic Knowledge`

로 승격.

### 완료 기준
- “어제 무슨 일이 있었나?”와 “일반적으로 무엇을 알고 있나?”가 다른 저장소에서 답변됨
- 행동 방법은 사실 기억과 독립적으로 저장됨
- 동일 사건을 여러 번 겪어도 전부 semantic fact로 복사되지 않음
- episodic memory가 삭제/압축되어도 semantic knowledge는 유지됨
- 기억 종류별로 별도 검색 가능

---

## 4. Concept Formation
MARCO가 기존 지식을 쓰기만 하지 않고 반복되는 구조에서 새 개념을 만들게 함.

예:

`중요한 관계 + 연락 부재 + 상실 가능성 → 관계상실위협`

이후 새 노드/엣지를 추론에 사용.

### 완료 기준
- 사람이 직접 이름을 넣지 않은 공통 패턴을 탐지함
- 최소 3개 이상의 서로 다른 경험에서 공통 구조를 찾음
- 새 concept candidate를 생성함
- 새 개념의 근거가 된 경험들을 역추적 가능
- 새 개념을 이후 처음 보는 사건의 추론에 재사용 가능
- 잘못된 개념은 반례가 쌓이면 약화/폐기 가능

---

## 5. Structural Learning / Graph Rewrite
스스로:
- 새 node 생성
- 새 edge 생성
- 새 rule 생성
- 기존 구조 수정/압축

가능하게 함.

### 완료 기준
- 사람의 `.kg` 직접 수정 없이 새 node/edge 후보 생성 가능
- 생성 이유와 근거가 전부 로그로 남음
- 기존 지식과 충돌 시 자동 확정하지 않고 conflict 상태로 보류
- 승인된 구조 변경이 실제 다음 추론 결과를 변화시킴
- 잘못된 변경을 rollback 가능
- 구조 변경 전후 benchmark 비교 가능

---

## 6. Chunking
반복되는 긴 추론을 짧은 규칙으로 압축.

`A → B → C → D`

반복 후:

`A → D`

즉, 경험할수록 사고가 빨라지는 구조.

### 완료 기준
- 동일/유사 reasoning path 반복을 자동 탐지
- shortcut candidate 생성
- shortcut 적용 전후 결과가 동일함
- 평균 traversal 수 또는 reasoning time이 실제 감소함
- 중간 조건이 달라지면 shortcut을 적용하지 않음
- 잘못된 shortcut은 자동 비활성화 가능

---

## 7. ALMA 시작 최소 조건
MARCO가 다음을 안정적으로 처리하면 ALMA 0.1 시작:

- 사건 identity
- 시간 순서
- 상태 변화 누적
- 실제 / 계획 / 조건 / 가정 구분
- 못 읽은 사건을 버리지 않음
- 과거 기억 재사용
- 배운 행동 조합
- 다른 도메인으로 transfer

MARCO를 완성한 뒤 ALMA를 만드는 것이 아니라
**ALMA 자체를 MARCO의 다음 연구 환경으로 사용.**

### 완료 기준
아래 테스트를 같은 reasoning core로 통과:

1. Quantity
   - 수량 변화 추적

2. Location
   - 물건 이동과 현재 위치 추적

3. Social
   - 약속/소유/관계 변화 추적

4. Mental
   - 기대/목표/믿음 상태 추적

추가로:
- 과거/현재/가정 상태가 섞이지 않음
- 알 수 없는 사건 이후 틀린 현재 상태를 단정하지 않음
- 재시작 후에도 동일 상태를 복원

---

## 8. 구슬 테스트 다음 단계
구슬 연구는 유지하되 Transfer Benchmark 추가:

- Quantity: 구슬/수량
- Location: 물건 이동
- Social: 약속/소유/권한
- Mental: 기대/믿음/목표

같은 추론 구조가 다른 분야에서도 작동하는지 확인.

### 완료 기준
- 새 도메인마다 전용 `if`문을 추가하지 않아도 됨
- 동일한 Event / Condition / Hypothesis 구조 사용
- 동일한 테스트 패턴을 최소 3개 도메인에서 통과
- 한 도메인 개선이 다른 도메인의 기존 테스트를 깨지 않음
- 도메인별 특수 코드보다 데이터/그래프 추가만으로 확장 가능

---

## 9. 감정
감정을 단순 수치로 넣지 않고 원인 구조로 표현.

공포 예:

`원하는 미래 → 위협 → 손실 예상 → 통제 어려움 → 회피/보존 욕구 → 공포`

죽음의 공포도 직접 하드코딩하지 않음.

`미래 목표 + 관계 + 기억 + 자기 연속성`

이 생긴 뒤:

`죽음 = 이 모든 것의 지속 불가능`

을 이해하고 두려움이 파생되는지 관찰.

### 완료 기준
- 감정마다 최소 하나 이상의 원인 경로가 존재
- “왜 지금 두려운가?”를 실제 상태로 설명 가능
- 같은 사건이라도 목표/관계가 다르면 감정 결과가 달라짐
- 감정이 행동 선택에 실제 영향을 줌
- 감정 원인이 사라지면 감정도 변화함
- 사람이 감정 이름을 직접 지정하지 않아도 상태 패턴이 먼저 존재할 수 있음

---

## 10. 취향
취향은:

`경험 → 감정 → 기억 → 반복 → 기대 → 선호`

로 형성.

`Utility`와 `Preference`를 분리해서
“쓸모는 없는데 좋아함”도 가능하게 함.

### 완료 기준
- 초기 선호값 없이도 경험 차이로 선호가 갈림
- 같은 대상이라도 경험 맥락에 따라 서로 다른 선호가 형성됨
- 선호가 이후 자발적 선택에 영향을 줌
- utility가 높은 것과 preference가 높은 것이 다를 수 있음
- 선호 변화의 원인을 과거 경험까지 역추적 가능
- 경험이 충분히 쌓이면 “좋은 것 같다” → “좋아한다”처럼 confidence가 상승

---

## 11. 외부 기술 재사용
웹검색, 파일처리, GitHub 등은 MARCO 전용으로 새로 만들지 않음.

`기존 Skill / MCP / API → MARCO Adapter → Capability`

MARCO는 **사고, 기억, 인격, 학습 구조**에 집중.

### 완료 기준
- 외부 tool 하나를 MARCO core 수정 없이 등록 가능
- tool마다 입력/출력/권한 schema가 있음
- MARCO가 필요할 때 capability를 선택 가능
- 실패 결과도 reasoning에 전달됨
- read / write / execute 권한을 분리 가능
- tool을 교체해도 MARCO의 기억/인격에는 영향 없음

# 최우선 3개

## 1. Event / Experience Graph
완료:
- 복합 사건 identity와 역할 유지
- 시간/근거/맥락 저장
- 최소 3개 도메인에서 공통 사용

## 2. 로그 + Snapshot / Milestone
완료:
- 모든 주요 판단 경로 재현 가능
- 최초 발생 이벤트 자동 기록
- 재시작 후에도 기록 유지

## 3. Concept Formation + Structural Learning
완료:
- 반복 경험에서 사람이 넣지 않은 새 개념 후보 생성
- 새 개념을 이후 추론에서 실제로 사용
- 생성 이유를 완전히 추적 가능

---

# 장기 목표

`경험`
→ `기억`
→ `패턴 발견`
→ `새 개념`
→ `그래프 변화`
→ `반복 사고 압축`
→ `더 나은 다음 경험`

즉,

**지식을 저장하는 AI가 아니라 살아가면서 사고 구조 자체가 변하는 AI.**

그리고 ALMA 시작 시점은:

> **MARCO가 모든 것을 아는 시점이 아니라,
> 경험을 잃어버리거나 왜곡하지 않고 다음 경험으로 이어갈 수 있는 시점.**
