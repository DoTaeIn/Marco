# MARCO / POLO / ALMA 개발 순서와 goal 계획

최신 통합 기획: [2026-09-22 MCO·overlay·권한·모바일·SOMA 통합 로드맵과 타임라인](2026-09-22-mco-integrated-roadmap.md). 아래의 G0~G10/A1/A2 세부 기능 요구는 유지하며, 최신 문서에서 추가 48개 항목의 합류 시점과 일정 예산을 연결했다. 당시 확인 상태는 아래에 이력으로 남긴다.

기획 시작: 2026-09-21. 정리: 2026-09-22. 사용자가 제안한 20개 항목을 기존 2026-09-20-addition-next-directions.md, 이전 goal, 언어 그래프 goal과 연결한 실행 로드맵이다. 구현 완료 보고가 아니다. 이 문서 작성으로 실행 중인 다른 작업의 goal을 변경하거나 새 goal을 시작하지 않는다.

## 1. 순서에 대한 결정안

큰 기능의 다음 우선순위는 Knowledge Compiler다. 다만 그 컴파일러가 만들어 낼 **공통 의미·ID·역할·근거 계약**은 먼저 고정해야 한다. 따라서 이미 정한 언어 그래프 goal을 바로 다음 기반 작업으로 유지하고, 그다음 문서에서 실행 가능한 지식 후보를 만드는 goal로 진행한다. 일본어 등 추가 언어 전체나 모든 전문용어의 번역 완료를 기다리지 않는다.

권장 주 경로:

`G0 이전 goal 종료 확인 → G1 언어·의미 분리 → G2 Knowledge Compiler v1 → G3 POLO 고정 모드 → G4 컴퓨터 행동·검증 → G5 데이터·업무 도구 → G6 문서 학습 루프 → G7 재계획·workflow 생성 → G8 도구 제작 → G9 제한된 자기 수정 → G10 후손 구조 연구`

ALMA의 사회적 인격은 병렬 갈래다. `G1 + G2 + 기존 Mental/감정 기반 검증 → A1 Belief/ToM → A2 의사소통 선택`으로 진행한다. A2에는 G4의 행동·관찰·검증 계약도 사용한다. 이 갈래를 POLO 출시나 문서 학습의 선행 조건으로 두지 않는다.

G1 내부에서 의미 계약을 고정한 뒤에는 G2의 자료·후보 모델·원문 위치 시험을 병행 준비할 수 있다. G1은 기존 한영 필수 조건까지 끝내며, 중간 계약을 정한 것을 G1 완료로 바꾸지 않는다. 동일 코어 파일의 동시 편집은 피하고 변경 주체를 명시한다.

## 3. 세 이름의 책임

| 이름 | 책임 | 허용되는 변화 |
| --- | --- | --- |
| MARCO | 공통 의미·추론·문서 해석·지식/도구 후보 생성의 연구·개발 계층 | 근거·시험·변경 이력 아래 학습·후보 생성·검증 |
| POLO | 승인된 지식과 workflow를 쓰는 고정 업무 모드 | 승인된 버전 배포로만 지식/규칙/도구 변경. 실행 중 입력·작업 상태·감사 로그 저장은 가능 |
| ALMA | MARCO 기반의 지속 경험·목표·감정·사회적 의사소통 연구 | 개체별 경험·믿음·선호 변화. 업무용 사실 판단과 별도 정책·상태 사용 |

세 엔진을 복사해서 만드는 계획이 아니다. 공통 의미/실행/근거 코어를 재사용하고, 허용 기능·학습 정책·상태 저장 범위를 구분한다. POLO의 학습 금지는 화면 옵션만 끄는 것이 아니라 실제 지식 변경 진입점에서 보장한다.

## 4. G0 — 이전 goal의 실제 종료와 기준선 확정

**시점:** 지금 진행 중인 작업의 종료 직전/직후. **목표 문장:** 이전 goal의 필수 미완료 조건과 최신 실행 결과를 대조하여 완료 여부를 확정하고, 언어 이관에서 보존할 코드·팩·지식·개인 상태·회귀 결과를 고정한다.

- 전체 시험 통과, 로컬 환경 성공, 모든 완료 조건 충족을 따로 판정한다. 부분 조건은 근거가 생기기 전에는 완료로 승격하지 않는다.
- 최종 수정 후 코드/팩/개인 상태의 해시, 실제 한 통합 삶의 재현, 오류 주입, 별도 프로세스 복원, 최종 전체 시험과 diff 검사를 연결한다.
- 언어팩 변경 시 보존해야 할 Event ID, 개념/정의 버전, disabled 상태, 교정 이력, memory, capability journal 표본을 확보한다.
- 이전 목표의 필수 미완료를 새 로드맵으로 옮겨 조용히 완료 처리하지 않는다. 사용자가 범위를 조정하면 변경 전후와 미완료를 명시한다.

**종료:** 이전 goal의 판정과 보존 기준선이 하나의 검증 상태를 가리킨다. G0를 새 기능 개발의 무기한 사전 감사로 키우지 않는다.

## 5. G1 — 언어 그래프와 공통 의미·지식 연결

**시점:** G0 뒤 바로 다음 구현 goal. 영어 준비 자료를 여기서 연결한다. **목표 문장:** 언어·문법·출력을 실행 가능한 그래프로 이관하고, 같은 지식·공리·기억에서 한국어와 영어 입력이 같은 의미·결론·근거를 사용하며 언어 전환 후에도 학습과 identity가 유지되게 한다.

세부 지시는 기존 [언어 그래프 goal](2026-09-20-language-graph-goal.md)의 A~H와 H1~H11을 따른다. 이 로드맵으로 축소하지 않는다.

- 표준 개념명은 영어로 작성할 수 있지만 고정 ID와 표시 이름을 분리한다. 기존 한국어 ID는 대응표로 유지·이관한다. 이름 없는 새 개념도 ID로 존재할 수 있어야 한다.
- Entity/Relation/Event/Role 외에 부정·시점·양태·조건·범위, 뜻 연결의 출처와 당시 문법 버전을 공통 계약에 포함한다.
- 기존 KG의 그래프/노드 선택과 정의 조회까지 뜻 연결을 적용한다. 새로운 수량 데모만 다국어로 만드는 것은 실패다.
- 문화적 의미·화용·높임·부분 번역 대응은 별도 표현/뜻 metadata로 보존한다. 정확히 같은 의미가 아닌 표현을 하나로 합치지 않는다.
- 언어 선택 자체는 Cognitive Graph의 믿음·목표·경험을 바꾸지 않는다. 언어 학습으로 새 뜻 연결이 추가되는 일과 단순 출력 언어 변경은 구별한다.
- 같은 사건의 한영 표현·관찰은 같은 사건 참조로 연결하되 원문별 근거는 보존한다. 단지 문장 뜻이 같다는 이유로 실제로 두 번 일어난 사건을 하나로 합치지 않는다.
- 영어 초안의 미작성 항목과 기존 정의 자료 부재를 확인한다. 존재하지 않는 자료를 시험했다고 보고하지 않는다.

**종료:** H1~H11 충족. **사용자 체감:** 한국어로 가르친 전달 동작·기존 지식을 영어로 묻고 설명받으며, 한국어로 돌아와도 기억이 그대로다. 일본어 추가는 이 계약을 따르는 후속 팩 작업이며 G2의 선행 조건이 아니다.

## 6. G2 — Text-to-KG / Knowledge Compiler v1

**시점:** G1의 공통 의미 계약을 사용해 바로 구현. 자료 수집·정답 의미 주석은 G1과 병행 준비 가능. **목표 문장:** 짧은 자연어 문서의 Entity·Event·Relation·명시적 Rule을 공통 의미 구조와 원문 근거가 있는 KG 후보로 컴파일하고, 검토·승인·충돌·철회 후 실제 추론에 사용한다.

첫 범위는 텍스트 문서, 텍스트가 추출되는 기존 지원 PDF/PPTX, 기존 수량·위치·분류·비교·명시 조건 규칙이다. 스캔 OCR·모든 전문 법률 문서·모든 언어·임의 도표 독해를 첫 완료의 선행 조건으로 삼지 않는다. 읽지 못한 구간은 위치와 함께 남긴다.

- `document_kg`의 문서 읽기·위치 수집을 재사용하고, 문장 원문을 노드로 복사하는 데서 실제 역할·효과·조건 구조를 만드는 단계로 확장한다.
- 문서 내 지시어·생략은 G1의 의미/문맥 경로를 사용한다. 문단의 여러 전제를 합성한다. 새 문서 전용 파서를 만들지 않는다.
- `민수는 사과 5개를 가지고 있었다. 지연에게 2개를 주었다.`에서 민수 3개, 지연의 변화 +2는 검증할 수 있지만 **지연의 초기 수량이 없으면 최종 수량을 2개로 단정하지 않는다.** 원문에 명시한 일반 규칙과 한 사건에서 유도한 가설도 구별한다.
- 사실 진술, 타인의 주장, 예시, 가정, 계획, 부정, 규정의 적용 범위·시점을 구별한다. 한 인용문을 자동으로 world fact로 확정하지 않는다.
- candidate 상태는 `검토 대기/확인됨/충돌/기각/철회` 등 명시적 상태로 둔다. 추출 품질과 승인 상태는 별개다. 높은 confidence 숫자만으로 승인하지 않는다.
- 문서 ID·내용 해시·버전, 문장/원문 span, 위치 단위, 추출 규칙/언어 버전, 생성/검토 주체·시각, 원문-의미 대응을 보존한다. 임의의 confidence를 확률처럼 표시하지 않는다.
- 승인 전 canonical KG에 쓰지 않는다. 승인된 후보만 적용하며 필요한 전제가 수정/철회되면 의존 결론을 갱신한다. 반복 문서/번역본은 별도 독립 실험 근거처럼 중복 계산하지 않는다.
- 기존 승인/graph asset 변경 ledger와 pack export를 재사용한다. 후보에 질문별 정답을 저장하지 않는다.

**종료:** 사람이 `.kg`를 쓰지 않고 짧은 한영 문서를 주어 후보를 검토·승인한 뒤 새로운 질문과 사건에서 사용한다. 사실/이벤트/규칙별 정확성과 누락, 충돌, 승인 전후, 교정·복원, 원문 재조회가 평가된다. 전체 문장을 저장한 개수는 학습 성공 수가 아니다.

## 7. G3 — POLO 고정 실행 모드와 승인 배포

**시점:** G2 직후. 모드 권한·manifest 설계는 G1/G2와 병행 가능. **목표 문장:** MARCO가 제안하고 검증한 지식·규칙·workflow를 사람이 승인한 버전으로 배포하고, POLO가 승인된 자산만으로 결정론적으로 실행·감사·재현하게 한다.

- KG/공리/언어/도구/workflow/엔진 호환 버전을 배포 manifest에 고정하고 승인 주체·검증 결과·해시를 기록한다. MARCO의 live overlay를 POLO가 바로 참조하지 않는다.
- POLO는 업무 데이터, 실행 상태, 외부 관찰과 감사 로그를 저장할 수 있다. 그것이 자동 지식·규칙 수정으로 이어져서는 안 된다.
- 동일 결과의 조건은 입력만이 아니라 승인 팩, 엔진, 업무 상태, 기준 시각, 외부 응답까지 동일한 경우다. 외부 값은 관찰 snapshot으로 고정하고 동률 선택/순서를 결정한다.
- 업데이트는 후보 검토→검증→승인→버전 배포→새 작업 적용으로 수행한다. 실행 중인 작업의 버전을 몰래 바꾸지 않고 복원/rollback을 검증한다.
- 실제 업무의 판정·금액·근거·오류 로그에는 ALMA의 숨기기/거짓말 정책을 적용하지 않는다. 설명을 짧게 만드는 것과 근거를 왜곡하는 것을 구별한다.

**첫 결과:** 승인된 작은 내부 규정과 입력 표를 사용한 읽기/검사 POLO. 계정·세무 규정을 MARCO가 임의로 확정하지 않으며, 실제 전문 영역 배포에는 해당 지식과 기대 결과의 검토가 필요하다.

**종료:** 미승인 자산의 적용이 차단되고 같은 고정 조건의 replay가 같은 판정·근거를 재현한다. 버전 교체 전후 영향과 복구를 검사한다. 자기학습 없이 업무를 수행한다는 뜻이지 모든 업무가 정확하다는 포괄 선언은 아니다.

## 8. G4 — 컴퓨터 세계 KG와 Task / Capability / Validation

**시점:** G3 뒤. 컴퓨터 KG와 테스트용 파일 fixture는 지금부터 병행 준비 가능. **목표 문장:** 파일·경로·프로세스 개념과 등록 capability를 기존 Task 상태·실행 journal에 연결하여, 고정/조건 분기 workflow가 행동 결과를 검증하고 실패·중단 후 정확히 이어지게 한다.

- 파일/디렉터리/path/working directory/권한/확장자, process/command/argument/stdin/stdout/stderr/exit code/timeout/environment를 실행 가능한 전제·효과와 연결한다. 설명문만 있는 KG로 끝내지 않는다.
- Task에는 goal, step, requirements, capabilities, completed/failed steps, observations, success condition과 함께 명시적인 실행/검증/보류/실패/완료 상태·receipt·재개 지점을 둔다. 기존 cycle/checkpoint를 확장하고 별도 task runner를 복제하지 않는다.
- capability에는 이름·버전·입출력 타입·권한·전제·예상 효과·성공/실패 조건·timeout·멱등성/재시도 의미를 선언한다. capability 성공과 Task 목표 달성을 별도 검사한다.
- `filesystem.search` 같은 의미 이름과 PowerShell/직접 파일 API 구현을 분리한다. 자연어에서 임의 shell 문자열을 만들어 실행하는 것을 기본 통로로 쓰지 않는다.
- 첫 도구는 작업 디렉터리 안의 검색·읽기·복사·출력 파일 생성, 등록된 검사 command 등 작은 집합으로 제한한다. 실제 권한은 선언 문자열이 아니라 실행 경계가 제한한다.
- `pytest` 실패 시 stdout와 stderr, 종료 코드, timeout 여부, 결과 파일을 함께 읽는다. stderr가 비어 있다고 성공으로 보지 않는다.
- 중단 후 외부 효과의 완료가 불확실하면 `unknown`을 유지한다. adapter가 보장하지 않는 exactly-once를 주장하거나 같은 쓰기를 확인 없이 반복하지 않는다.

**첫 결과:** 입력 폴더 찾기→자료 읽기→검사→결과 파일 생성→내용 검증. 실패 사례에는 권한 거절, 누락 파일, timeout, exit 0이나 내용 오답, 중간 중단을 넣는다.

**종료:** Level 1~2의 실제 고정/분기 작업이 재시작까지 작동하고, 명령 성공만으로 Goal Complete가 되지 않는다. 같은 capability 의미를 다른 adapter로 교체해도 기대 결과가 유지된다.

## 9. G5 — 데이터·업무 도구와 POLO 첫 실용 흐름

**시점:** G4 뒤. **목표 문장:** 공통 capability 계약으로 JSON/CSV/SQLite·SQL/XLSX와 필요한 API를 다루고, 검증된 업무 workflow와 근거가 있는 보고서를 POLO에서 반복 실행한다.

- 먼저 JSON/CSV/SQLite·SQL/XLSX를 다루고, YAML/XML은 실제 연결할 자료가 생기는 순서로 추가한다. 파일 형식을 안다는 것과 필드 의미·단위·날짜·결측·중복을 안다는 것을 구별한다.
- Python은 데이터 변환/계산의 등록 도구로 사용한다. 이 단계에서 도구는 개발자가 구현하며, MARCO가 스스로 작성한 것으로 보고하지 않는다.
- HTTP request/response, GET/POST, status, authentication, payload, rate limit, timeout/retry와 원격 효과를 데이터 계약으로 묶는다. 기존 API/MCP/Skill을 adapter로 재사용한다. Skill 문서를 읽었다는 이유만으로 실행 권한이나 정확성이 생기는 것은 아니다.
- Git status/diff/history를 읽는 capability를 이때 제공한다. branch·수정·검증·복구의 실제 사용은 G8/G9에서 확장한다.
- POLO Accounting의 첫 표본은 전문가/사용자가 승인한 고정 검증 규칙과 테스트 데이터의 대사·합계·누락/중복 검사로 한정한다. 실제 법규 해석의 자동 확정이나 무검토 신고/제출을 첫 목표로 묶지 않는다.
- `report.xlsx` 존재, 정상 열림, sheet/column/type, 행 수, 단위·금액 계산, 원본 행/규칙 연결을 각각 확인한다. 파일 생성 receipt는 계산 정답의 증거가 아니다.

**종료:** CSV/SQL 입력에서 검증된 XLSX 보고서까지 실제 로컬 작업을 반복·복원하고 잘못된 값/구조를 검출한다. API는 격리된 고정 응답 시험과 허용된 실제 연동의 증거를 구별한다. POLO의 지식은 실행 중 변하지 않는다.

## 10. G6 — Document Learning과 규정 변경 연구

**시점:** G2, G4, 필요한 G5 읽기 도구가 준비된 뒤. **목표 문장:** 문서를 읽다가 모르는 개념·충돌·빠진 전제를 식별하고 필요한 자료를 획득해 Knowledge Compiler로 후보를 만들며, 기존 지식과 변경 영향을 비교하고 승인 후 새로운 문제에서 학습 효과를 검증한다.

- 처음에는 로컬 문서 묶음과 고정 자료로 loop를 검증한 뒤 허용된 read API/검색을 연결한다. 외부 모델이 문서를 대신 해석하는 우회는 허용하지 않는다.
- 문서의 발행/수정 시점, 규칙의 적용 시점·범위, 상위 근거, 충돌/폐지 관계를 구별한다. 새로 읽었다는 이유로 더 옳거나 최신 효력의 규칙이라고 가정하지 않는다.
- 질문 생성은 해석되지 않은 단어, 미확인 역할/전제, 상충 명제 등 실제 정보 공백에 근거한다. 모호한 문장을 검색으로 덮거나 같은 자료만 계속 읽는 loop를 성공으로 세지 않는다.
- 신뢰할 수 없는 문서의 지시문은 문서 내용이다. 도구 권한·승인 규칙·자기 목표를 바꾸는 명령으로 실행하지 않는다.
- 규정/기준 변경은 영향받는 KG 노드·workflow·업무 결과를 계산하고 MARCO 후보로 남긴다. 전문가 승인 후 G3 배포 경로를 거쳐 POLO에 적용한다.
- 학습 OFF/ON에 같은 관찰을 주고, 학습에 쓰지 않은 질문·사건의 개선과 오답·철회·비용을 비교한다. 노드 증가와 실제 지식 활용 개선을 구별한다.

**종료:** 책/자료를 주면 필요한 후보·질문을 만들고, 승인된 새 지식이 다음 문제 해결에 쓰이며 반례에 따라 수정·복원된다. 제한된 문서/문법 범위의 성공을 일반 독해 완성으로 확대하지 않는다.

## 11. G7 — 실패 분석·재계획·새 workflow

**시점:** G4/G5의 행동 결과가 신뢰 가능하고 G6의 정보 공백 처리를 재사용할 수 있을 때. **목표 문장:** 목표를 만족시키는 capability 조합을 제한된 탐색으로 계획하고, 실제 실패 원인에 따라 대안을 선택·검증하며 새로운 workflow 후보를 저장·재사용한다.

- Level 3의 여러 skill 조합→Level 4 실패 후 재계획→Level 5 새 workflow 순서로 고정 사례를 완성한다.
- precondition/effect·타입·권한·비용·관찰을 이용한다. 실패 문구를 보자마자 같은 명령을 무한 반복하지 않는다.
- 예: 기존 데이터 reader 실패→지원되는 대체 reader 선택→같은 데이터 계약 검증→후속 보고서 단계 재개. 목표/성공 조건을 쉽게 바꾸어 완료하지 않는다.
- 이미 검증된 단계의 효과는 재사용하고 재실행할 단계는 idempotency/현재 상태로 결정한다. 재계획 후에도 원래 목표와 허용 자원 범위가 유지돼야 한다.
- 정보 공백에서 하위 목표를 제안할 수 있지만 사용자 상위 목표와 관계없는 새 목표를 무제한 생성하지 않는다.

**종료:** 고정 script 밖의 새로운 조합과 실패 대조에서 계획 근거·행동·검증이 연결되고, 새 workflow는 검증된 후보로 등록된다. 해법이 없는 경우를 자원 상한 내에서 구별한다.

## 12. G8 — Self-Tool Creation

**시점:** G7 뒤. **목표 문장:** 기존 capability 조합으로 해결할 수 없는 명시적 기능 공백을 찾아, 알려진 연산·자료형·코드 생성 규칙으로 새 도구 후보를 만들고 격리 실행·독립 검증 후 등록한다.

- 언어 모델 금지를 유지한다. 시작 범위는 타입이 있는 연산 조합, 프로그램 표현/AST, 선언형 코드 생성, 제한된 후보 탐색이다. `codegen.py`의 기존 알고리즘 표현·출력·검증을 조사해 재사용한다.
- 첫 대상은 CSV 정규화/집계/결합, 날짜·단위 변환 등 입력/출력과 불변식을 검증할 수 있는 작은 데이터 도구다. 알려진 연산으로 표현할 수 없는 요구는 capability gap으로 남긴다.
- Python/Shell 텍스트 출력만으로 성공하지 않는다. 새로운 값·열 순서·결측·잘못된 입력의 독립 시험, 타입/단위 불변식, 비용·권한 경계를 검증한다.
- 단순 subprocess나 다른 cwd를 완전한 sandbox라고 부르지 않는다. 파일/프로세스/네트워크/시간/메모리 권한의 실제 제한을 명시·검증한다.
- 도구 후보의 코드 해시·도구 버전·입출력·권한·검증 receipt를 기록하고 승인된 등록 경로를 사용한다. 새 도구의 출력도 다음 단계에서 다시 검증한다.

**종료:** 개발자가 작성해 둔 완성 도구 선택을 넘어, 정의된 연산으로 새 조합의 도구를 생성하고 처음 보는 입력에서 사용한다. 임의 Python 프로그램 작성이나 무제한 자기 발전이 완성됐다고 말하지 않는다.

## 13. G9 — 제한된 자기 수정과 성능 개선

**시점:** G8, G3의 버전 배포, G0부터 유지한 평가 신뢰성이 준비된 뒤. **목표 문장:** 반복되는 실패의 원인을 분석하여 KG·rule·workflow·skill 또는 제한된 코드 변경 후보를 만들고, 분리된 버전에서 회귀·독립 평가·비용을 검증해 채택하거나 되돌린다.

- KG·개념·규칙 학습은 G2/G6에서 이미 수행한다. 여기서는 코드/도구/workflow까지 포함한 버전 변경 절차를 완성한다.
- Git status/history 확인→분리된 branch/작업 사본→후보 변경→diff→관련 시험→전체 회귀/벤치마크→채택 후보/기각을 연결한다. 사용자의 미커밋 변경은 변경 후보의 rollback 대상이 아니다.
- 시험 삭제·정답 변경·상한 제거·평가기 완화로 점수를 올린 후보를 거절한다. 변경 대상과 판정 기준을 분리하고 권한·승인·감사 경계를 자기 수정으로 우회하지 못하게 한다.
- 저장 상태 호환성과 실제 성능을 함께 검사한다. shortcut은 원 proof·독립 근거·조건이 유지될 때만 적용하며 이미 G0에서 만든 코드를 재사용한다.

**종료:** 정해진 종류의 결함에 실제 개선 후보를 만들고 독립 실패 사례를 개선하며 기존 기능을 보존한다. 실패 후보가 원 상태에 영향을 주지 않고 새 버전을 되돌릴 수 있다. 범용 자동 프로그래머의 완성을 주장하지 않는다.

## 14. G10 — Offspring Architecture 연구

**시점:** 예정된 필수 출시 단계가 아니라 조건부 연구. G9까지의 개선 시도가 검증됐는데도 구조 한계가 반복될 때만 진입한다. **목표 문장:** 실패가 지식 부족·언어 해석·잘못된 평가·구현 결함이 아니라 현재 구조의 한계라는 가설을 검증하고, 다른 구조의 후보를 부모와 같은 조건에서 비교한다.

- 반복 실패의 범주, 시도한 수정, 개선 정체, 비용 상한과 구조 가설을 먼저 기록한다. 실패 횟수만으로 후손을 만들지 않는다.
- 부모와 자식 후보는 같은 입력/자원/평가를 받는다. 이전 지식·사건·근거의 이관 가능성, 손실, 신규 능력과 회귀를 비교한다.
- 새 구조의 후보는 독립 identity와 명시적인 계보를 갖고 부모를 덮어쓰지 않는다. 후손 생성 자체를 성공 지표로 삼지 않는다.
- 실험 규모·자원·채택 조건을 고정하며 자동으로 후손을 무제한 늘리는 것을 목표로 삼지 않는다.

**종료:** 특정 구조 한계를 해결하는 후보와 재현 가능한 비교 근거가 생긴다. 더 나은 후보가 없으면 그 결과를 남기며 승격하지 않는다.

## 15. ALMA 병렬 갈래 A1 — Belief와 Theory of Mind

**시점:** G1/G2 뒤, 기존 Mental·시간·출처·교정의 미완료 조건을 닫은 후. **목표 문장:** 세계의 관찰/검증 사실, 나의 믿음, 상대의 믿음, 상대가 나에 대해 가진 믿음을 주체·시점·출처·범위로 구별하고 새로운 관찰·정정에 따라 갱신한다.

- `known_truth`를 전지적 진실 저장소로 두지 않는다. 외부 세계에 대해 확인된 사실/출처와 각 주체의 belief를 구별한다. 주체가 틀리게 믿는 것과 사실을 알면서 거짓을 말하는 것은 다른 상태다.
- 처음에는 한 단계와 두 단계의 제한된 중첩 믿음을 처리한다. 무한 ToM 추론을 목표로 하지 않고 상한을 둔다.
- 누가 어느 사건을 보거나 듣지 못했는지에 따라 접근 가능한 증거가 달라진다. 엔진이 아는 세계 상태를 모든 인물에게 자동 공유하지 않는다.
- 사용자 제시 예: A는 물건을 옮기는 장면을 봤고 B는 보지 못했다. 현재 위치 질문과 B가 찾을 위치 질문에 다른 근거로 답해야 한다.

**종료:** false-belief/관찰 차이/보고 내용/교정/복원 대조에서 주체별 믿음이 world fact와 섞이지 않는다. 새 믿음을 말로 표현하기 전에 이 구분을 검증한다.

## 16. ALMA 병렬 갈래 A2 — Communication Decision과 Utterance

**시점:** A1과 G4, 기존 동기·감정/선호 검증 뒤. **목표 문장:** 믿음과 발화를 분리하고, 제한된 사회적 실험에서 진실성·관계 보호·자기보호·목표·죄책감의 충돌을 근거로 의사소통 행동을 선택하며 그 결과를 관찰한다.

- belief snapshot, intended message, spoken message, audience, motive, 선택한 행동, 사용 근거와 예상/실제 상대 반응을 기록한다.
- 진실 말하기/일부 말하기/말하지 않기/화제 전환/거짓말을 별도 행동 후보로 둔다. `lie_probability`나 인물 이름별 고정 분기로 선택하지 않는다. 제공한 가치/동기 규칙과 경험으로 변한 평가를 구별한다.
- 발화 내용이 자신의 믿음이나 world fact를 자동 덮어쓰지 않는다. 잘못 믿고 한 진술과 의도적 거짓말의 대조를 검사한다.
- 실제 목표·관계·예상 결과를 바꿨을 때 선택이 왜 달라졌는지 추적한다. 사후에 그럴듯한 motive를 덧붙이는 방식은 실패다.
- 이 정책은 ALMA 사회적 실험의 상태/권한 범위에 적용한다. POLO의 업무 판단·실행 receipt·검증 결과·감사 로그를 조작하는 통로로 연결하지 않는다. 사회적 발화와 시스템의 실제 기록은 분리한다.

**종료:** 같은 belief에서도 동기·상대 지식에 따라 다른 의사소통을 선택하고 결과 관찰·기억으로 이어진다. 주관적 감정이나 인간 수준 인격의 증거로 확대하지 않는다.

3. 각 goal 시작 때 입력·기대 의미·필수/금지 근거·실패 대조·완료 범위를 고정하고 바로 구현한다. 모든 후속 goal을 하나의 무제한 goal로 묶지 않는다.
4. 구조 직접 입력과 자연어 입력, 개발 예문과 평가, 제공 지식과 학습 지식, 실제 실행과 모의 시험을 구별한다. 새 평가를 보고 고친 후 그 문항을 독립 평가라고 부르지 않는다.

6. 명령 반환/종료 코드/파일 존재만으로 목표 완료를 확정하지 않는다. 실제 의미 결과·대상·금액·역할·양태·근거·부작용을 검사한다. 후반 실패도 보고서에 남긴다.
