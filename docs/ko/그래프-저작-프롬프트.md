# 그래프 저작 프롬프트 — 다른 AI 에게 통째로 준다

아래 `---` 부터 끝까지를 복사해 다른 AI 에게 붙여넣는다. 저장소를 모르는
AI 도 이것만으로 쓸 수 있게 자족적으로 적었다. `{{분야}}` 만 바꿔 쓴다.

왜 병렬로 돌리나. 라우터를 고치고 재보니 문서 질문 204개 중 57개(28%)만
갈 그래프가 있었다. 샌 질문 12개 중 10개는 **갈 그래프가 아예 없었다** —
조직도 · 서버 배포 · 자료구조 · 주식 · 팀 목표. 판정을 아무리 고쳐도
덮는 분야가 없으면 답이 안 나온다. 지금 병목은 그래프 수다.

이 프롬프트에 적힌 것은 전부 실제로 돌려보고 확인했다. 특히 `이름말: 문장`
과 공리를 [논증]에 잇는 것은 빼먹으면 바로 티가 난다.

# 지식 그래프(.kg) 저작 요청

너는 **한국어 지식 그래프**를 쓴다. 이 그래프는 답을 지어내지 않고 **고르는**
엔진이 읽는다. 그래프에 없는 것은 답이 되지 않고, 그래프에 적힌 것은 근거
경로가 되어 사용자에게 그대로 보인다. **모르는 것을 적지 마라.**

## 무엇을 만드나

`{{분야}}` 의 `.kg` 파일 하나.

## 형식 — 이대로 돌아가는 것을 확인한 예시다

```
# 종합소득세 신고 상담. 법정 어휘를 쓰지 않는다.
역할: 세무 상담
목표: 종합소득세를신고한다
임계값: 0.50 / 0.60
이름말: 문장
전진관계: 갖춤, 함의함
부정관계: 걸림돌
근거관계: 갖춤

[개념]
종합소득세를신고한다: "종합소득세를 신고할 수 있다" | "신고가 된다"
소득자료있음:        "소득 자료가 준비됐다" | "신고할 자료가 다 있다"
수입액을안다:        "얼마 벌었는지 안다" | "작년 수입을 안다"
공제서류있음:        "공제 서류를 챙겼다" | "영수증이 있다"
자료없음상태:        "자료가 하나도 없다" | "증빙을 못 챙겼다"

[공리]
신고기간은5월@국세청: "종합소득세 신고 기간은 5월입니다" | "5월에 신고한다"

[사례]
*원천징수영수증: "원천징수영수증" | "회사에서 받은 영수증" | "소득 자료 있어요"
*기부금영수증:   "기부금영수증" | "기부한 영수증" | "공제 서류 있어요"
*영수증분실:     "아무 자료도 없어요" | "영수증을 다 버렸어요"

[무관]
_잡담: "점심 뭐 먹지" | "날씨가 좋네요"

[논증]
원천징수영수증 -갖춤-> 수입액을안다
수입액을안다   -함의함-> 소득자료있음
기부금영수증   -갖춤-> 공제서류있음
영수증분실     -갖춤-> 자료없음상태
자료없음상태   -걸림돌-> 소득자료있음
소득자료있음   -함의함-> 종합소득세를신고한다
공제서류있음   -함의함-> 종합소득세를신고한다
신고기간은5월  -함의함-> 종합소득세를신고한다

[대사]
B2: 그건 세금 신고와 상관이 없습니다.
B2_강등: 신고에 필요한 것만 다룹니다.
A: 혹시 {claim} 말씀인가요?
근거없음: {claim} 는 알겠는데, 무엇을 보고 하시는 말씀인가요?
인정: {ev} 니까 {claim} 네요.
인정_반격: {ev} 는 맞는데 {bad} 가 걸립니다.
C: {ev} 만으로는 {claim} 까지 안 됩니다.
B1: {claim} 은 알겠습니다. 서류를 보여주셔야 합니다.
미지: 그건 모르겠습니다.
목표주장: 신고 자체는 좋습니다. 자료부터 봅시다.
요건충족: (확인했습니다)
남은요건: 아직 {남은}이 남았습니다.
공리: {claim} — 이건 따로 근거를 대지 않아도 되는 것입니다.
```

## 규칙 — 어기면 안 돌아간다

### 1. `이름말: 문장` 을 넣어라

이게 없으면 기본값이 `용어` 라서 답이 **노드 이름을 그대로 읽는다**.

```
이름말 없음:  "원천징수영수증 니까 소득자료있음 네요."     <- 기계가 말하는 티
이름말: 문장: "원천징수영수증 니까 얼마 벌었는지 안다 네요."
```

노드 이름 자체를 보여주고 싶은 그래프(카드 이름, 법조문 이름)만 `용어` 로 둔다.

### 2. 관계 이름은 네가 정한다

엔진이 필요로 하는 것은 **세 역할**뿐이고 이름은 그래프가 선언한다.

| 머리말 | 뜻 | 방향 |
|---|---|---|
| `근거관계` | 이 관계로 나가는 [사례] 노드가 **증거**가 된다 | 사례 → 개념 |
| `전진관계` | 목표로 직접 오는 것이 **요건**(채워야 이기는 칸) | 개념 → 목표 |
| `부정관계` | 상대를 무너뜨린다 | X → Y |

- `근거관계` 는 반드시 `전진관계` 안에 있어야 한다. 밖이면 파일이 안 열린다.
- 셋 다 안 적으면 법정 어휘(`증명`/`충족`/`부정`)가 기본이다.
- **분야 말로 골라라.** 요리면 `넣음`·`됨`, 정비면 `증상`·`가리킴`,
  배포면 `띄움`·`갖춤`.

### 3. 예시 문장은 **말투를 바꿔 3개 이상**

엔진은 사용자의 말을 노드에 붙인다. 예시가 곧 "이 노드를 부르는 법"이고,
**예시에 없는 말투는 못 알아듣는다.** 실제로 확인했다:

```
"원천징수영수증"          -> 붙는다
"회사에서 받은 영수증 있어요"  -> 못 붙는다 (예시가 "회사에서 받은 영수증" 뿐일 때)
```

그러니 존댓말·반말·짧은 말·긴 말을 섞고, **네가 안 적은 말투로 직접 물어봐
확인해라.** 안 붙으면 그 말투를 예시에 더한다.

```
나쁨:  소득자료있음: "소득자료있음"
좋음:  소득자료있음: "소득 자료가 준비됐다" | "얼마 벌었는지 안다" | "작년 수입 정리했어요"
```

### 4. [개념]은 상태, [사례]는 행동·증거

같은 문장을 두 곳에 쓰면 매처가 둘을 못 가른다. 실제로 겪은 버그다.

```
나쁨:  자동차가져감(사례): "자동차를 가져간다"
       자동차있음(개념):   "자동차를 가져간다"   <- 똑같다
좋음:  자동차있음(개념):   "자동차가 그 자리에 있다" | "차를 가져갔다"
```

[사례] 이름 앞에는 `*`, [무관] 이름 앞에는 `_` 를 붙인다.

### 5. [공리]는 증거를 안 묻는 노드

`대한민국의 수도는 서울` 처럼 **사용자가 댈 증거가 없는 사실**을 여기 둔다.
`@출처` 를 붙이면 근거로 남는다.

**공리는 [논증]에서 목표로 바로 이어야 한다.** 개념으로 이으면 목표까지
닿기는 하는데 **아무 일도 하지 않는다** — 판정은 인정이 나면서 요건은 그대로
빈다. 요건을 채우는 것은 증거인데 공리에는 증거가 없기 때문이다.
`--diagnose` 가 "요건이 아닌 공리" 로 잡아 준다.

```
나쁨:  라벨이세탁방법안내 -준비됨-> 세탁표시확인함    <- 개념. 헛돈다
좋음:  라벨이세탁방법안내 -준비됨-> 빨래를한다        <- 목표. 요건이 된다
```

그리고 **공리는 사용자가 댈 증거를 대신하지 않는다.** '라벨은 세탁 방법을
안내한다' 가 참이라고 해서 이 사람이 제 옷 라벨을 봤다는 뜻은 아니다.
그건 증거가 할 일이다.

**목표는 공리가 될 수 없다.** 결론을 증거 없이 인정하면 논증이 사라진다.

이 구역을 안 쓰면 모든 주장에 증거가 필요하다 — 그것도 정상이다.

### 6. [무관]에 미끼를 넣어라

**목표에 기여하지 않는 그럴듯한 수치**가 미끼다. 안 적으면 엔진이 넘어간다.

```
세차 그래프    _시간비교: "걸어서 5분 차로 10분" | "걷는 게 더 빠르다"
연주 그래프    _인원비례: "사람이 두 배면 시간이 절반" | "120명이면 30분"
```

잡담(`_잡담`)도 여기 둔다. 이게 "딴 얘기"를 거절하는 근거가 된다.

### 7. 한 개념으로 들어가는 전진 엣지는 **각각 혼자서 충분해진다**

이 엔진에 AND 는 없다. 한 노드로 들어오는 전진 엣지는 서로 OR 다.

```
물올리기 -갖춤->  물이끓는다      "물을 부어넣었다" 만으로 물이 끓는다
불이켜짐 -함의함-> 물이끓는다      "불을 켰다" 만으로도 물이 끓는다
```

물만 부어도, 불만 켜도 채워진다. 증거 여럿이 **같은 사실 하나**를 각각
증명하는 것이라면 옳다(CCTV 든 압수품이든 흉기 소지를 보인다). 하지만
**둘 다 있어야 하는 것**을 그렇게 적으면 하나로 통과한다.

둘 다 필요하면 **각각을 요건으로 갈라라.**

```
물올리기   -갖춤->  물있음
가스불켜기 -갖춤->  불이켜짐
물있음   -함의함-> 라면을끓인다     <- 각각 목표로. 요건은 AND 다
불이켜짐 -함의함-> 라면을끓인다
```

### 8. 답에 **수**가 필요하면 값을 나르고, 필요하면 셈해라

이 엔진은 값을 만들지 않는다. 하지만 사용자가 말한 수를 그래프가 그은 길로
**나를** 수는 있다. 그러면 그래프에 한 번도 안 적힌 답이 나온다.

```
[개념]
제친사람순위를안다 {등}:                  "제친 사람이 몇 등이었는지 안다"
지금순위를안다 {등 <- 제친사람순위를안다}:   "지금 몇 등인지 알 수 있다"

[대사]
인정:    {ev} 니까 {claim}.
인정_값: {ev} 니까 {claim}. 지금 {값} 입니다.
```

- `{등}` — 발화에서 '등' 단위의 수를 **붙잡는다**
- `{등 <- 다른노드}` — 그 노드가 붙잡은 수를 **가져온다**
- `{값}` — 대사에서 꺼낸다. `인정_값` 은 값이 나온 턴에만 쓰인다

`2등을 제쳤다` 면 2등, `17등을 제쳤다` 면 17등이라 답한다. 그래프에는
17이라는 수가 없다. **수가 없는 발화에서는 값을 만들지 않는다** — 빈 칸이다.

비교(`{% >= 0.03}`)와 다르다. 비교는 참/거짓을 가르고, 이건 수를 들고 간다.

**셈이 필요하면 식을 적어라.** 엔진이 식을 고르지는 않는다 — 사람이 적고
엔진은 계산만 한다.

```
[개념]
몫을안다 {원 = 총액 / 인원}: "한 사람이 얼마 낼지 안다"
총액 {원}:                 "전체 금액을 안다"
인원 {명}:                 "몇 명인지 안다"

[대사]
결론값: 그러면 한 사람 {값} 입니다.
```

`12만원` 과 `3명` 을 들으면 `한 사람 40000원` 이라 답한다. 40000은 그래프에
없다. **피연산자가 하나라도 없으면 아무 말도 안 나간다** — 모르는 자리를 0으로
두면 없는 답이 생긴다. 0으로 나누는 것도 값 없음이다.

`결론값` 은 목표의 값이 풀리는 턴에만 나간다. 그 순간이 새 사실이 선 자리다.

쓸 수 있는 것은 `+ - * /` 와 괄호, 그리고 다른 노드 이름과 숫자뿐이다.

**셈이 필요 없는 경우가 더 많다.** '120명이 연주하면 몇 분?' 의 답은 곡
길이 그대로다 — 인원과 무관하다. 그건 `{분 <- 곡이정함}` 으로 나르고,
'사람이 두 배면 절반' 은 [무관]에 미끼로 둔다.

### 9. 남은 요건을 **물어라** — `[물음]`

요건이 남으면 엔진은 기본으로 통보한다. 물을 말을 적어 두면 대신 묻는다.
반응만 하던 것이 일을 같이 진행하는 것이 된다.

```
[물음]
총액: 얼마 나왔나요?
인원: 몇 분이서 나누세요?
```

```
없을 때:  … 얼마 나왔는지 안다. 아직 몇 명인지 안다가 남았습니다.
있을 때:  … 얼마 나왔는지 안다. 몇 분이서 나누세요?
```

증거를 요구하는 자리(B1·근거없음)에서도 그 노드의 물음을 쓴다.

**요건마다 한 줄씩 적어라.** 요건은 3~5개니 몇 줄 안 된다. 엔진은 언제
물을지만 고른다 — 물음 문장을 만들면 지어내기다.

### 10. 대사의 조사는 붙여 써라

조사는 앞말 받침을 보고 고쳐지는데, **바로 뒤에 붙어 있을 때만** 고쳐진다.

```
나쁨:  남은요건: 아직 {남은} 이 남았습니다.   -> "영수증이 있다 이 남았습니다"
좋음:  남은요건: 아직 {남은}이 남았습니다.    -> "영수증이 있다가 남았습니다"
```

띄우고 싶으면 조사를 아예 빼라: `아직 "{남은}" 그게 남았네.`

### 11. 개념끼리도 이어라 — 여기서 새 사실이 나온다

`[논증]` 을 **사례 → 개념 → 목표** 두 홉 평면으로만 짜기 쉬운데, 실제로
도는 그래프는 그렇지 않다. 재보니 **엣지의 절반 이상이 개념끼리** 잇는
것이었고(취약점분석 100/140, Bash 58/114), 증거에서 목표까지 평균 3홉이다.

개념 사슬이 하는 일이 이거다. `수입액을안다` 를 `소득자료있음` 에 이어 두면,
"작년 수입을 안다" 는 말 하나가 **적어 두지 않은 결론까지** 닿는다.

```
원천징수영수증 -갖춤->  수입액을안다      <- 증거가 붙는 자리
수입액을안다   -함의함-> 소득자료있음      <- 개념끼리. 이 줄이 없으면 안 닿는다
소득자료있음   -함의함-> 종합소득세를신고한다
```

사슬을 2홉으로 잘라 보면 요건 도달이 100개에서 84개로 떨어진다. Bash 기초와
버그바운티 그래프는 **2홉이면 요건 0/3** — 사슬이 전부다.

그러니 개념을 적을 때마다 물어라. **이건 어느 개념의 한 종류인가? 무엇을
뜻하는가?** 그 답이 엣지다. 엣지 수는 노드 수의 1~1.5배쯤 나온다.

### 12. 요건은 3~5개로 하고, 증거는 그보다 넉넉히

**노드 수는 제한이 없다.** 재보니 노드 123개짜리도 자기복귀 99.6% 로
작은 그래프(99.8%)와 차이가 없다. 크게 써도 매칭은 안 무너진다.

무너지는 건 **요건 수**다. 요건마다 서로 다른 증거가 하나씩 배정되고, 그
증거를 대는 데 한 턴씩 든다. 인내심은 5고 헛턴 하나에 1~2점이 깎이므로,
요건이 20개인 그래프는 **20턴을 거의 안 틀리고 가야** 이긴다.

```
요건 20 · 증거 20 (여유 0)  -> 증거 하나만 안 붙으면 영영 못 이김
요건  4 · 증거  7 (여유 3)  -> 4턴에 승소
```

주제가 넓으면 요건을 늘리지 말고 **그래프를 쪼개라.** 요건 20개짜리 하나보다
요건 4개짜리 다섯이 낫다.

증거가 요건보다 적으면 `--diagnose` 가 "증거가 모자람" 으로 잡아준다.
(공리 요건은 증거를 안 쓰므로 이 셈에서 빠진다.)

## 검사 — 반드시 돌리고 결과를 붙여라

```bash
KG_ENCODER=문자 python engine.py --diagnose <파일>.kg
```

`문제 없음` 이 나와야 한다. `[정보]` 줄은 흠이 아니다.

그리고 **직접 대화해 보고 그 기록을 내라.**

```bash
KG_ENCODER=문자 python engine.py <파일>.kg
```

증거를 차례로 대서 `=== 승소 ===` 까지 가는 길이 있어야 하고, 잡담에는
[무관] 대사가 나와야 한다. **안 돌려본 그래프는 안 낸 것과 같다.**

## 하지 말 것

- **모르는 것을 적지 마라.** 법·의료·세금은 틀리면 사람이 다친다.
  확실하지 않으면 그 노드를 빼라.
- 노드 이름에 공백·특수문자를 넣지 마라. `소득자료있음` 처럼 붙여 쓴다.
- 예시 문장에 `|` 를 쓰지 마라(구분자다).
- `[대사]` 의 `{claim}` `{ev}` `{bad}` `{남은}` 은 엔진이 채운다.
  다른 이름을 쓰지 마라.
- 요건을 늘려서 주제를 넓히지 마라. 그래프를 쪼개는 편이 낫다.

## 낼 것

1. `.kg` 파일 하나
2. `--diagnose` 출력 (`문제 없음`)
3. 승소까지 가는 대화 기록 + 잡담 거절 한 번
4. **네가 확신 못 해서 뺀 것** 목록 — 이게 다음 사람이 채울 자리다
