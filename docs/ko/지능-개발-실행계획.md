## 1. 절대 바꾸지 않을 목표

사람이 정한 `docs/ko/목표와-구조.md`가 기준이다. 사용자의 이번 대화에서 추가로
확정된 것은 **공리팩을 `axioms/` 폴더로 분리한다**는 결정이다.

- 목표는 가볍고 설명 가능하며, 새로운 문장을 이해하고 지식을 조합하는 그래프 기반 AI다.

- 큰 자기회귀 언어 모델을 상시 답변기로 붙여 성능을 대신하지 않는다.
- 언어 교체 구현 자체는 다른 작업이 맡는다. 여기서는 한국어 이해와 추론의 일반화를 개선한다.

## 3. 개정 실행 순서와 상세 명세

### 지금부터의 실행 목록 — 이 순서가 우선한다

**목표:** 지식 저장량 증가, 설명을 읽고 적용하는 능력, 교정의 일반화를 구분한다.
초기 GPT-3의 문맥 내 적응도 대규모 사전학습을 토대로 했다. 그 결과가 작은 그래프
시스템에서도 저절로 생긴다고 가정하지 않는다. 아래 학습 방법은 검증할 가설이다.

**0. 현재 동작을 고정하고 이미 한 작업을 재사용한다.** (P0·P1·P7a)

- 실제 앱의 코드/팩/대화 상태와 시험용 팩을 구분해 기록한다. v3 후보는 별도로 만들고 원본을 보존한다.
- 기존 답변 평가에 최소한의 결론 의미 판정과 오류 구분을 보강한다. 답변 가능 문항의 해결률,
  단정 정확률·응답률, 적절한 보류를 분리한다. 확인하지 못한 근거는 ‘미검토’로 남긴다.
- 문자열 `15`가 `115`에 포함돼 통과하거나, 프로그램 오류가 올바른 보류가 되는 경우부터 차단한다.
  숫자·단위·대상은 답변과 문맥을 함께 읽고, 자동 판정이 어려운 설명은 사람 검토를 기록한다.
- 산출물: 실제 응답/실패 이유/미검토 항목/버전이 있는 짧은 기준선. 큰 평가 플랫폼부터 만들지 않는다.

**1. 첫 체감 목표를 ‘설명을 받아 새로운 질문에 적용하기’로 잡는다.** (L2·P3·P4·P6b)

- 새 표현의 뜻, 새 분야의 사실, 기존 규칙들의 새 조합, 정보가 부족한 질문을 구분한 작은 개발 묶음을 만든다.
- 설명 전 → 설명 후 → 새로운 질문 → 설명 정정 후의 응답을 비교한다.
- 수량 이동만 쓰지 말고 분류/조건/사용 규칙 같은 다른 관계 유형도 포함한다.
  한 관계군에서 먼저 구현하되 다른 유형까지 된 것처럼 주장하지 않는다.
- 개발용과 독립 평가용을 표현·정의·관계 조합·문서 단위로 분리한다. 이름/숫자 치환은 약한 대조군이다.
  이미 실패 내용이 공개돼 수정에 이용된 평가 문항은 보지 않은 최종 평가로 다시 주장하지 않는다.
- 산출물: ‘설명 전에는 못했지만 설명 후 새 질문에서 됐다’는 전후 사례와 실패 사례.

**2. 이해와 추론의 어느 쪽이 막히는지 같은 문제로 나눈다.** (L3·P2a·P4)

- 올바른 구조와 사실을 직접 준 실행, 원문 설명을 준 실행, 필요한 문서를 스스로 찾는 실행을 비교한다.
- 구조를 줘도 실패하면 표현/추론을 고친다. 원문에서만 실패하면 형태·역할·조건 해석을 고친다.
  검색을 추가해서 읽기 실패를 가리지 않는다. 정답 구조 주입은 진단 전용이며 제품 점수에서 제외한다.
- 기존 활용/관계 파서/연산 그래프를 재사용하고, 이번 문제를 표현하는 데 필요한 구조만 추가한다.
- 산출물: 원인 하나, 일반적인 수정 하나, 관련된 여러 문장에서의 효과. 전체 파서 교체를 선행 조건으로 삼지 않는다.

**3. 문장별 예외 대신 공통 해석 방법을 배우는 작은 실험을 한다.** (L1·P2b·P3)

- 학습 자료는 질문-정답 짝만이 아니라 원문↔개체·사건·역할·조건의 대응, 다른 표현의 같은 뜻,
  비슷하지만 다른 뜻, 부정/가정/역할 역전, 실제 교정으로 구성한다. 출처와 작성 비용도 기록한다.
- 가설 H1: 기존 형태 분석과 역할 제약으로 부분 해석을 조합하고, 여러 용례의 공통 구조에서
  표현↔의미 연결 후보를 유도하면 문장 전체 틀보다 미등록 표현을 더 잘 처리하는가?
- H1의 후보 안에 정답 해석이 있는데 선택이 실패할 때 가설 H2를 비교한다: 역할 적합성·
  문맥·조건 충족·근거 일치 특징을 쓰는 작은 학습형 후보 선택기가 고정 점수보다 전이하는가?
  정답 후보 자체가 없으면 순위 학습으로 해결했다고 주장하지 않는다.
- 동일한 학습/평가 분할에서 기존 방식과 비교한다. 한 번에 한 가설만 바꾸며, 개선이 없으면
  후보 생성·표현 구조·학습 자료 중 병목을 재진단한다. 정규식/동의어 항목만 계속 늘리지 않는다.
- 작은 학습형 부품은 비교할 선택지이지 도입 확정이 아니다. 큰 LLM/API 답변기나 외부 모델을
  자동 도입하지 않는다. 채택 후보는 팩 포함·재현성·원문 대응·메모리 조건도 통과해야 한다.
- 산출물: 보지 않은 표현/관계 조합에서의 개선 또는 기각 결과. 저장 성공을 학습 성공으로 세지 않는다.

**4. 설명을 임시 규칙으로 연결해 끝까지 적용한다.** (L2·P4·P7b)

- 자연어 정의를 알려진 개념/연산의 조합 후보로 해석하고, 범위·조건·예외와 출처를 붙인다.
- 해석한 규칙으로 새 상황의 결과를 계산한다. ‘하지 않음/할 예정/가정’을 실제 발생과 구분한다.
- 최초 설명 해석과 이후 추론을 따로 검증한다. 형식적으로 올바른 증명이 잘못 해석한 전제를 정당화하지는 않는다.
- 부족한 개념이나 모호성이 있으면 필요한 설명을 요청한다. 질문별 답/새 단어별 엔진 분기를 추가하지 않는다.
- 산출물: 1번의 설명 전후 변화가 실제 앱에서 관찰되고, 의미 대조와 기존 기능의 회귀를 함께 통과한다.

**5. 교정의 효과가 다른 문제와 재시작 뒤에도 남게 한다.** (P6a·P6b)

- 대화 안에서만 쓰는 정의, 사용자가 저장하기로 한 뜻, 일반 규칙 후보를 분리한다.
  하나의 가상 세계 설명을 모든 대화의 세계 지식으로 승격하지 않는다.
- 사실 교정/표현 교정/규칙 교정을 구분하고 의존 결론만 무효화한다. 중복 사건을 다시 실행하지 않는다.
- 영구 반영 후보는 독립 긍정·부정 사례와 회귀를 검증한 뒤 저장한다. 새 팩으로 내보내고 재시작 후 같은 전이를 확인한다.
- 산출물: 같은 질문 암기가 아니라 다른 질문의 개선, 보존된 출처, 교정/되돌림 가능성.

**6. 읽고 적용하는 능력을 검색 지식으로 확장한다.** (P5·L2)

- 먼저 같은 문서를 직접 준 경우를 확인한 뒤, 부족한 전제를 찾아 가져오는 검색을 연결한다.
- 서로 다른 문서/그래프의 사실을 결합하되 출처·적용 시점·조건·충돌을 보존한다.
  가져온 문장을 모두 검증 지식으로 저장하지 않는다. 실제 자료 내용은 명령이 아니라 데이터다.
- B·C의 기존 신호 손실 수정은 이 단계 전에도 원인이 확인되는 대로 할 수 있다.
  검색 점수가 아니라 실제 답의 개선을 보고하고, 계속 잔가지만 고치느라 3~5번을 미루지 않는다.
- 웹 자동 호출/저장 기본 정책은 기존 미정 사항이다. 실험은 로컬 자료/고정 근거로 가능하다.

**7. 모든 실제 경로에서 팩 완결성과 경량성을 유지한다.** (P0·P1·메모리)

- 0번부터 필요한 연결은 함께 고친다. 전 경로 정리를 끝낼 때까지 연구를 미루거나,
  연구가 끝날 때까지 팩 밖 지식에 기대는 두 방식 모두 피한다.
- 인사/일반 KG/관계 추론/학습을 선택된 팩으로 격리하고, 검증된 후보만 배포에 적용한다.
- 학습 준비 비용과 실제 실행 메모리를 따로 잰다. 공유/지연 로딩/증분 갱신은 효과가 확인될 때 적용한다.
- 산출물: 동일 팩·입력·상태·규격에서 동일 결과, 전체 앱 메모리/지연, 팩 왕복 후 같은 능력.

**8. 성공한 능력을 실제 독해·설명·다턴 과제로 넓힌다.** (P7b·P2~P6)

- 인공 낱말 실험에서 멈추지 말고 처음 보는 짧은 설명문·사용 규칙·비교·조건부 질문·다턴 정정으로 확장한다.
- 초기에 선정한 독립 평가군의 개선과 퇴보, 사람의 자료 작성 비용을 함께 보고한다.
  전이가 없으면 대규모 자료 수집이나 전면 재작성에 들어가지 않고 방법을 다시 선택한다.
- GPT-3 수준 여부는 비교 대상/과제/조건을 정한 별도 평가로 판단한다. 이 목록을 구현했다는 사실로 선언하지 않는다.

**먼저 하지 않을 것:** 사전 무차별 증설, 예문 전체 틀 증설, 전면 파서 재작성,
평가 도구만 장기 개발, 새 기능 없는 메모리 최적화에 집중, 언어 교체 담당 작업의 재구현.

### L0~L3. 어휘를 의미와 사건에 연결하는 단계 — 신규

**목적:** 단어 목록을 늘리는 것이 아니라, 알고 있는 단어의 뜻을 재사용 가능한
의미 구조로 연결한다. 자모 계산만으로 단어 뜻을 얻을 수 있다고 가정하지 않는다.

#### L0. 기존 어휘 자산과 실제 빈칸을 센다

1. `graphs/*.kg`의 개념·별칭·관계, 언어팩의 어간/활용, `docs/ko/_동의어.json`,
   기존 정의문 자료의 형식·출처·사용 범위를 읽기 전용으로 조사한다.
2. 동일 표기라도 뜻이 다를 수 있으므로 문자열만으로 노드를 합치지 않는다.
   ‘개념 중복’, ‘같은 뜻의 다른 표현’, ‘다의어’, ‘아직 연결되지 않은 표현’을 분리한다.
3. 실제 실패 문장을 표본으로 골라 필요한 어휘/의미가 없는지, 이미 있지만 검색/연결에 실패하는지 센다.
   어휘 수가 아니라 **필요한 의미를 후보에 포함하는 비율**과 **잘못된 의미를 선택하는 비율**을 잰다.

   **이 세기는 2026-09-14 에 한 번 돌렸고, 결과가 이 단계의 우선순위를 바꾼다.**

   | 물음 갈래 | 그 낱말을 그래프가 이미 아는 비율 |
   |---|---:|
   | 고정 물음 400개 | 100.0% |
   | 잣대와 안 겹치는 실제 실패 발화 1,184개 | **92.1%** |

   모르는 258종도 대부분 사람 이름(`서우`·`도아`·`라온`)과 조사가 붙은 꼴이지 개념이
   아니다. 고정 물음의 100%는 그래프에서 뽑았으므로 순환이니 92.1% 쪽을 본다.
   **사전을 새로 쌓는 작업은 우선순위가 아니다. 다만 표기 덮임과 의미 이해는 구분한다.**

   예전 176건의 ‘미공유 51.1%’ 설명은 잘못됐다. §2의 정정된 A/B/C/읽기 실패 분류를 사용한다.
   §2의 색인 제외 원인을 반영하고 같은 버전에서 사례 목록을 고정한 뒤, B·C에서 어떤 특징이
   생성/필터/순위/문턱/근거 판정 단계에 걸려 사라지는지 기록한다.
   C의 원인을 확인하기 전에 `_RARE_MAX_GRAPHS`나 가산값을 고정 잣대에 맞춰 쓸지 않는다.
   관련 없는 신규 입력과 밖 물음에서도 개선이 유지되는지를 따로 검증한다.
4. 공개 사전/용례를 추가로 쓸 때는 의미 구분·품사·용례·출처 ID와 재배포 조건을 확인한다.
   뜻풀이 원문을 보유한 것과 그 뜻을 기계가 이해한 것은 다른 상태다.

산출물: 원천별 자산 목록, 중복/미연결 진단, 대표 실패군, 우선 연결할 의미 목록.
단어 몇 천 개만 채우면 범용 이해가 된다는 목표치는 두지 않는다.

**규모를 먼저 정한다.** 한국어의 꼬리는 길어서 전부에 선언을 달 수 없다.

| 자주 쓰는 낱말 | 전체 쓰임에서 차지하는 비율 |
|---:|---:|
| 500 | 44.4% |
| 2,000 | 58.3% |
| 5,000 | 71.0% |
| 10,000 | 80.8% |

그래프의 서로 다른 낱말은 25,748종이다. **잣대 실패에 실제로 나오는 동사·사건어
200~300개부터 달고 곡선을 본다.** 몇 개에서 이득이 꺾이는지가 이 방식의 값어치를
정한다. 목표치를 먼저 선언하고 거기 맞추지 않는다.

**같은 실험을 반복하지 말 것:** `docs/ko/synonym-table.md`에는 자동 동의어 짝 확장이
라우팅을 개선하지 못한 기록이 있다. 그 기록은 모든 학습 방식의 불가능성을 증명하지는
않지만, 유사도가 높다는 이유만으로 동의어를 확정하는 접근을 반복할 근거도 아니다.

#### L1. 표기·뜻·사건 틀을 분리한다

언어팩에는 표제어/품사/활용 부류, 가능한 뜻 ID, 문법적 자리와 사건 역할의 대응을 둔다.
공통 의미 ID와 사건의 역할/관계는 그래프 자산으로 표현하고, 상태 변화 규칙은
일반 공리와 분야별 지식으로 나눈다. 새로운 독립 ‘어휘 DB’를 팩 밖에 만들지 않는다.

어휘 항목은 다음을 참조할 수 있어야 한다.

- 표기와 기본형, 품사와 활용 부류.
- 하나 이상의 뜻 ID. 서로 다른 뜻을 한 벡터/한 노드로 강제 합치지 않는다.
- 사건 틀: 누가, 무엇을, 누구에게, 어디서/어디로, 얼마나.
- 문법 자리와 역할의 대응, 생략할 수 있는 자리, 해석에 필요한 조건.
- 출처/용례 ID, 확인 상태, 버전. 용례는 답표가 아니라 의미 연결의 증거다.

예를 들어 ‘주다’와 ‘받다’는 같은 전달 사건을 서로 다른 참여자 관점에서 설명할 수 있다.
그렇다고 두 단어를 무조건 치환하지 않는다. 주체/대상의 역할이 함께 맞아야 한다.
‘빌려주다’는 반환 관계가 있는 사건으로, ‘먹다’의 섭취와 ‘마음을 먹다’는 다른 뜻으로
표현할 수 있어야 한다. 이들은 설계 대조 예이지 새 예문별 코드 분기를 만들라는 목록이 아니다.

단어→뜻 연결만으로 상태를 바꾸지 않는다. 상태 변경은 사건의 실제 발생 여부·대상·양·
장소·관련 조건을 확인한 뒤 규칙으로 실행한다. 어떤 사과를 몇 개 먹었는지 없으면 -1을 추정하지 않는다.
형식 이름/저장 필드는 기존 규격과 맞춰 구현 때 정하되, 언어별 표기와 공리를 다시 섞지 않는다.

#### L2. 모르는 뜻을 확보하는 경로를 둔다

1. 기존 그래프에 있으면 재사용할 연결을 제안한다. 같은 이름이라는 이유로 자동 병합하지 않는다.
2. 없으면 사전·용례·사용자 설명에서 후보를 만든다. 출처 문장이 있다고 자동 승인하지 않는다.
3. 알려진 개념의 새로운 표현과, 현재 개념 체계에 없는 새로운 뜻/사건을 구분한다.
   전자는 연결 후보, 후자는 사건/관계 구조 자체를 추가할 제안이다.
4. 한 용례로 관계를 결정할 수 없으면 후보로 남기고 필요한 대조 용례/교정을 요청한다.
   사용자에게 매번 복잡한 슬롯 JSON을 작성하게 만드는 것을 최종 UX로 삼지 않는다.
5. 저작 시 자동 제안은 가능하지만, 작은 검증 표본에서 정밀도와 교정 시간을 먼저 잰다.
   자동 뜻풀이 해석기가 이미 있다고 가정해 입력 이해 문제를 다른 이름으로 숨기지 않는다.
6. 승인된 연결은 원천 자산 한 곳에 기록하고 다른 경로는 참조한다. 파생 조회 색인은 재생성 가능하게 둔다.

새 고유명사는 이름 슬롯으로 처리할 수 있지만, 처음 보는 동사의 의미를 철자만으로
확정할 수는 없다. 미등록 표기/새로운 뜻/사건 조건 누락을 서로 다른 실패 코드로 남긴다.

#### L3. 어휘 부족과 조합 실패를 분리해서 검증한다

같은 입력 집합에 대해 아래 실험을 따로 수행한다. 사람이 지정한 값은 **진단용 정답 주입**이며
실제 제품 성능에 합산하지 않는다.

1. 사람이 올바른 의미 구조와 필요한 사실을 준다 → 추론이 실패하면 P4의 문제다.
2. 필요한 사실 없이 같은 구조를 준다 → 자료를 못 찾으면 P5의 문제다.
3. 단어별 올바른 뜻 후보를 제공하고 원문을 분석시킨다 → 조합이 실패하면 P3의 문제다.
4. 원문만 준다 → 3번보다 낮아진 부분은 어휘 후보 생성/뜻 선택 경로를 조사한다.
5. 표현할 구조 자체가 없으면 P2로 분류한다. 무조건 어휘 항목을 추가하지 않는다.

**이 실험을 돌리려면 지금 없는 자료가 필요하다.** 1~3번의 ‘사람이 준 올바른 의미
구조’를 담은 자료가 저장소에 없다. **금본위 진단 자료 50~100건을 만드는 것을
명시적 작업으로 잡는다.**

- 고정 물음과 실제 실패 발화에서 고르되, **얼린 잣대의 정답을 개선 코드의 입력으로
  쓰지 않는다.**
- 개체·사건·역할·수량·부정·질문 여부를 손으로 단다.
- 이 자료로는 최종 점수를 주장하지 않는다. 층을 가르는 데만 쓴다.

거친 판은 이미 한 번 돌렸고 값이 있었다. 라우팅을 `라우터 1등 / 상위 셋 /
근거까지 봄` 으로 갈랐더니 **상위 셋 안에 있는데 못 쓰고 있던 20%** 가 드러났고,
근거 라우팅에서 31.8% -> 40.2%, 별도 드문 낱말 변경에서 40.0% -> 49.8%가 보고됐다
(`docs/ko/evidence-routing.md`, `docs/ko/rare-word-routing.md`). 서로 다른 변경/시점의
결과이며, 어느 것도 최종 답의 의미 정확도를 뜻하지 않는다.

평가는 알려진 뜻의 새로운 문장, 알려진 단어의 다른 뜻, 새로운 표현을 교정한 뒤의 전이,
완전히 미등록된 뜻을 나누어 보고한다. 단순 총점 차이를 인과적 기여율로 단정하지 말고
사례별 중간 결과로 실패 위치를 확인한다.

완료 기준: 새 표현/뜻 연결을 저장한 뒤 학습하지 않은 문장에서도 필요한 의미가 살아나고,
반대말·다의어·역할 역전·부정·가정 대조에서 과잉 연결이 늘지 않는다.

### P2. 이해·검색·추론이 주고받는 의미 표현을 맞춘다

**핵심 아이디어:** 문장 문자열끼리 연결하지 말고, 같은 개체·사건·관계·질문을 가리키는 구조끼리 연결한다.

**P2a 구현:** 기존 자료를 보존하는 구조/어댑터/검증기를 만든다. 사람이 올바른 구조를
직접 주었을 때 P4가 처리하는지를 먼저 검증한다. 처음부터 모든 의미를 담는 거대한 체계를 설계하지 않는다.

**P2b 연구:** 이 구조가 새로운 문장의 의미 차이를 충분히 표현하는지 확인한다.
표현 불가능한 사례가 발견됐을 때 근거를 갖고 확장한다. JSON 변환 성공을 의미 이해 성공으로 세지 않는다.

1. 기존 `semantic-state-v1`과 관계 삼중항을 버리지 말고 어댑터를 통해 확장한다.
2. 개체 ID, 사건 ID, 행위자·대상·출발/도착, 수량·단위, 시간/장소 범위,
   부정·가정·계획·질문 여부를 명시한다. 단순 삼중항에 못 담는 사건은 사건 노드를 둔다.
3. 각 후보에 원문 위치와 사용 규칙을 붙인다. 여러 해석은 별개 후보로 보존한다.
4. 개체명이 바뀌어도 같은 추론이 실행되고, 행위자·대상·부정만 바꾸면 결과가 달라지게 한다.
5. 구조가 있다고 사실로 승인하지 않는다. 발화가 진술인지 질문/인용/가정인지 함께 검사한다.

**완료 기준:** 같은 의미의 표현들이 같은 구조로 수렴하고, 의미가 다른 최소 대조 문장은 구분된다.
중간 구조의 정확도와 최종 답 정확도를 따로 측정한다.

### P3. 문장별 대응에서 조합 가능한 이해로 이동한다

**재사용:** `marco/language/hangul.py`, `relational_semantics.py`, 언어팩의 활용/물음 어미,
`graph_dialogue.py`의 요청 구성. 언어 교체 담당자의 구현을 통째로 다시 쓰지 않는다.

**연구 절차:** L0의 실패군에서 대표적인 하나를 골라 현재 방식과 조합식 분석을 비교한다.
어휘를 고정한 실험과 어휘를 교정한 실험을 분리하고, 보지 않은 표현/관계 조합에서 검증한다.
오류·미지·후보 수·메모리·지연과 사람이 추가한 주석량을 함께 기록한다.
개선이 없으면 규칙 수만 늘리지 말고 분석 구조/후보 선택 가설을 바꾼다.
작은 성공은 확장 여부를 결정할 증거이지, 전체 파서나 일반 지능 완성의 근거가 아니다.

1. 어휘/어간의 의미 후보와 문법 규칙을 분리한다. 단어·불규칙 사전은 필요하지만 문장 전체의 답표는 필요하지 않다.
2. 기존 활용 계산으로 형태 후보를 만들고, 조사·문장 성분·절 연결로 후보를 결합한다.
3. 동일한 부분 구간의 분석을 공유한다. 공유 차트나 후보 그래프를 써서 문장 꼴을 전부 전개하지 않는다.
4. 어순 변화·수식어·생략·복합 명사·대명사·부정 범위·질문 대상을 단계적으로 처리한다.
5. ‘크다→크고’는 형태 문제다. ‘먹다/꺼내다/옮기다’가 어떤 상태를 바꾸는지는 의미와 상황 문제다.
   **‘먹었다’면 항상 -1** 같은 치환은 금지한다. 대상·양·위치·사건 결과를 결합해야 한다.
6. 새 표현을 못 풀 때는 어휘/형태/구문/의미/대명사 중 어느 단계가 막혔는지 기록한다.

**완료 기준:** 학습에 없는 표현과 관계 조합으로도 해석한다. 이름/숫자만 바꾼 성공은 별도로 보고한다.
형태 규칙 하나가 여러 동사·요청에서 함께 작동하는지 확인하고, 문장별 if문 증가를 리뷰한다.

### P4. 공리를 ‘허가 목록’에서 조합 가능한 규칙으로 확장한다

현재 `axioms/core.json`에는 규칙 3개와 연산 이름 목록이 있다. 허가 목록을 늘리는 것만으로
지능이 늘지는 않는다. `graph_inference.py`의 결합/추론과 `marco/language/arithmetic.py`의 연산 그래프를 재사용한다.

1. 엔진에 남길 기본 연산과 팩에 둘 세상 지식을 구분한다.
   숫자 덧셈의 실행은 코드에 있어도 되지만, 어떤 사건이 어떤 상태에 어떤 변화를 주는지는 모델의 선언이어야 한다.
2. 비교·분류·소유/이동·수량·공간·시간·조건·제약을 공통 개체/변수 표현으로 조합한다.
3. 목표에서 필요한 전제를 찾는 추론과 관찰에서 새 사실을 만드는 추론을 연결한다.
   무조건 모든 그래프의 폐포를 매 턴 생성하지 않는다.
4. 알 수 없음과 거짓, 계획과 실행, 언급과 관찰, 전제 오류와 정보 부족을 구분한다.
5. 순환·모순·중복 사건·범위 혼동을 검사하고, 결론마다 규칙 ID와 부모 근거를 남긴다.
6. 전문 도메인의 사실을 ‘모든 분야의 공리’로 올리지 않는다. 규칙의 적용 조건과 범위를 자료에 둔다.

**완료 기준:** 사람 이름이나 질문 번호를 코드에 추가하지 않고 새 다단계 문제를 해결한다.
전제를 지우거나 부정하거나 사건 순서를 바꾸면 설명 가능한 방식으로 결론이 바뀐다.

### P5. 검색을 답 선택기가 아니라 추론의 자료 공급자로 연결한다

1. 검색 실패와 이해 실패와 추론 실패를 분리한 뒤 가장 큰 실패군부터 개선한다.
2. 질문 전체와 문자열이 비슷한 그래프만 고르지 말고, 질문 구조의 개체·관계·부족한 전제에 필요한 자료를 찾는다.
3. 검색 후보는 검증할 재료다. 유사도가 높다는 이유만으로 결론으로 승격하지 않는다.
4. 서로 다른 그래프에서 얻은 사실도 공통 의미 표현으로 결합해 답할 수 있게 한다.
5. 라우팅과 노드 매칭, 최종 근거 판정을 따로 잰다. 한 점수가 올라 다른 단계의 퇴보를 숨기지 못하게 한다.
6. 두 실행 경로를 즉시 하나로 다시 쓰기보다 먼저 입력·결과·근거 규격을 맞춘다.
   최종 통합 여부는 사용자 미정 사항이므로 결정을 받기 전에는 확정하지 않는다.

**완료 기준:** 단일 그래프에 정답 문장이 없어도 여러 근거를 조합하며, 무관한 그래프가 늘어도 오답이 늘지 않는다.

### P6. 대화 기억과 학습을 연결한다

**P6a 구현 — 기억 관리:** 이미 식별된 관찰/사건의 저장·복구·정정·중복 방지·근거 무효화를 맡는다.
이 작업은 어휘가 풍부해질 때까지 기다릴 필요가 없다. 대명사/자유로운 정정 발화의 이해는 P3와 별도 검증한다.

**P6b 연구 — 일반화 학습:** 교정이 다른 표현/문제에도 도움이 되는 연결이나 규칙으로 바뀌는지 잰다.
먼저 L0~L3로 필요한 뜻/사건 틀, 학습 사례, 독립 대조 사례 중 무엇이 부족한지 확인한다.
‘재고 부족’이라는 말만으로 무차별 수집을 시작하거나, 저장 기능만 만든 뒤 학습 완성으로 처리하지 않는다.

1. 현재의 원문 관찰 기록·명시적 정정·재계산·재시작 복구는 유지한다.
2. 이후 대명사/생략 연결, 사건 ID, 시간·장소 범위, 정정으로 무효가 되는 결론을 추가한다.
3. 같은 질문이나 사건을 다시 읽었다고 수량이 두 번 바뀌지 않게 한다.
4. 사용자의 교정을 표현 학습/사실 교정/추론 규칙 교정으로 구분한다.
5. `marco/learning/expressions.py`, `marco/learning/rules.py`, `marco/learning/feedback.py`를 이용해 후보를 만들고,
   기존 회귀와 학습에 쓰지 않은 긍정·부정 사례로 전이를 검사한다.
6. 통과한 변화만 overlay에 저장한다. 실패한 후보·추측·검색 발췌를 검증된 사실로 섞지 않는다.
7. 배운 내용을 팩으로 내보내고, 다른 실행 환경에서 다시 읽었을 때 같은 향상이 나타나는지 확인한다.

**완료 기준:** 새 관계/표현을 한 번 교정한 뒤 다른 문제에서도 개선되고, 재시작·팩 이동 후에도 유지된다.
정답 문자열을 외워 같은 질문에만 답하는 것은 실패다.

### P7. 답변 품질과 지능을 독립적으로 검증한다

**평가 설계는 맨 처음 시작한다.** 번호가 마지막이라는 이유로 구현 뒤에 정답/합격 기준을 만들지 않는다.
L3의 진단 실험과 제품의 원문 입력 성능을 분리하며, 연구 과제는 확장 전에 새 표현에서의 개선을 보여야 한다.

#### P7a. 실제 답의 의미를 채점하는 기준선 — 우선 구현

**현황 정정:** `350988f`에서 `bench/answer_quality.py`가 추가됐다. 아래는 완성 조건이며
모두 구현됐다는 뜻이 아니다. 기존 평가를 보강하고 별도의 동일 기능을 다시 만들지 않는다.

현재 `yardstick.evidence_group`은 `best[1] == x["그래프"]`를 센다. 이름에 ‘근거’가
들어가도 최종 답 정확도가 아니다. 기존 라우팅 줄을 유지하고 **별도의 실제 응답 평가**를 추가한다.

**입력/정답 자료**

- 문항마다 ID, 질문/다턴 이력, 팩 지문, 답할 수 있는지 여부, 필수 결론,
  금지되는 주장/모순, 적용 조건, 허용되는 근거를 기록한다.
- 런타임에는 질문/이력/팩만 전달한다. 정답 그래프·예상 결론·문제 분류는 채점기만 본다.
- 개발 진단군과 보지 않은 평가군을 분리한다. 로그에 섞인 시험 문장을 학습시키지 않는다.
- 별칭 제거 조건은 후보 검색뿐 아니라 최종 판정/답변이 읽는 자료에서도 확인한다.
  정상 팩 사용 성능과 별칭 제거 일반화 성능은 다른 표로 보고한다.

**채점 방법**

- 숫자/상태는 값·단위·대상·시간/장소 범위를 함께 비교한다. 숫자가 등장했다는 이유로 통과시키지 않는다.
- 설명은 정해 둔 핵심 명제의 충족과 잘못 덧붙인 주장을 확인한다. 다른 올바른 표현/근거 경로는 허용한다.
- 문장 유사도나 키워드 포함만으로 의미 정답을 확정하지 않는다. 자동 판정할 수 없는 설명은
  사전 기준에 따른 사람 검토로 남긴다. 판정 불가를 정답/오답으로 몰래 바꾸지 않는다.
- 근거는 결론을 실제로 뒷받침해야 한다. 출처 URL이나 그래프 경로가 있다는 사실만으로 통과시키지 않는다.
- 단정 답/부분 답/조건부 답/재질문/미지/실행 오류를 구분한다. 오류 문항을 분모에서 조용히 빼지 않는다.

**반드시 함께 보고할 지표**

1. 전체 과제 성공률: 올바르게 해결한 답변 가능 문항 수 / 전체 답변 가능 문항 수.
   풀 수 있는 문제에 미지로 답하면 성공이 아니다.
2. 단정 답 정확률과 응답률: 맞는 단정 답 / 모든 단정 답, 단정 답 / 전체 문항.
   단정 답이 없으면 정확률은 100%가 아니라 미정이다. 응답률이 다른 두 시스템의 오류율을 단독 비교하지 않는다.
3. 근거 충족률: 내용상 결론을 뒷받침한 응답 / 근거 검증 대상 응답. 검토되지 않은 비율도 따로 적는다.
4. 적절한 보류율: 정보 부족/모호한 문항에서 적절히 재질문·보류한 수 / 해당 문항 수.
   밖 물음 24/24를 모든 미지 입력에 대한 보장으로 확대하지 않는다.
5. 지시 준수와 다턴 상태 정확도: 지정된 형식, 동일 개체/사건의 유지, 정정 반영, 반복 사건 방지를 별도로 센다.

**실행/산출물**

- `bench/dialogue_evaluation.py`의 실제 `AppState.turn` 경로와 기존 추론 자료를 재사용하되,
  정확 문자열 비교만으로 끝나는 기존 방식에 위 의미 판정/보류 분류를 보강한다.
- CLI와 실제 UI가 선택한 팩으로 각각 실행해 차이를 보고한다. 웹은 고정된 외부 근거를 주는 평가와
  로컬 평가를 분리하며, 실시간 검색 결과 변화가 코드 개선으로 집계되지 않게 한다.
- 문항별 응답·근거·판정 이유·지연, 각 지표의 분자/분모, 코드/팩/자료 버전과 변경 전후 차이를 저장한다.
- B·C 개선은 이 표에서도 확인한다. 정답 그래프 선택만 늘고 최종 답이 틀리면 지능 개선으로 집계하지 않는다.

완료 기준: 채점기를 고의적인 오답·잘못된 단위/개체·그럴듯한 무근거 설명·과도한 거절로 시험하고,
올바른 바꿔 말하기는 통과하는지 확인한다. 개발자 자신의 성공 예시만 검증하지 않는다.

#### P7b. 응답 구성과 더 넓은 능력 평가

1. 검증된 결론·근거·필요한 가정에서 응답 계획을 만든다. 기본은 짧은 답, 필요할 때 계산/근거를 펼친다.
2. 요약·비교·설명은 그래프에서 필요한 내용을 선택하고 조합한다. 웹 페이지의 메뉴나 계산기 버튼 목록을 답처럼 내보내지 않는다.
3. 불확실한 해석은 후보/가정으로 표현할 수 있어야 한다. 불확실하다는 이유만으로 모든 요청을 거절하거나 검색에 넘기지 않는다.
4. 평가를 계산, 관계, 사건, 시간/공간, 조건/제약, 짧은 독해, 다턴 정정, 요청 수행, 설명으로 나눈다.
5. 개발용 자료와 숨긴 최종 평가를 분리한다. 단지 개체명을 바꾸지 말고 표현·관계 조합·문서/그래프를 분리한다.
6. ‘GPT-3 수준’은 비교 대상과 평가 절차를 먼저 정하고 실제 비교 후 판단한다.
   자체 제작 예제 몇십 개의 만점이나 테스트 개수로 선언하지 않는다.

**완료 기준:** 각 능력의 정답률/근거 정확도/오답 확신/미지 비율/자원 사용을 함께 보고한다.
성능이 정체되면 예문만 계속 추가하지 말고, 의미 후보 선택 부품의 학습 가능성 등 구조 가설을 제한된 실험으로 비교한다.
큰 상시 LLM 도입은 이 계획의 해결책이 아니다.

## 4. 경량화는 전 단계에서 측정하되 지능 개발을 대신하지 않는다

- 매 변경에서 전체 앱 시작 시간, 첫 답/웜 답 지연, 상주/최대 RSS, 팩 크기, 저장·복구 비용을 기록한다.
  작은 함수의 시간이나 Python 할당 추적만으로 전체 메모리를 주장하지 않는다.
- 먼저 중복 파서 생성·전체 deepcopy·중복 문자열·전체 그래프 펼치기 비용을 측정한다.
- 효과가 확인되면 불변 자료 공유, 정수 ID, 지연 로드, 필요한 규칙만 실행, 상한 있는 캐시,
  증분 무효화, 압축/메모리 매핑을 적용한다. 파생 색인은 배포 팩에 고정하지 않는다.
- 자원 상한에 걸리면 그 이유를 남긴다. 후보를 조용히 버려 답을 바꾸지 않는다.
- 구현 교체 가능성을 위해 숫자 정밀도·정렬/동률 처리·규칙 적용·원문 위치·정규화 규격을 문서화하고
  공통 입출력 시험 자료를 제공한다. 다른 언어 엔진 구현 자체는 담당 작업과 조율한다.

## 5. 작은 모델이 토큰을 낭비하지 않게 일하는 절차

한 작업은 다음 다섯 가지로 끝낸다.

1. **실패 하나의 재현:** 실제 진입점에서 입력·팩 지문·중간 결과를 확보한다.
2. **원인 가설 하나:** 어느 계층이 왜 잘못되는지 적는다. 이미 했던 실험은 기록을 먼저 찾는다.
3. **일반적인 변경 하나:** 관련 파일만 고친다. 전체 구조 재작성과 별도 기능을 끼워 넣지 않는다.
4. **관련 검사 → 통합 검사:** 자주 돌릴 것은 짧은 검사, 전체 잣대는 의미 있는 단계의 완료 시 돌린다.
5. **짧은 인수인계:** 변경 파일, 실제 결과, 안 된 것, 다음 한 가지를 `HANDOFF.md` 맨 위에 남긴다.

같은 실패에 두 번의 실험이 진전이 없으면 변형을 계속 추가하지 말고 가설을 다시 진단한다.
큰 로그/전 파일을 반복 읽지 않는다. 고정 평가의 정답을 개선 코드의 입력으로 쓰지 않는다.
사용자의 별도 요청 없이 새 작업/하위 에이전트, 커밋/푸시, 서비스 재시작을 만들지 않는다.

## 6. 검증 명령과 판정의 범위

```sh
KG_ENCODER=문자 python -m pytest -q tests/test_pack_model.py
KG_ENCODER=문자 python -m pytest -q
KG_ENCODER=문자 python kgpack.py --check
KG_ENCODER=문자 python engine.py --regress
KG_ENCODER=문자 python -m bench.yardstick
```

`bench/yardstick.py --얼리기`는 실행하지 않는다. 기존 잣대는 유지한다.
`bench/dialogue_evaluation.py`는 `--output`이 필요하며 `--dataset`으로 기존 16/14문항 자료를 선택한다.
결과 파일은 별도 경로에 남기고 기준 결과를 덮어쓰지 않는다. 이 세트들은 이미 개발에 사용했으므로 블라인드가 아니다.

파일 이동은 팩 왕복/누락 검증, 파서 변경은 의미 대조/일반화, 추론 변경은 전제 변조/모순,
학습 변경은 전후 전이/회귀, 자원 최적화는 같은 출력과 측정된 자원 감소로 각각 판단한다.

## 7. 사용자에게 남아 있는 결정

- 공리 위치: **`axioms/`로 확정. 다시 묻지 않는다.**
- 이해 실패 시 웹 조사, 재질문, 조건부 답변 중 어떤 정책을 기본으로 할지: 미정.
- 두 추론 경로의 최종 통합 방식: 미정. 공통 문맥/결과 연결은 먼저 진행 가능.
- GPT-3 수준의 구체적인 비교 과제와 합격 기준, 실제 기기의 메모리/지연 예산: 미정.

정책 결정을 기다리는 동안에도 P0~P4의 공통 기반 작업은 진행할 수 있다.
수치 목표를 임의로 만들어 사용자 승인이나 일반 지능 달성의 증거처럼 쓰지 않는다.

## 8. 다음 모델이 처음 수행할 구체적인 작업

1. 최신 코드와 작업 차이를 확인한다.
2. `bench/answer_quality.py`를 재사용하고, 문자열 부분 일치에 따른 오채점과 예외가 보류 성공이 되는
   경로를 개발용 채점 테스트로 막는다. 평가 문항을 맞히도록 본체를 개별 수정하지 않는다.
3. §3의 1번에 해당하는 개발용 설명·질문을 준비하고, 올바른 구조를 직접 주는 진단과 원문 설명 실행을 비교한다.
4. 처음 확인한 공통 실패 하나를 고치고, 설명 후 새로운 질문과 의미가 다른 대조 문장에서 다시 확인한다.
5. 이후 §3의 H1/H2와 설명 적용·교정 실험으로 이어간다. 검증되지 않은 큰 파서 공사나 사전 수집을 앞세우지 않는다.

위 목록은 구현 요청을 받은 다음 작업의 시작점이다. 이번 개정은 계획 작성만이며
코드 수정·검사 실행·배포·커밋·푸시는 하지 않았다. 인사/일반 KG 팩 격리 등 P1의 남은 일은
실제 실험 경로에 필요한 부분부터 함께 처리한다.
