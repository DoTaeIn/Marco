# 새 지식 그래프 만들기

엔진은 안 건드린다. `graph_*.json` 하나가 곧 역할 하나다.

```bash
cp graphs/graph_템플릿.kg graphs/graph_내것.kg        # 1. 복사
#                                       2. 채운다 (아래 참고)
python engine.py --diagnose graphs/graph_내것.kg   # 3. 점검
python engine.py --tune graphs/graph_내것.kg   # 4. 임계값 확인
python engine.py --edges graphs/graph_내것.kg data/  # 5. 빠진 엣지 후보 (사슬이면 필수)
python engine.py --regress                    # 6. 실제 판례 기대 승패 회귀
python engine.py graphs/graph_내것.kg          # 7. 굴려본다
```

## 판례를 md 로 쓰기 (에피소드 추가)

법리(형법 21조 28노드)는 이미 `법리_형법21조.kg` 에 있다.
**판례마다 새로 쓸 것은 증거·사실과 그 연결뿐이다.**

```bash
cp cases/사건_템플릿.md cases/사건_새판례.md
python engine.py --case cases/사건_새판례.md    # -> cases/사건_새판례.kg
python engine.py cases/사건_새판례.kg           # 바로 플레이
```

```markdown
# 편의점 야간 알바생 폭행 사건

## 사건
- 역할: 검사
- 목표: 정당방위
- 법리: 법리_형법21조.kg

새벽 2시, 흉기를 든 강도가 들어와 금품을 요구했다.   ← 설명 문단은 자유

## 증거
- CCTV: 시시티비, 매장 영상
- 진단서: 피고인 진단서, 병원 기록

## 사실

### 흉기소지
- 증거: CCTV, 압수된흉기
- 말: 흉기를 들고 있었습니다 / 칼을 꺼냈습니다 / 무기를 소지했습니다
- 충족: 부당한 침해였다, 침해가 현재 진행 중이었다
```

**법리 이름을 외울 필요가 없다.** `충족:` / `부정:` 에 자연어로 쓰면 매처가
가장 가까운 법리 노드에 붙이고 무엇을 골랐는지 보고한다:

```
법리 매칭 16건 (실패 0 · 약함 0)
```

신뢰도가 낮으면 붙이지 않고 알려준다:
```
X 0.524  서명함.충족 "채무불이행이 있었다" -> 붙이지 못함
[주의] 붙지 못한 연결은 그래프에서 빠졌다. 법리 표현을 바꿔 다시 써라.
```

컴파일 직후 `--diagnose` 가 자동으로 돌아 이길 수 없는 그래프와 고아 사실을 잡는다.

## `.kg` 형식

화살표가 눈에 보이는 텍스트 형식이다. `#` 은 주석.

```
역할: 검사
목표: 정당방위
임계값: 0.50 / 0.60
포함: graph_연구.kg          # 다른 주제 그래프의 개념 빌리기
이름말: 용어                 # 대사에 노드 이름을 쓸까 예시 문장을 쓸까
전진관계: 증명, 충족          # 목표 쪽으로 밀어주는 관계 (기본값)
부정관계: 부정               # 상대를 무너뜨리는 관계 (기본값)
근거관계: 증명               # 사례층 노드를 '증거'로 만드는 관계 (기본: 전진관계의 첫 항목)

[개념]
정당방위:      "정당방위입니다" | "정당한 방어였습니다"
침해의현재성:   "침해가 진행 중이었습니다" | "그 순간 위험했습니다"

[사례]
*CCTV:        "CCTV" | "매장 영상"          # * 는 증거라는 표시(읽는 사람용)
흉기소지:      "흉기를 들고 있었습니다"
연소득요건 {원 >= 50000000}: "연소득이 6천만원입니다"   # 수치 조건

[무관]
_잡담:        "점심 뭐 드셨어요" | "날씨가 좋네요"

[논증]
CCTV       -증명->  흉기소지, 선제공격, 출구차단
흉기소지     -충족->  침해의현재성, 침해의부당성
선제공격     -부정->  침해의현재성

[대사]
인정: 확실히 {ev}에 「{말}」는 점은 인정하겠습니다.
```

* 노드 한 줄: `이름: "예시" | "예시" | "예시"` — **예시는 말투를 바꿔 3개 이상**
* 엣지 한 줄: `출발 -관계-> 도착1, 도착2` (`→관계→` 도 된다)
* 파싱 오류는 줄 번호와 함께 나온다

## 채우는 순서

### 1. `목표` — 도달하려는 결론 하나
`정당방위` / `급성심근경색` / `DB병목` / `대출승인`

### 2. `공통층` — 목표에 이르는 개념
**`충족` 으로 목표에 직접 붙는 노드가 곧 승리 요건이 된다.** 따로 적지 않는다.

에피소드가 여럿이면 여기가 공유 자산이다. 한 번 쓰고 계속 재사용한다.

### 3. `사례층` — 이 사건의 증거와 사실
* **증거** = 고유명사. `CCTV`, `진단서`, `APM트레이스`. **문자열로 찾으므로 별칭을 넉넉히 적는다.**
* **사실** = 명제. `흉기를 들고 있었습니다`. **임베딩으로 찾으므로 말투가 다른 예시를 3개쯤 적는다.**

증거인지 사실인지는 따로 표시하지 않는다. `증명` 엣지가 나가면 증거다.

### 4. `엣지` — `[출발, 관계, 도착]`
| 관계 | 쓰는 곳 |
|---|---|
| `증명` | 증거 → 사실 |
| `충족` | 사실 → 개념, 개념 → 개념 |
| `부정` | 무너뜨리는 관계 |

`부정` 은 **목표로 전진하는 노드를 무너뜨릴 때만** 반격이 된다.
방해 노드를 부정하는 것은 플레이어에게 이득이다.

### `[개념망]` (선택) — 단어와 단어의 관계

논증 그래프(`증거 → 사실 → 요건`)와 **다른 층**이다. 여기는 단어 사이 관계만 담는다.

```
[개념망]
과도    -상위->  흉기, 칼
각목    -상위->  흉기
쇠파이프 -상위->  흉기
```

한 줄 적으면 **모든 예시 문장이 자동으로 불어난다.**
`"흉기를 들고 있었습니다"` 하나에서 과도·각목·쇠파이프 변형이 생긴다.

| 발화 | 개념망 없이 | 개념망 있이 |
|---|---|---|
| 과도를 들고 들어왔습니다 | 0.580 | **0.905** |
| 각목을 들고 있었습니다 | — | **0.999** |
| 우산을 들고 있었습니다 | — | 0.536 (그대로 낮음) |

노드의 예시 목록 자체는 안 늘어난다 — 벡터만 는다. 파일은 깨끗하게 남는다.
과잉 일반화도 안 한다: 흉기가 아닌 것은 안 딸려온다.

**이 층은 논증 순회에 끼어들지 않는다.** 방향이 위로만 간다(하위어 → 상위어).

### 5. `[무관]` (선택) — 딴소리 판별용
잡담·다른 주제 예시. **다른 그래프를 `포함` 하면 걸러진 개념이 자동으로 여기 들어간다.**
주제를 많이 알수록 판별이 좋아진다.

### 6. `수치조건` (선택) — 숫자가 결론을 가를 때
```json
"수치조건": { "연소득요건": {"단위": "원", "최소": 50000000} }
```
노드는 *무엇에 대한 주장인가*, 숫자는 *충족되는가*. 매칭할 때 숫자는 가려진다.
`3억 5천만원` 같은 한국식 자릿수를 읽는다. 애매하면 추측하지 않고 되묻는다.

### 7. `대사` — 필수 8종 + 선택
필수: `B2 B2_강등 A 근거없음 인정 인정_반격 C B1`
선택(`_말` 계열, `요건충족`, `남은요건`, `힌트_증거`, `압박`, `수치미달`)은
있으면 대답이 길고 자연스러워지고, 없으면 한 줄로 답한다.

`{말}` 에는 **노드의 예시 문장 중 유저 말투에 가장 가까운 것**이 들어간다.

### 8. `이름말` — `{claim}`/`{ev}`/`{bad}` 자리에 무엇을 넣나

기본값 `용어`. 노드 이름을 그대로 넣는다.

    A: 혹시 [{claim}]을 말씀하신 건가요?   ->   혹시 [방위의사]를 말씀하신 건가요?

법리·의료·금융 그래프는 이게 맞다. `방위의사`, `트로포닌상승`, `DSR요건` 은
그 인물이 실제로 입에 올리는 말이다.

`이름말: 문장` 으로 두면 그 노드의 **예시 문장**이 대신 들어간다.

    A: 혹시 "{claim}" 그런 뜻이야?        ->   혹시 "네가 그리웠어" 그런 뜻이야?

NPC 그래프는 노드 이름이 `마음고백`·`그리움` 처럼 **기획자가 붙인 내부 딱지**다.
그대로 읽으면 인물이 자기 상태를 낭독하는 것처럼 들린다 —
`혹시 [마음고백]을 말한 거야?`

> 이름이 제 예시 안에 나오는지로 자동 판별해 봤으나 못 쓴다. 법리 노드는
> 이름이 용어인데도 예시에는 안 나온다(`침해의현재성` <- "지금 칼을 들고
> 있었다"). 30개 그래프 1063개 노드 중 779개가 딱지로 잘못 걸렸다.
> 구조로 갈리는 구분이 아니라 **저작 의도**다.

`문장` 으로 둘 때는 **값 뒤에 조사를 바로 붙이지 말 것.** 문장이 통째로
들어오므로 `"{claim}" 그런 뜻이야?` 처럼 띄우거나 따옴표로 감싼다.

### 9. 관계 어휘 — `전진관계` / `부정관계` / `근거관계`

관계 이름은 엔진이 정하지 않는다. **그래프가 정한다.** 안 적으면 법정 어휘
(`증명`·`충족`·`부정`)를 쓰므로 기존 그래프는 그대로다.

엔진이 필요로 하는 구조적 역할은 셋뿐이다.

| 머리말 | 뜻 | 엔진이 이걸로 하는 일 |
|---|---|---|
| `근거관계` | 사례 -> 개념 | 이 관계를 가진 사례층 노드가 **증거**가 된다 |
| `전진관계` | 개념 -> 목표 | 목표로 직접 오는 것이 **요건**(승리 조건) |
| `부정관계` | X -> Y | Y 를 무너뜨린다. 반격·자책 판정에 쓴다 |

`근거관계`는 `전진관계` 안에 있어야 하고, 안 적으면 `전진관계`의 첫 항목이다.

> 셋을 하나로 뭉치면 안 된다. `근거관계`를 `전진관계` 전체로 두면 `충족` 엣지를
> 가진 사실까지 증거로 세어 **30개 중 25개 그래프의 증거 목록이 부푼다**(실측).

법정 어휘를 한 개도 쓰지 않는 예가 `graphs/npc_대장장이.kg` 다.

```
전진관계: 내놓음, 뜻함
부정관계: 걸림돌
근거관계: 내놓음

[논증]
부러진검 -내놓음-> 고칠물건있음
고칠물건있음 -뜻함-> 검을고쳐준다
외상     -걸림돌-> 삯을치름
```

### 10. 발화가 통째로 증거일 때

법정에서 증거는 `"CCTV를 보면 ~"` 같은 **앞표지**라 주장이 뒤에 남는다.
NPC 는 다르다 — 손님이 `"검이 부러졌어"` 하면 **그 한마디가 곧 증거**이고
주장은 글 어디에도 없다.

이때 엔진은 주장을 글에서 다시 찾지 않고 **근거관계 엣지를 따라간다.**
지어내는 것이 아니라 기획자가 그은 선을 읽는 것이므로 환각이 늘지 않는다.
이 길이 없을 때는 예시 그대로 말해도 전부 `미지` 가 나왔다.

### 11. `임계값`
`A_MIN` 미만은 딴소리, `OK_MIN` 이상은 확정, 사이는 되묻기.
**공통층이 커지면 반드시 다시 재야 한다.** 기본값 0.50 / 0.60.

## 다른 그래프 붙이기

```json
"포함": ["graph_연구.json"]
```
상대의 **공통층만** 빌려온다. 사례층은 안 온다 — 개념은 재사용 대상이지만
사례는 그 사건의 것이다.

붙이는 것만으로는 아무 일도 없다. 목표와 이어지는 **다리 엣지** 하나를 그어야
두 주제가 결합한다. 안 이어진 개념은 자동으로 널 클래스가 되므로 붙여도 손해가 없다.

## `--diagnose` 가 잡아주는 것

| 표시 | 뜻 |
|---|---|
| `X 그래프 오류` | 형식이 깨졌다. 목표 오타, 미정의 노드, 대사 키 누락 등 |
| `[치명] 증거가 못 닿는 요건` | **이길 수 없는 그래프.** 그 요건에 닿는 증거를 만들어야 한다 |
| `[경고] 고아 사례층 노드` | 어떤 개념에도 안 붙었다. 링크를 빠뜨렸다 |
| `[정보] 항상 B1 이 되는 개념` | 증거가 없는 개념. 해당 없는 법리라면 정상이다 |

---

## 잘 안 될 때

**딴소리가 인정된다** → `무관층` 에 그 부류의 예시를 넣는다. 또는 다른 주제 그래프를 `포함` 한다.

**맞는 말인데 B2 로 기각된다** → 그 노드의 예시 문장이 유저 말투와 너무 다르다. 예시를 늘린다.

**되묻기(A)만 나온다** → 예시가 부족하거나 `OK_MIN` 이 높다.

**숫자를 엉뚱하게 읽는다** → 증거 별칭에 숫자가 섞였는지 본다. 단위를 명시한다.

**이길 수가 없다** → `--diagnose` 의 `[치명]` 줄을 본다.

# 알려진 한계

솔직하게. 이 엔진이 지금 못 하거나, 확인되지 않은 것들.

## 1. 정확도 수치가 자기 채점이다 — 가장 큰 구멍
노드의 예시 문장과 검증용 발화를 **같은 사람이 썼다.** 그래서 "26건 오분류 0" 같은
숫자는 낙관적이다. 실제 사용자는 다르게 말한다.

**대책:** 남이 쓴 발화 수백 개로 다시 재야 한다. 그 전까지 모든 정확도 수치는 참고용이다.

## 2. 노드 표현이 겹치면 절반은 엉뚱한 곳으로 간다 — `--tune` 으로 잰다
```bash
python engine.py --tune graphs/graph.kg              # 외부 데이터 없이
python engine.py --tune graphs/graph.kg 발화_샘플.json  # 남이 쓴 발화로 (권장)
```

외부 데이터가 없으면 **leave-one-out** 으로 잰다. 각 예시 문장을 자기 노드에서
하나씩 빼고 맞히는지 본다 = "예시에 없는 표현을 썼을 때 맞히는가".
실제 유저는 우리 예시문을 쓰지 않으므로 이 값이 현실에 가깝다.

실측 (leave-one-out 자기 노드 적중률):

| 그래프 | 적중 |
|---|---|
| `graph_대출.json` | **86%** (연소득/DSR/신용점수/담보가 서로 뚜렷하다) |
| `graph.kg` (법정) | **50%** |
| `graph_코드리뷰.json` | 46% |
| `graph_의료.json` | **37%** (심근경색 주변 개념이 서로 너무 비슷하다) |

낮은 값은 **엔진이 아니라 그래프 문제**다. 뜻이 거의 같은 노드가 서로 뺏는다:

```
0.905  과잉방위 -> 방위행위의과잉   <- "정도를 초과했습니다"
0.880  정당방위 -> 상당성           <- "정당한 방어였습니다"
0.867  침해의존재 -> 침해의현재성   <- "침해가 있었습니다"
```

**고치는 법:** 예시 문장을 노드마다 구별되게 다시 쓰거나, 뜻이 겹치는 노드를 합친다.
`--tune` 이 상위 충돌 쌍을 짚어준다.

임계값 추천도 같이 나온다. 다만 `A_MIN`/`OK_MIN` 은 공통층 크기에 따라 움직이므로
(8노드 간격 0.19 → 28노드 0.05) **그래프를 키울 때마다 다시 돌려야 한다.**

## 3. 시작이 느리다 — 첫 발화까지 약 14초
| | |
|---|---|
| 모델 로드 | **13.9s** (병목) |
| 그래프 로드 | 0.18s (벡터 디스크 캐시 적용 후. 캐시 없으면 15s) |
| 발화 1건 | **10ms** |
| 프로세스 메모리 | **약 1.5GB** |
| 모델 파일 | 422MB |

발화 처리 10ms 는 충분히 빠르다. 문제는 시작과 메모리다.
설계 문서의 "스마트폰 RAM 2GB 이하" 주장은 아슬아슬하고, **실제 모바일에서 검증한 적이 없다.**

**대책:** `multilingual-MiniLM`(118MB)으로 바꾸면 로드와 메모리가 크게 준다.
단 임계값을 전부 다시 재야 한다.

## 4. 숫자: 못 읽는 표기가 있다
| 표기 | |
|---|---|
| `60,000,000원` `3억 5천만원` `1조 2천억원` `약 6천만원` | 읽음 |
| `육천만원` `삼억원` (순한글 수사) | **못 읽음 → 되묻기** |
| `5천~6천만원` (범위) | **못 읽음 → 되묻기** |
| `1억 2천 3백만원` (뒤의 만이 앞으로 분배) | **애매 → 되묻기** |

틀리게 읽느니 되묻는 쪽을 택했다. 순한글 수사가 필요하면 곱셈표를 늘리면 된다.

## 5. 자책 논증은 복구할 수 없다
자기 논증이 요건을 무너뜨리면 **즉시 패배**다. 그래프에 부정을 되돌릴 경로가 없기 때문이다.
게임으로서는 가혹하다. 재반박을 넣으려면 '부정을 부정하는' 구조가 필요하다.

## 6. 한 판이 짧다
5요건 = 증거 5개 = 5수. 사례층이 두꺼운 에피소드를 만들어봐야 실제 길이를 알 수 있다.

## 7. 한국어만 검증했다
예시 문장이 전부 한국어다. 다른 언어는 시도한 적 없다.

## 8. 생성은 못 한다 — 설계상
그래프에 없는 내용은 절대 나오지 않는다. 이것이 무환각과 탈옥 저항성의 근거이지만,
동시에 **모르는 것에 대해 말할 수 없다**는 뜻이다. 자유 대화나 창작에는 쓸 수 없다.

경계 밖 발화는 두 갈래로 처리한다:

| 판정 | 조건 | 뜻 |
|---|---|---|
| `B2` | 무관층이 이겼다 | **무관하다** — 다른 주제라는 적극적 증거가 있다 |
| `미지` | 아무것도 안 걸렸다 | **모른다** — 증거의 부재. 무관하다고 단언하지 않는다 |

둘을 뭉쳐 "관련 없습니다"라고만 답하면, 그래프에 없는 **유효한 논증**에 대해
시스템이 거짓말을 하게 된다. 예:

```
> 피고인에게 퇴각할 의무가 없다는 판례가 있습니다
  검사: 무슨 말씀인지 모르겠습니다. 이 재판에서 다루는 쟁점으로 다시 말씀해 주십시오.
```
이것은 한국법상 **맞는 논증**이다. 노드가 없을 뿐이다. "관련 없다"고 하면 거짓말이다.

미지 발화는 `<그래프이름>.미지.log` 에 쌓인다. 읽고 그래프를 키우면 된다 —
**그래프가 사용자에게서 자란다. 재학습은 없다.**

## 9. 순서·시간 계획을 못 다룬다
`A 다음 B 다음 C` 같은 절차 추론은 그래프 도달성으로 표현되지 않는다.

## 10. 개념 이름이 전역이다
주제 그래프를 여러 개 `포함` 하면 같은 이름이 충돌한다. 지금은 로드를 거부해서
알려주지만, 주제가 수십 개가 되면 접두어 규칙이 필요하다.
