# 관계 해석 실패의 위치와 원인

`python semantic_feedback.py diagnose '질문'`은 관계 해석 실패를 문장별로 나눈다.
처음 실패한 곳에서 나머지를 버리지 않고 모든 미인식 절의 원문과 시작·끝 위치를
`diagnostics`에 기록한다. 이 부분 자료를 답의 전제로 사용하는 것은 아니다.
원문 전체를 해석하지 못하면 기존처럼 답변을 보류한다.

- `unrecognized_clause`: 학습된 해석 후보가 없는 절.
- `ambiguous_clause`: 다른 명확한 절과 대조해도 후보가 하나로 정해지지 않음.
  경쟁하는 삼중항이나 질의 구조를 함께 기록한다.
- `missing_facts` / `missing_query`: 표현 자체의 미인식과 구별되는 구조 부족.
- `multiple_queries_or_invalid_meaning`: 현재 단일 질의 구조에 맞지 않는 후보.

해석이 완료됐지만 답을 얻지 못하면 `missing_proof`와 `nonunique_proof`를 구분한다.
여러 후보가 나오는 경우 각 후보의 사실과 증명 경로를 반환한다. 기존 `reason`의
`missing_or_nonunique_proof` 코드는 이 두 값으로 세분화됐다.

실행 예제에서 '돌은 23개 있다. 몇 개를 덜어냈는지 모르겠다. 지금 돌은 몇 개야?'
는 미인식된 두 번째 절을 정확하게 지정한다. 처음의 23개만 사용해 답하지 않는다.
범위는 관계 해석기이며, 수식·일반 지식 검색의 모든 실패 원인을 분류하는 것은 아니다.
모르는 절에 올바른 의미를 자동으로 붙이거나 교정을 자동 승인하지도 않는다.

원문 위치, 복수 미인식 절, 모호한 구조의 경쟁 후보, 질문 누락, 근거 부족과
상충하는 복수 답변을 검사했다. 관련 해석·학습·수사 회귀 33개가 통과했다.
전체 목표의 자유로운 표현 이해와 감독 부담 감소는 계속 남아 있다.
