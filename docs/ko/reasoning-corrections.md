# 대화의 사실 정정

채팅에서 다음 형식으로 이미 저장한 관찰 문장을 정정할 수 있다.

```text
돌은 23개 있다.
돌 8개를 꺼냈다.
정정: 돌은 23개 있다 => 돌은 31개 있다.
지금 돌은 몇 개야?
```

답은 23개다. 초기값이 31로 정정된 뒤 기존의 8개 제거 사건이 다시 적용된다.
정정 문장을 새로운 수량 사건으로 추가하지 않는다. 앞서 저장한 관찰 한 개를
지정해야 하며, 같은 문장이 여러 번 있으면 어느 사건인지 모호하므로 거부한다.
끝의 문장 부호와 양끝 공백은 대상 비교에서 제외한다.

`ReasoningContext.correct(index, replacement, knowledge_path)`는 지정 관찰을
복사본에서 교체하고 모든 관찰을 원문 순서로 재해석한다. 후속 사건이 적용 불가능해지면
전체 정정을 취소한다. 예를 들어 초기값을 3으로 바꾸면 뒤의 8개 제거가 불가능하므로
기존 23개 초기값이 유지된다. 질문·해석 불가능 문장은 교체 사실로 받지 않는다.

답변과 중간 추론 결과는 사실 저장소에 저장하지 않으므로, 정정 후 질문할 때
새 사실만으로 추론한다. 키 비교 사슬의 첫 관계를 부정으로 정정하면 그 관계에
의존한 결론이 사라지고, 관련 없는 비교의 답은 유지된다.

저장은 `reasoning-context-v2`다. 현재 관찰들과 정정의 전후 원문·관찰 인덱스를
함께 기록하며 v1 스냅샷도 읽는다. 정정 기록은 기본 128개로 제한된다.
기존 UI의 저장 및 실패 복구 경로에 연결되어 실제 앱을 다시 만들어도 정정 상태가
복원된다. 디스크 저장 실패 시 대화와 메모리 모두 이전 상태로 돌아간다.

검증: 정정·문맥·영속성 테스트 13개 통과. 수량 재계산, 추론 철회, 관련 없는
사실 보존, 실패 시 원자적 취소, 중복 대상 거부, 실제 UI 연구 미호출 및 재시작을 검사했다.

현재는 명시적인 전체 관찰 교체를 지원한다. '아니, 그 사람 말고…' 같은 자유로운
정정 발화, 한 관찰 안의 일부 문장만 교체, 정정 의도의 자동 발견은 지원하지 않는다.
문장 해석 모델을 바꾸는 표현 교정과 특정 대화의 사실 정정은 별개다. 전체 개발
목표의 남은 범위인 표현 일반화·검증된 학습·독립 종합 평가·자원 측정은 계속 진행 중이다.
