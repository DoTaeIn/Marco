# 가벼움 — 잰 값과 지키는 성질

2026-09-18. 목표 4번("가벼움을 수치로 관리")의 기록이다. 새 채점기는 만들지
않았다. 흔들리는 값(시간·메모리)은 여기에 적고, **흔들리지 않는 성질**은
`tests/test_lightweight_runtime.py` 가 지킨다.

## 잰 값 (이 기계, `KG_ENCODER=문자`)

    적재(import)              13 ms
    첫 턴                    354 ms
    세 턴 한 바퀴(반복)      1002 ms   -> 턴당 약 334 ms
    파이썬 할당 봉우리        4.2 MB
    프로세스 최대 RSS        31.4 MB   <- import 와 전체를 포함한다. 한 턴 비용이 아니다.

**턴당 334ms 는 작지 않다.** 라우팅·다시읽기가 매 턴 전체 관찰을 다시 푸는
구조라 대화가 길어질수록 늘 수 있다. 이 문서는 그것을 개선했다고 말하지 않는다 —
지금 값이 얼마인지만 적는다.

## 반복 상태 질의 (2026-09-18, 문자 팩)

같은 `ReasoningContext`에서 `민수 구슬은 100개 있다` 뒤에 꺼낸 사건을 1·8·20개
넣고, `지금 민수 구슬은 몇 개야?`를 다섯 번 물어 중앙값을 쟀다. 파서 인스턴스와
검증된 재생 결과를 재사용하는 **반복 질의 경로**만의 값이다. 초기 적재나 첫 사건,
전체 UI 라우팅 비용과 합치지 않는다.

    사건 수       답             반복 질의 중앙값
       1          99개입니다.       0.723 ms
       8          92개입니다.       1.723 ms
      20          80개입니다.       3.426 ms

초기화부터 마지막 질의까지를 별도 Python 프로세스에서 다시 재고, `tracemalloc`
할당 피크와 `resource.getrusage(RUSAGE_SELF).ru_maxrss`를 함께 읽었다. macOS의 이
값은 byte 단위이며, import와 해당 대화 전체를 포함한다.

    사건 수     전체 wall     Python 할당 피크     프로세스 최대 RSS
       1          359.557 ms       3.05 MB              24.56 MB
      20        1,134.357 ms       3.22 MB              25.33 MB

따라서 위 반복 질의 표와 이 표는 섞어 읽지 않는다. 전자는 이미 열린 대화에서의
질의 비용이고, 후자는 초기 준비·사건 처리·마지막 질의를 모두 포함한 상한이다.
`ReasoningContext`의 관찰 기록은 기본 128개로 제한한다. 한도 뒤의 사건을 조용히
버리지 않고 미해석 변화로 남긴다. 그 뒤 같은 대상의 값을 물으면 이전 값을 확정하지
않고 `조건부족`과 한도 메시지를 돌려준다
(`tests/test_reasoning_context.py`).

## 직접 상태 사건의 영향 구간 재생 (2026-09-18)

`돌은 100개 있다` 뒤에 `돌 1개를 꺼냈다`를 20번 넣고, 같은 프로세스에서 일곱 번
반복해 중앙값을 쟀다. 새 직접 사실만 읽는 경로와, 같은 입력에서 증분 경로를 꺼
전체 재생을 강제한 경로를 비교했다. 두 쪽 모두 최종 답은 `80개입니다.`였다.

    경로                         20개 사건 처리 중앙값
    직접 사실 영향 구간 재생          9.939 ms
    전체 재생 강제                    67.265 ms

이 수치는 조건·배운 동작·보완이 없는 직접 상태 사실에만 해당한다. 그런 입력은
과거 의미를 바꿀 수 있으므로 현재도 전체 재생을 선택한다. 따라서 이를 모든 대화의
일반 비용이나 초기 준비 비용으로 보고하지 않는다.

## 팩 크기

    기본 팩(정의 말뭉치 포함)   26.0 MB · 파일 959
    정의 말뭉치 없이            1.6 MB · 파일 958
    말뭉치가 차지하는 몫       24.4 MB

**핵심은 1.6MB 다.** 26MB 의 거의 전부가 `data/위키/정의문.jsonl`(원본 82MB)
하나이고, 그건 `.gitignore` 된 **선택 자산**이다. `kgpack.default_file()` 은 그
파일이 없으면 조용히 건너뛴다.

## 지키는 성질 (시험이 붙들고 있다)

- **기본 실행이 망을 안 탄다.** 세 턴 대화에서 소켓 연결 시도 **0회**로
  `6개입니다` 를 낸다.
- **안 고른 부품은 불러오지도 않는다.** 팩이 `부품` 에 적지 않으면
  `marco.language.passages` 는 `sys.modules` 에 들어오지 않고, 적으면 그때 들어온다.
- **기본 경로에 제삼자 꾸러미가 없다.** 대화 한 바퀴를 돌린 뒤 새로 들어온
  모듈 가운데 표준 라이브러리도 이 저장소 파일도 아닌 것은 **0개**다.

## 부품 선택 — 한 곳으로 모았다 (목표 2번)

`PackModel.component(종류)` 하나를 본다. 주입 > 팩 선언(`부품`) > 부르는 쪽의
기본값. 불러온 부품은 **팩마다 따로** 담기므로 팩 둘을 동시에 띄워도 안 섞인다
(`tests/test_component_selection.py`).

발췌 분류의 `NAI_PASSAGE_BACKEND` 는 걷어냈다. 환경변수는 한 실행 안에서 팩마다
다르게 고를 수가 없어, 팩을 둘 띄우면 나중에 켠 쪽이 앞엣것의 선택을 덮었다.

## 인코더도 팩별로 고른다

`인코더` 선언은 문자/신경망 방식, 문자 벡터 차원·자모 가중치·매끈값,
라우팅·군집·목표 문턱, CPU 장치를 함께 기록한다. `EncoderRuntime`은 그 선언을
팩마다 하나씩 가지며, `AppState`가 그래프 적재와 라우팅·판정 때 그 런타임을
활성화한다. 벡터 캐시 열쇠에도 인코더 구성이 들어가므로 차원·가중치가 다른
팩의 벡터를 재사용하지 않는다.

`tests/test_pack_model.py`은 한 프로세스에서 256차원 팩과 512차원 팩을 번갈아
열고 질문한 뒤, 먼저 연 팩의 그래프 벡터가 여전히 256차원이고 두 활성 벡터가
서로 다른 차원을 유지하는지 확인한다. 신경망 모델 이름이나 원격 주소는 팩에서
고를 수 없다. 선택지는 고정된 `문자`/`신경망`뿐이며 기본 팩은 CPU 문자 경로다.

개발용 `KG_*` 환경변수와 `encoder.MODEL` 같은 호환 이름은 선언 없는 옛 호출의
기본값으로 남는다. 선택된 팩의 실행 경로는 이 값을 읽지 않는다.

남은 선택용 환경변수(측정 당시 20개 중):

    KG_CMP KG_DEVICE KG_DIM KG_ENCODER KG_INDEX KG_JAMO KG_LANG KG_NEG
    KG_NEIGHBOR KG_NEIGHBOR_WIDTH KG_PROGRESS KG_SMOOTH KG_TOPIC_MIN
    NAI_DOCUMENT_VLM NAI_DOCUMENT_VLM_ALL NAI_LANGUAGE NAI_PDFTOTEXT
    NAI_RELATIONAL_MODEL

`NAI_PASSAGE_BACKEND` 하나가 빠져 **20 -> 19** 가 됐다. 나머지는 인코더·색인
쪽이라 위 한계와 같은 뿌리다.
