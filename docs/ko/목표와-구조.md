# 목표와 구조

이 문서는 **사람이 정한 것**을 적는다. 진행 기록은
[reasoning-development.md](reasoning-development.md), 왜 그런 설계인지는
[direction.md](direction.md) 에 있다. 여기 적힌 값은 전부 실측이고, 아직
정하지 않은 것은 "정할 것" 으로 남겨 둔다.

## 목표

> 하나의 모델을 공유해서 전 세계 사람들이 **가볍고**, 이 결과가 **어떻게
> 나왔는지 알 수 있는** 고성능 AI 를 쓸 수 있게 한다.

세 낱말이 다 조건이다.

- **하나의 모델** — 팩 하나를 받으면 누구나 같은 답을 얻는다. 코드 버전이
  달라도 같아야 한다.
- **가볍다** — 큰 언어 모델을 안 쓴다. 문자 인코더로 돌면 numpy 말고 아무것도
  안 올라온다(engine 들이는 데 14ms · 한 턴 1.1ms).
- **어떻게 나왔는지 안다** — 답마다 어느 그래프의 어느 문장에서, 어느 규칙으로
  왔는지 남는다.

## kgpack 이 무엇인가

대화는 **팩을 통해서만** 답을 낸다. 엔진 코드는 **예시 구현**이다 — 팩만 있으면
누가 어떤 언어로 다시 짜도 같은 답이 나와야 한다.

    kgpack (format: nai-kgpack)
    ├─ manifest.json
    │    manager   그래프끼리 잇는 엣지 = 노드매니저
    │    files     담긴 파일 목록
    ├─ graphs/     지식팩
    │    *.kg              분야 지식
    │    *.학습.jsonl       대화하며 늘어난 말
    └─ styles/     언어팩 (문장이해)
         한국어.json · english.json

**색인은 팩에 안 넣는다.** 지식에서 계산되는 것이라, 굳혀 두면 늘어난 지식이
실시간으로 안 붙는다. 임베디드처럼 껐다 켜는 자리에서는 `kgbin.py` 로 굳힐 수
있고 그건 선택지다.

잰 것 (`NAI.kgpack`): 파일 910개 — manifest 1 · graphs 907 · styles 2.
런타임 색인 캐시 `.색인벡터.npz` 39MB 는 팩 밖에 따로 있다.

## 스스로 늘어나고, 실시간으로 붙는다

대화하다 보면 지식이 세 갈래로 는다.

    세션 지식      이 대화 안에서만. 활성값이 식으며 옅어진다
    배운 말        .kg 옆의 .학습.jsonl 에 쌓인다
    새 그래프      자가저작이 지어 관문을 통과한 것

늘어난 것은 **바로 반영된다.** 색인 캐시 키가 `.kg` 옆의 `.학습.jsonl` 을 같이
보므로(engine.py:2584), 배우면 키가 바뀌고 색인이 저절로 다시 난다. 지금 로컬에
49개 파일이 쌓여 있다.

## 세 층 — 무엇이 어디에 사는가

지식팩과 언어팩만으로는 자리가 모자란다. 층이 셋이다.

| 층 | 사는 곳 | 담는 것 | 언어를 바꾸면 | 분야를 바꾸면 |
|---|---|---|---|---|
| 언어팩 | `styles/*.json` | 문장 쪼개기 · 조사 · 어미 · 수사 | **바뀐다** | 안 바뀐다 |
| 공리팩 | 팩의 새 칸 | 세상 이치 | 안 바뀐다 | 안 바뀐다 |
| 지식팩 | `graphs/*.kg` | 분야 지식 | 안 바뀐다 | **바뀐다** |

공리팩에 들어갈 것의 예:

    A>B, B>C  ->  A>C            비교의 추이성
    A isa B, B subclass C -> A isa C   분류의 상속
    꺼냄 = -1, 넣음 = +1          수량 사건의 방향

이건 요리든 법이든 천문이든 똑같이 성립한다. **특정 `.kg` 에 가두면 라우팅이 그
그래프를 못 고른 순간 못 푼다.** 그래서 분야와 따로 둔다.

## 두 가지 규율

**① 근거가 보여야 한다.** 답마다 어디서 왔는지 남는다. 지금 두 길 다 남긴다.

    그래프 선택   어느 그래프의 어느 노드, 어느 별칭
    관계 추론     원문 몇 번째 글자에서 왔는지, 어느 규칙을 썼는지
                  예: 23 <- "돌은 23개 있다"(0~9자)
                      15 <- "돌 8개를 꺼냈다"(11~20자) delta -8

**② 팩 안에서 완결돼야 한다.** 팩을 받으면 지식·규칙·언어가 다 온다. 코드에
지식이 남아 있으면 안 된다 — 엔진은 갈아 끼울 수 있어야 하니까.

## 호환성보다 성능

팩 형식을 올릴 일이 생기면 **올린다.** 옛 팩에 새 칸이 없으면 그 기능만 빠진
채로 돈다(구식으로 돈다). 호환성 때문에 성능을 묶어 두지 않는다.

## 파서의 경계 (실측)

자리(슬롯)로 뽑는 것은 **일반화된다.** 목록에 없어도 된다.

    ✅ 물건 이름   사과 · 동전 · 블록 (examples 에는 구슬 · 단추 · 연필 · 지우개뿐)
    ✅ 사람 이름   철수 · 가은 · 가나
    ✅ 수식어      "빨간 사과"
    ✅ 한글 수사   "스물세 개"

막히는 것은 **한국어 활용과 문장 잇기**다. 전부 언어팩 층 문제다.

    ❌ "크고"      어미가 붙어 잘린다. clause_pattern 이 "고 "(공백) 만 찾는다
    ❌ "먹었다"    examples 에 "꺼냈다" 만 있다
    ❌ 어순·말투   "23개 있었는데 8개를 꺼냈어"

원인이 확인됐다. `clause_pattern` 은 `"(?:(?!고\s)[^.!?,\n])+"` 한 줄이라
`"크고"` 를 `"크"` + `"고 …"` 로 자른다. 그래서 `examples` 에
`"하루는 모래보다 키가 크"` 라는 **끝이 잘린 항목**이 등록돼 있다 — 파서가 잘못
자른 조각을 자료로 덮은 것이고, 새 어미가 올 때마다 줄이 는다.

그리고 문장 쪼개는 자리가 **세 군데**고 셋 다 손으로 적은 목록이다.

    encoder._conj_ending   "하여|해서|하고|지만|는데|면서|어서|아서|니까|므로|려고|두고"
    relations.json         "(?:(?!고\s)[^.!?,\n])+"
    hangul.용언끝           ('지','기','여','며','면','고','서','게','히','이','어','아','나')

`hangul.용언끝` 에 `고` 가 이미 있는데 파서가 안 쓴다. 조사 짝표가 네 벌이었을
때와 같은 모양이다 — 그때 한 벌만 ㄹ 예외를 알았다.

어미를 글자에서 계산해 자르면 넷 다 풀리는 것을 확인했다.

    옛  '철수는 영수보다 크'  + ' 영수는 민호보다 크다'
    새  '철수는 영수보다 크고' + '영수는 민호보다 크다'
    옛  '사과가 23개 있었는데 8개를 꺼냈어'        (못 쪼갬)
    새  '사과가 23개 있었는데' + '8개를 꺼냈어'

## 할 일 순서 (제안 — 아직 안 정함)

1. **문장 쪼개기를 `hangul.py` 한 곳으로.** 세 군데를 거기로 돌린다. 조사를
   모았을 때 숨은 버그가 드러났던 자리다.
2. **어미를 표가 아니라 규칙으로.** 조사에서 짝 4개 + 돋는 이/으 + ㄹ 예외로
   갈아 `이랑` 이 저절로 됐던 것과 같은 자리. 모음조화(-아서/-어서)와
   받침(-으니까/-니까)은 자모에서 계산된다.
3. **팩 v3 으로 옮기기.** 세 층으로 갈라 넣는다. 공리팩 칸을 만든다.
   1·2를 먼저 하는 이유는, 지금 옮기면 파서의 결함까지 팩 안으로 들고
   들어가기 때문이다.

각 단계마다 얼린 잣대(`data/benchmarks/고정물음.json`)와 pytest 를 돌리고,
**밖 거절**을 먼저 본다. 그게 카나리아다.

## 아직 정하지 않은 것

- 공리팩을 manifest 의 새 키로 둘지, `axioms/` 폴더로 둘지.
- 새 길(관계 추론)이 못 푸는 것을 **웹으로 넘기는 지금 방식**을 유지할지.
  실측: v2 진단 14문항 중 실패 7개가 **전부 웹 조사로 넘어갔다**. 옛 길은 모르면
  "모른다" 로 끝낸다(밖 거절 24/24). 두 길의 규율이 다르다.
- 두 길을 계속 나란히 둘지, 하나로 합칠지. 지금은 새 길이 먼저 보고
  못 받으면 옛 길로 넘어간다(`engine.answer`).
