# 기능별 포함 범위와 미확정 설계 결정

작성: 2026-09-21. 이 문서는 영어 언어팩 **내용 준비**의 경계선이다.
구현 지시가 아니며, 여기 적은 미확정 항목은 다음 메인 goal 이 정한다.

## 0. 이 작업이 한 것과 하지 않은 것

한 것

- 영어 규칙 자료 작성 (`01-english-grammar-rules.json`)
- 한영 뜻 대응 자료 작성 (`02-sense-links-ko-en.json`)
- 저장소에 실재하는 지식과의 연결 목록 작성 (`03-existing-knowledge-links.json`)
- 13개 시나리오별 평가 사례 고정 (`04-evaluation-cases.json`)
- 학습용 예문을 평가와 분리해 작성 (`05-training-examples.json`)
- 현재 실행 베이스라인 측정·고정 (`evidence/baseline-2026-09-21.json`)
- 누락·중복·잘못된 참조·의미 모순 점검기 (`check.py`)

하지 않은 것 — 그리고 하지 않았다고 보고해야 하는 것

- 엔진 코드를 고치지 않았다. 기존 코드·팩·학습 상태는 읽기만 했다.
- 실행 그래프 형식을 확정하지 않았다. 이 자료는 교환용 초안이다.
- 영어 전용 엔진이나 영어 전용 처리 경로를 만들지 않았다.
- 영어 팩을 런타임에 연결하지 않았다. **따라서 '영어팩 실행 성공'도 '다국어 추론 완성'도 아니다.**
- 지식 그래프를 영어로 복제하지 않았고, 없는 노드 ID 를 만들지 않았다.
- 언어 모델·번역 API·사전학습 임베딩 의존성을 더하지 않았다(어떤 코드도 추가하지 않았다).

이 자료의 저자는 개발용 AI다. MARCO 가 스스로 학습하거나 발견한 지식이 아니다.

## 1. 측정한 현재 상태

`evidence/baseline-2026-09-21.json` 에 원시 결과가 있다.
진입점은 `reasoning_context.ReasoningContext.turn(text, "graphs/graph_일상추론.kg")` 다.

| 입력 | 결과 |
| --- | --- |
| 한국어 수량 연쇄 3턴 | `observed → observed → answered` |
| 영어 동등 3턴 | `null → null → null` (세 턴 모두 해석 결과 없음) |
| 한국어 전달 5턴 | `observed ×3 → answered ×2` |
| 영어 동등 4턴 | `null ×4` |
| 한국어 정의 질의 `음운이 뭐야` | `unresolved` |
| 영어 정의 질의 `What is a phoneme?` | `null` |

`knowledge_path` 없이 `turn()` 을 부르면 한국어도 `null` 이다.
이는 언어 문제가 아니라 진입 규약이다 — 영어 실패의 증거로 쓰면 안 된다.

영어 실패는 해석 경로 미완성의 증거이지, 추론 연산이 영어에서 틀렸다는 증거가 아니다.

## 2. 저장소 자산의 실제 상태

| 항목 | 값 | 출처 |
| --- | --- | --- |
| `graphs/*.kg` 개수 | 904 | `check.py --tally` |
| `언어: 영어` 로 태그된 팩 | 1 (`graph_en_bill_split.kg`) | 헤더 필드 |
| `[개념]` 노드 총수 | 3685 | 같은 집계 |
| 출처 태그(`@…`)가 붙은 노드 | 752 | 같은 집계 |
| 이 초안이 연결한 노드 | 22 (0.6%) | `03` |
| 이 초안이 연결한 팩 | 8 / 904 | `03` |
| `data/위키/정의문.jsonl` | **없음** | `engine.py:3415` 가 참조하지만 파일 부재 |

한국어 팩 `styles/한국어.json` 은 77,679바이트에 48개 최상위 키.
영어 팩 `styles/english.json` 은 6,242바이트. 영어 쪽에 **아예 없는** 칸:

`인코더` · `관계해석`(수사·정정·응답문) · `활용` · `문장분리` · `수량연쇄` · `자리말` ·
`지시어` · `부정` · `계획` · `수량표현` · `행위대상결합` · `상태표현` · `말수식` ·
`범위답` · `정정대상답` · `관계선택답` · `자리물음` · `짧은답꼬리` · `출력계약` ·
`응답구성` · `의도표` · `뜻표지` · `외부조사` · `군말` · `문서분류` · `학습질문종결`

영어 쪽에 이미 있는 것은 `관계말`(25종 관계 표현), `질문틀`, `내용어`, `주어없음`,
`대화질문`, `자세히`, `conversation.shell_risks`/`context_refs` 뿐이다.
즉 **출력 표현의 일부만 있고 입력 해석에 필요한 것은 전부 없다.**

`styles/english.json` 의 `조사짝: {}` · `붙일조사: []` · `이음규칙: "없음"` 은
"영어에는 필요 없다"는 주석과 함께 비어 있다. 이는 절반만 맞다 —
조사가 없는 것은 사실이지만, 그 자리가 **비는 것이 아니라 어순과 전치사로 대체**된다.
영어 팩에는 그 대체 기제를 적을 칸 자체가 없다. `01` 의 `typology`·`adpositions` 가 그 칸이다.

또 `styles/한국어.json` 의 `문서분류` 에는 영어 패턴(`causes?`, `leads? to`, `first`,
`then`, `this|that|these|those`)이 섞여 있다. 파일 자신이 `_주의` 에
"팩 하나가 두 언어를 겸하던 흔적이고, 영어 팩이 서면 그쪽으로 갈라야 한다"고 적어 두었다.
**갈라야 할 자리가 자산에 기록돼 있다** — `07` 의 대응표 M13 항목.

## 3. 기능별 포함 범위

13개 시나리오 기준. `04-evaluation-cases.json` 의 사례 ID 와 짝을 이룬다.

| # | 시나리오 | 이 초안의 포함 범위 | 명시적 제외 |
| --- | --- | --- | --- |
| 1 | 수량 상태 | 존재문·소유문·꺼냄/넣음, 정수 수량, 부정/계획 대조, phrasal verb 분리 어순 | 분수·소수 수량, 대략수(about 20), 집합명사 |
| 2 | 전달 역할 | 이중목적어·전치사구·수동태 세 어순, 역할 반전 대조 | 3자 연쇄 전달, 되받기 |
| 3 | 위치 이동 | from/out of + into/onto/in, 현재/이전 위치 질문 | 경로(through/via), 방향만 있는 이동 |
| 4 | 관계 결합 | 비교급 + than (`taller`만), isa/subclass | `smaller`·`older` (공리 부재 — D3) |
| 5 | 부정·조건·불확실성 | do-support·be-not·quantifier·never, if 절 양방향 어순, 미확인 표지 | 이중 부정, 반사실 가정(if I had) |
| 6 | 생략·지시어 | it/they/that/there/then, 후보 다수일 때 되물음·재개 | 먼 거리 조응, 부분 조응(one of them) |
| 7 | 행위 학습 | to-부정사/동명사 정의, 자리말 결합, 양방향 적용 | 조건부 정의, 여러 단계 절차 정의 |
| 8 | 경험 개념 | instance_of/classified_by 경로의 영어 입력 | 새 개념 형성 알고리즘 자체 |
| 9 | 별도 전제와 이유 | why/how do you know, 전제 변경·제거 | 다단계 why 연쇄 |
| 10 | 교차 언어 교정 | `Correction: A => B`, 대상 모호 시 되물음 | 암시적 교정("no, 3") |
| 11 | 어휘·표현 학습 | means / is another word for / we call X Y | 문법 규칙 자체의 학습 |
| 12 | 출력·대화 전환 | 영어 답 틀, number-only 계약, 표현 부족 명시, 한글 누출 검사 | 격식 수준 전환(높임 대응 축 없음 — D4) |
| 13 | 기존 KG 검색 | 고정 표본 7개, 동음이의 대조, 연결 제거·복원 | 903개 미연결 팩, 정의문 JSONL 경로(부재 — D7) |

제외한 것은 "지원하지 않는다"는 선언이 아니라 **이 준비 작업의 범위 밖**이라는 뜻이다.
실패한 조건을 미지원으로 옮긴 것이 아니다.

## 4. 미확정 설계 결정

다음 goal 이 정해야 한다. 임의로 고르지 않았다.

**D1. 역할 키를 무엇으로 할 것인가.**
현재 사건 역할은 한국어 조사를 키로 쓴다 — `marco/reasoning/context.py:1455` 가
`roles.get("은")`, `roles.get("에게")` 로 직접 읽고, `:1969` 는 `event["자리"]["은"]` 을
행위자로 쓴다. 한편 `action_runtime` 의 프로그램에는 이미
`signature.open_roles = {"giver": "은", "taker": "에게"}` 라는 **역할 이름 층이 있다**
(`tests/test_action_runtime.py:26` 확인).
선택지: (가) `open_roles` 층을 저장 키까지 끌어올려 `giver`/`taker` 를 키로 쓰고 조사는
언어팩의 표면 대응으로 내린다. (나) 현재 키를 유지하고 영어 쪽에 가짜 조사 키를 만든다.
(나)는 "키를 영어로 바꾸는 것" 과 같은 함정이라 권하지 않지만, 구형 저장 데이터의
이관 비용은 (가)가 크다. 결정 필요.

**D2. 표면형 없는 단위를 어떻게 적을 것인가.**
한국어 `개` 에 대응하는 영어 표면형은 **없다**(복수형이 그 자리를 맡는다).
`null` 이 "모른다"인지 "표면에 실현되지 않는다"인지 자료 형식이 구별해야 한다.
`02` 에서는 `l/unit-count` 의 주석으로만 구별했다. 형식 차원의 표현이 필요하다.

**D3. `smaller` 의 공리.**
E절 표의 관계 결합 예문은 "A가 B보다 작다"인데 `axioms/core.json` 에는
`strict-height-transitivity`(taller)만 있다. 선택지: (가) `smaller` 를 `taller` 의 역으로
선언하는 메타 규칙 (나) `smaller` 추이 규칙 추가 (다) 평가를 taller 로 유지.
이 초안은 (다)를 **임시로** 택하고 `04` 에 그렇게 적었다. 공리를 지어내지 않았다.

**D4. 높임·격식 축의 비대칭.**
한국어 `짧은답꼬리`(야/이에요/입니다)와 `활용`의 `polite`/`request_honorific_ask` 는
문법화된 높임 축이다. 영어에는 그 축이 없다. 1:1 로 옮기면 없는 구분을 만들거나
있는 구분을 잃는다. 선택지: (가) 언어팩마다 축 목록 자체를 선언하게 한다
(나) 공통 의미 계약에 formality 를 넣고 언어별로 실현 여부를 표시한다.

**D5. 인명 로마자 표기의 표준형.**
`민수` → Minsu / Minsoo / Min-su. 하나를 표준 표기로 고정하고 나머지를 별칭으로 둬야
한다. 표기 규칙을 엔진에 넣으면 언어 지식이 코드로 새는 것이고, 팩에 넣으면
표기가 팩마다 갈린다. 결정 필요.

**D6. 관계 이름의 공통 ID.**
팩 머리표의 `전진관계`·`부정관계`·`근거관계` 값이 언어별로 다르다
(`확인함`/`confirms`, `이어짐`/`leads_to`, `어긋남`/`blocks`).
지금은 두 팩이 같은 종류의 논증을 쓰는지 알 방법이 없다.
공통 관계 ID 를 도입할지, 팩 머리표에 대응을 적을지 결정 필요.

**D7. 정의문 자산의 부재.**
`engine.py:3415` 와 `views/kgpack_ui.py:253` 가 `data/위키/정의문.jsonl` 을 읽지만
이 작업 트리에 없다. H11 의 "정의 자료의 고정 표본"을 이 상태에서는 고정할 수 없어
`.kg` 노드로만 표본을 잡았다. 자산이 있는 환경에서 표본을 다시 고정할지,
`.kg` 표본만으로 H11 을 판정할지 결정 필요.

**D8. 부정 범위의 모호성 처리.**
"He didn't take out 8 stones" 는 두 읽기가 있다. 이 초안은 두 후보를 내고 보류하게
적었지만, 보류가 정답인 경우와 "둘 다 같은 답을 내므로 답해도 되는" 경우
(`04` 의 `ev/negation-condition-uncertainty` 반례 4번)가 섞인다.
"답할 수 있는데 보류" 로 집계될지가 평가 신뢰성에 직결된다.

**D9. 영어 팩의 `인코더` 설정.**
한국어 팩은 `mode: "문자"`, `jamo_weight: 0.5`, `route_threshold: 0.43` 등을 선언한다.
자모 가중치는 한글 전용 개념이다. 영어의 라우팅 인코더를 무엇으로 할지,
임계값을 어떻게 고를지는 실측 없이 정할 수 없다. 이 초안은 값을 적지 않았다.

## 5. 이 자료를 쓸 때의 주의

- `01`~`05` 는 **초안 형식**이다. `styles/` 나 `graphs/` 로 그대로 복사하면 안 된다.
- `04` 의 기대값을 런타임 팩이나 학습 입력으로 넘기면 평가가 무효다.
- `03` 의 `status: held` 항목을 추론에 쓰면 안 된다.
- 점검은 `python docs/ko/english-pack-preparation/check.py` 로 한다.
