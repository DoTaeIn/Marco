# 문장 쌍으로 표현 교정하기

이제 관계 이름과 슬롯 위치를 직접 주석하지 않고, 새 문장과 이미 이해되는
동일 의미 문장을 짝지어 학습 후보를 만들 수 있다.

```json
{
  "text": "모래에 비하면 하루의 키가 더 크다",
  "equivalent": "하루는 모래보다 키가 크다",
  "validation": [
    {"text": "미소에 비하면 유나의 키가 더 크다", "equivalent": "유나는 미소보다 키가 크다"},
    {"text": "유나에 비하면 미소의 키가 더 크다", "equivalent": "미소는 유나보다 키가 크다"},
    {"text": "미소에 비하면 유나의 키가 더 크지 않다", "unrecognized": true}
  ]
}
```

```sh
python semantic_feedback.py paraphrase pairs.json --output /private/tmp/relations.json
```

기존 파서가 `equivalent`를 정확히 한 관찰로 해석해야 한다. 그 관찰의 주체와
대상이 새 문장에 각각 한 번 나타나야 한다. 대상의 역할은 새 문장의 어순이
아니라 기준 문장의 관계에서 가져온다. 숫자 슬롯과 부정 메타데이터도 유지한다.
모르는 대명사나 반복된 이름을 임의로 정렬하지 않는다.

후보를 만든 뒤 별도 문장 쌍과 미인식 반례로 기존 전이 검증을 수행한다.
검증이 실패하면 모델을 바꾸거나 저장하지 않는다. 검증에 쓰인 개체와 문장은
학습 모델에 넣지 않는다. CLI 출력은 추론한 주석과 검증 결과·모델 해시를 보여 준다.

검증은 어순이 바뀐 비교, 저장 후 새로운 세 개체의 추론 사슬, 부정 의미 보존,
잘못된 검증 거부, 수량 표현에서 한글 수사와 후속 증감의 결합, 실제 CLI 재로딩을
포함한다. 시드 모델은 직접 저장 대상으로 사용하지 않는다.

이 기능은 사용자가 선언한 의미 동등성을 이용하는 감독 학습이다. 서로 다른
두 문장이 실제로 같은 뜻인지 스스로 증명하는 것은 아니며, 기존 파서의 오해석을
기준으로 주면 잘못된 후보가 생길 수 있다. 별도 검증도 유한한 사례 검사다.
현재는 CLI 입력이며 자유로운 채팅에서 정정 의도를 자동 발견하는 기능은 남아 있다.
학습한 문장 틀의 조사까지 자동 변형하지는 않는다. '단추는'을 교정한 뒤 '구슬은'으로
검증하면 거부된다. 같은 조사 틀의 새 개체로의 전이와 조사 변화 일반화는 구분해야 한다.
