# 다음 goal: 언어·문법의 그래프화와 언어 교체 시 추론·학습·기억 보존

## 그대로 설정할 목표

MARCO의 기존 Binary KG, 사건 실행, 근거 추적, 경험 개념, 학습·저장·복원과 ALMA 연결을 보존하면서, 현재 지원하는 언어별 어휘·문법·활용·문맥 표현·답변 표현을 실행 가능한 그래프 데이터로 이관한다. 공통 엔진은 특정 언어·단어·조사·동사·문장·개념 ID에 의존하지 않고 그래프가 선언한 규칙을 실행하게 한다. 한국어와 영어를 공통 의미·사건·역할·개념에 연결하여, 같은 지식·공리·의미 입력에서 언어팩만 교체해도 결론·상태 변화·필수 근거가 유지되고, 한 언어로 배운 사실·행동·개념을 다른 언어로 질문·적용·설명·교정할 수 있도록 구현하고 검증한다.

완료는 그래프 파일 생성, JSON의 확장자 변경, 영어 예문 몇 개의 통과, 시험 수 증가가 아니다. 아래 A~H와 완료 표의 조건을 모두 충족해야 한다. 한국어 이관만 하고 영어·교차 언어·기억 이관을 다음 goal로 넘기지 않는다. 이 문서는 구현과 검증을 지시하는 goal이며, 실행 시 다시 계획 문서만 작성하고 종료하지 않는다.

## 사용자 요구와 범위

- 언어 모델 금지, 글자·형태소 분석 허용. 생성형 언어 모델, 사전학습 텍스트 임베딩/문장 인코더, 번역 모델, 언어를 생성하는 VLM이나 외부 언어 API로 이해·추론·답변을 대신하지 않는다. 개발 도구가 사용하는 모델과 MARCO 제품 런타임을 구별한다.
- 언어마다 Python 처리기를 추가하는 방식으로 해결하지 않는다. 언어 지식은 그래프 자산에 두고, 공통 연산·규칙 실행·검증 코드는 기존 엔진에서 재사용한다.
- 기존 엔진 전체를 다시 만들지 않는다. 기존 Binary KG와 Event/Experience Graph를 유지하라는 2026-09-20-addition-next-directions.md의 요구를 따른다. 파일 개수 감소 자체도 목표가 아니다.
- 한국어의 기존 검증된 기능을 보존한다. 영어는 단순 인사·출력 번역이 아니라 아래 기능 표의 같은 의미·연산·역할·양태를 처리해야 한다.
- 모든 인간 언어와 모든 자연어 표현을 완성하는 goal은 아니다. 현재 구현된 기능 범위와 필수 한영 기능 표를 이행하고, 그 범위의 언어를 추가·변경할 때 엔진 수정이 필요하지 않은 구조를 완성한다. 이 제한으로 기존 지원 기능이나 아래 필수 조건을 제외하지 않는다.
- 새로운 감정 체계, 자율 목표 체계, 외부 행동, 새로운 범용 추론 엔진을 추가하지 않는다. 기존 ALMA가 이 경계를 사용하며 퇴행하지 않는 것은 검증한다.

## 현재 상태와 시작 절차

현재 열린 MARCO 저장소에서 수행한다. 작성 당시 작업공간은 `C:\Users\hirob\Desktop\Marco`다. 저장소 위치는 실제 실행 환경을 따른다. 사용자와 다른 작업의 미커밋 변경을 보존하며, 과거 HEAD로 되돌려 시작하지 않는다.

작성 전 확인한 내용은 다음과 같으며, 실행 시작 시 최신 코드에서 재확인한다.

- `PackModel`은 언어 자산과 공리 자산을 분리하지만 언어는 `styles/*.json`에서 읽는다. 실행 가능한 문법 그래프가 유일한 언어 원본인 상태는 아니다.
- 한국어 수량 대화 `돌은 23개 있다 → 돌 8개를 꺼냈다 → 지금 돌은 몇 개야?`는 15개와 변화 근거를 반환했다. 기존 영어 팩의 동등한 세 문장은 `ReasoningContext.turn`에서 모두 해석 결과가 없었다. 이는 영어 해석 경로 미완성의 증거이며, 추론 연산 자체가 영어에서 틀렸다는 증거로 바꾸어 보고하지 않는다.
- `reasoning_context.py`의 개념 질의·참조 기억에 특정 역할 키 직접 접근과 한국어 답말끝 고정이 확인됐다. 한국어 식별자나 주석 자체를 결함으로 세지 말고 실제 팩 의존성 우회 여부를 추적한다.
- `graph_inference`, `action_runtime`, `experience_concepts`, `PackModel`, 사건·proof·저장 구조는 재사용할 기반이다. 이름을 바꾸거나 전부 재구현하는 것으로 이관을 대신하지 않는다.
- 다른 작업이 코드를 변경 중일 수 있다. `docs/ko/2026-09-20-next-goal-evidence.md` 등 과거 보고는 참고 자료이며 최신 독립 검증을 대신하지 않는다.

먼저 최신 diff와 관련 진입점을 읽고, 실제로 동작하는 한국어 기능·공개 진입 경로·학습/저장 형식·언어 의존성의 목록을 만든다. 목록에는 위치, 역할, 이관할 그래프 요소, 남길 공통 연산, 대응 시험을 적는다. 조사 후 바로 구현한다. 저장된 학습 상태와 구형 팩의 비교 표본은 수정 전에 복사해 고정하고 원본은 유지한다.

## A. 실행 가능한 언어·문법 그래프와 자산 계약

1. 기존 그래프 자산과 `.kgpack`을 확장하여 언어팩을 그래프 파일로 배포·선택·교체할 수 있게 한다. 필요한 타입·속성·순서·조건은 명시적인 스키마로 표현한다. 기존 Binary KG에 없는 표현 때문에 별도 DB나 엔진 전체를 도입하지 않는다.
2. 어휘/표면형, 뜻, 형태·활용 규칙, 어순/문장 구조, 문장 경계, 수사/단위, 역할 대응, 부정·시제·양태·조건·범위, 지시어/생략 단서, 출력 구성을 노드·관계·규칙으로 담는다. 모든 언어가 같은 문법 범주를 갖는다고 가정하지 않는다.
3. 예를 들어 문법 규칙은 입력 구성 요소의 순서·선택 조건·변수 결합·생성할 의미 구조를 가리켜야 한다. 규칙을 관계로 연결하지 않고 거대한 JSON 문자열이나 Python 코드를 한 노드에 넣는 것은 그래프화로 인정하지 않는다. 사람이 읽는 문법 설명문만 저장하는 것도 불충분하다.
4. 실행 중 실제 사용하는 언어 지식의 원본은 그래프 하나의 계통으로 정한다. 기존 `styles`의 문법, 코드 상수, 그래프에 서로 다른 원본을 중복 유지하지 않는다. manifest·표시 이름 같은 관리 메타데이터는 JSON이어도 된다. 컴파일된 JSON/정규식/색인은 그래프에서 재생성 가능한 파생물이어야 한다.
5. 입력 이해와 출력 표현이 같은 뜻·역할·문법 선언을 공유하도록 한다. 방향별 규칙은 명시할 수 있지만 입력용 문법과 출력용 문법이 모순된 독립 체계가 되지 않게 검증한다.
6. 언어 그래프, 공통 의미 계약, 지식·공리, 학습 overlay의 식별자·버전·의존성을 분리한다. 언어팩이 언어 교체를 명목으로 산술 효과나 영역 공리를 몰래 변경해서는 안 된다.
7. 그래프 참조 누락, 중복·충돌 ID, 잘못된 규칙 타입, 지원하지 않는 필수 연산, 호환되지 않는 의미 계약을 사용 전에 검증한다. 실패하면 원인과 자산을 보고하며 기본 한국어로 조용히 돌아가지 않는다.
8. 그래프 해시·규칙 버전·엔진 계약으로 컴파일 캐시를 식별한다. 그래프를 고친 뒤 예전 캐시가 계속 실행되거나 다른 팩의 캐시가 섞이지 않아야 한다. 컴파일 여부가 결과의 의미를 바꾸지 않아야 한다.
9. 대화에서 새로 배운 표현·별칭·문법 대응도 같은 그래프 계약의 overlay로 저장하고 다음 해석에 사용한다. 기본 문법만 그래프로 옮기고 학습 결과는 별도 JSON 문법 체계로 남기지 않는다. 현재 지원하는 표현 학습을 이관하는 것이며 새 범용 문법 발견 알고리즘 전체를 선행 조건으로 만들지 않는다.
10. 해석 결과에는 원문 범위, 언어 그래프/규칙 버전, 적용된 역할·뜻 연결을 남기고 추론 proof와 연결한다. 설명할 때는 입력 해석의 근거와 결론을 도출한 지식·공리의 근거를 구별한다. 규칙 ID가 존재하기만 하는 것이 아니라 실제 사용한 규칙인지 검증한다.

## B. 공통 실행기와 언어 의존성 제거

1. 기존 연산을 재사용하여 그래프에 선언된 패턴 대응, 구성 요소의 결합, 조건 확인, 역할 연결, 의미 생성, 표현 생성을 실행한다. 한국어·영어의 별도 추론기나 복사한 대화 실행기를 만들지 않는다.
2. 언어별 글자 목록·조사·어미·활용 예외·어순·수사 표현·부정어·지시어·답말끝은 그래프로 옮긴다. Unicode 읽기, 문자 분해/결합, 문자열 비교, 산술, 자료구조, 변수 결합, 규칙 순회, 자원 상한 등 범용 실행 기능은 코드에 둘 수 있다. 이 구분을 문서와 코드 경계에 명시한다.
3. `hangul.py` 등 현재 언어 처리에서 재사용 가능한 문자 연산과 한국어 문법 지식을 구별한다. 한국어 문법을 호출하는 기존 함수를 그대로 감춘 뒤 팩의 `module:Class`로 선택하는 것은 이 goal의 완료가 아니다. 허용된 글자·형태소 분석 도구도 최종 의미·정답을 대신 결정하지 않아야 한다.
4. 사건의 역할은 표면 조사와 분리된 의미 역할로 연결한다. `은`, `에게` 같은 특정 표면형을 추론·학습·참조 해소의 필수 키로 가정하지 않는다. 구형 저장 데이터의 키는 명시적 이관 대응으로 처리한다. 단순히 키를 영어로 바꾸는 것을 해결로 세지 않는다.
5. 대화, 수량·위치, 행동 정의/적용, 개념 질의, 관계 판단·설명, 지시어·보완·교정, 계획·가정, 학습·복원에서 같은 경계를 사용한다. 기존 공개 CLI/UI/API 및 ALMA의 자연어 진입 경로를 실제로 연결한다. 새 데모 API만 그래프를 쓰게 해서는 안 된다.
6. 문장별 완성 답안, 이름/숫자/물건/동사/개념 ID 전용 분기, `if language == ...` 방식의 언어별 의미 실행 분기, 테스트 문항 식별자를 추가하지 않는다. 정규식을 써야 한다면 언어 그래프 선언으로부터 생성하고 근거를 추적한다.
7. 문장·문법·지식이 부족한 경우를 구별한다. 불완전한 해석으로 상태를 바꾸거나, 이해 실패를 외부 검색·모델 호출로 우회하거나, 기존 한국어 표현을 다른 언어의 답에 조용히 끼워 넣지 않는다.
8. 정적 검색만으로 무하드코딩을 선언하지 않는다. 문자열의 용도를 검토하고 아래 그래프 변경·제거 시험으로 실제 실행 의존성을 입증한다. 범용 연산 코드까지 없애는 것을 목표로 삼지 않는다.

## C. 공통 의미와 언어 사이 연결

1. 표면 문자열과 개념·개체·사건의 identity를 분리한다. 표시 언어가 달라져도 같은 개념과 같은 저장 사건을 같은 ID로 참조한다. ID가 한국어인지 영어인지보다 표면형 변경에 따라 identity가 달라지는지 검증한다.
2. 연결은 `표현 → 문맥에 맞는 뜻 → 공통 개념/사건 구조`로 만든다. 뜻이 같은 범위에서 공통 의미를 공유하되 언어별 구분까지 억지로 합치지 않는다. 부분 대응, 상하위 의미, 번역 대응과 동일 개념을 구별한다.
3. 최소한 다의어, 동의 표현, 여러 단어로 된 표현, 인명/개체 별칭을 검증한다. `사과`의 과일 의미와 사죄 의미가 같은 노드로 합쳐지지 않아야 한다. `책`/`book`이나 한영 인명 표기는 근거 있는 연결로 같은 대상에 접근해야 한다.
4. 문장 간에는 사건 역할, 수량·단위, 부정, 실제/계획/조건/가정, 시점·범위, 질문 대상을 보존한다. 문자열 번역 또는 단어별 치환을 의미 동등성으로 보지 않는다.
5. 기존 경험 개념을 언어가 다르다는 이유로 중복 생성하지 않도록 구조 비교를 검증한다. 실제로 다른 경험은 별도 사건으로 유지한다. 같은 내용의 문장을 다시 입력했다고 언제나 중복 사건으로 제거해서도 안 된다. 언어 전환 자체는 새 관찰이나 새 실행이 아니다.
6. 언어 연결·초기 문법·공리로 사람이 제공한 지식과 경험/대화에서 학습한 지식을 구별한다. 제공한 한영 대응표를 스스로 발견한 번역 능력으로 보고하지 않는다.
7. 대응 표현을 모르면 공통 지식과 근거를 보존한 채 표현 부족을 명시한다. 공통 개념에 연결됐다는 이유만으로 모든 언어의 이름과 표현을 자동으로 아는 것으로 처리하지 않는다. 필수 평가 범위의 표현 부족은 성공이 아니다.
8. 문법 해석과 기존 지식 검색의 언어 연결은 별도로 구현·검증한다. 현재 Binary KG의 별칭/문자 유사도 기반 그래프 선택·노드 선택, 표제어 기반 정의 검색까지 공통 뜻/개념 참조를 전달한다. 새 사건 데모에서만 한영 연결을 하고 기존 지식 그래프는 한국어 문자열로만 찾게 남겨서는 안 된다. 실제 활성 경로를 조사하여 적용하고 문자열 유사도를 언어 간 동일 의미의 증거로 사용하지 않는다.
9. 언어별 표현과 분야별 지식 노드를 연결하는 대응 그래프를 팩 자산으로 둔다. 공통 개념·관계 ID와 각 팩 내부 ID 사이의 대응, 출처·버전·모호성·의존성을 명시한다. 서로 다른 팩에서 이름이 같다고 같은 개념으로 합치지 않는다. 개체 이름뿐 아니라 질문에 쓰인 술어·관계·단위도 연결한다. 언어팩 교체 때문에 지식 그래프 전체를 번역·복제하거나 모든 기존 노드 ID를 바꿔야 하는 구조를 만들지 않는다.
10. 이미 구조화된 사실/관계와 한국어 원문으로만 저장된 정의·설명문을 구별한다. 원문은 출처로 보존하고 지원 문법으로 검증해 얻은 구조만 추론에 사용한다. 단어 뜻 연결만으로 원문의 모든 문장을 이해·번역했다고 주장하지 않는다. 모든 기존 지식과 출처는 보존하되 한영 연결이 된 범위, 연결되지 않은 범위, 의미 구조가 없는 자료를 따로 집계한다. 필수 평가에 사용할 기존 지식과 연결 범위는 구현 전에 고정하고 실패 후 줄이지 않는다.

## D. 기존 지식·학습·기억 이관과 실제 팩 교체

1. 기존 한국어 팩과 검증된 학습 자료를 새 그래프로 옮기는 재현 가능한 이관 경로를 제공한다. 원본은 유지하고 새 자산은 검증 후 사용한다. 기존 사실·행동 정의·개념·활성 상태·교정 이력·독립 근거가 사라지지 않아야 한다.
2. 변경 전과 후의 ID/버전 대응을 남긴다. 원문, 당시 언어, 당시 규칙·정의 버전, 파생 결론의 근거를 보존한다. 예전 기록을 현재 언어 문법으로 다시 읽어 사실처럼 확정하지 않는다.
3. 같은 지식·공리·기억을 유지하면서 입력/출력 언어 선택을 명시적으로 변경할 수 있게 한다. 한국어→영어, 영어→한국어, 다시 원 언어로의 왕복을 실제 공개 경로에서 검증한다. 언어 변경으로 대화/ALMA identity를 바꾸거나 저장소를 초기화하지 않는다.
4. 팩 전체 해시가 달라졌다는 이유로 동일한 의미 기억을 버리지 않도록 언어 버전과 의미/지식 호환성을 구별한다. 반대로 의미 계약이 다른 팩을 무조건 호환된다고 받아들이지 않는다.
5. 문법·어휘 해석 규칙이 바뀌었을 때 과거 확정 사건은 당시 해석·근거를 유지하고, 새 입력은 새 규칙을 사용한다. 의미를 바꾸는 재해석·교정이 필요하면 명시적 수정 이력과 영향받은 결론 철회를 남긴다. 설명이 폐기된 근거를 현재 이유로 제시해서는 안 된다.
6. 원본 상태, 언어 교체 후 상태, 개념 비활성 상태, 교정 후 상태를 각각 저장하고 실제 별도 프로세스로 복원한다. 객체만 새로 만든 것을 새 프로세스 복원이라고 보고하지 않는다.
7. 팩과 명시적인 사용자 상태/overlay, 엔진만 가진 별도 작업 디렉터리에서 재현한다. 원래 저장소의 느슨한 언어 파일, 개발 환경변수, 이전 캐시가 없어도 작동해야 한다. 사용자 기억 없이 팩만 옮긴 경우와 overlay까지 옮긴 경우를 구별한다.
8. 같은 프로세스의 한국어·영어 대화 두 개가 문법·출력 언어·캐시·학습 overlay를 서로 오염시키지 않아야 한다. 명시적으로 공유한 지식만 공유한다.
9. 필요한 구형 호환 읽기는 이관 경계로 한정한다. 이관 완료 후 두 문법 원본이나 두 추론 경로를 영구적으로 유지하지 않는다. 손상·불일치·저장 실패 때 정상 상태를 덮어쓰지 않는다.

- 한국어 학습→영어 적용, 영어 학습→한국어 적용, 언어 전환 없이 수행한 대조. 학습되지 않은 영어 동사 뜻을 자동 추측할 것을 요구하지 말고 필요한 뜻 연결은 명시적으로 가르친 뒤 검사한다.

- 기존 ALMA 로컬 환경에서 기록된 사건을 다른 언어로 질문·설명하고 교체·재시작 후 유지하는 통합 경로. 이 시험을 위해 실제 외부 행동을 실행하지 않는다.

## F. 그래프가 실제 동작을 지배한다는 검증

1. 런타임 코드를 고정한 채 그래프만 바꿔 새 어휘와 적어도 하나의 새로운 문법 조합을 추가한다. 동사/문장 한 개의 별칭 추가만 하지 말고, 순서·구성·역할 연결이 달라지는 규칙이 새 문장 조합에서 작동함을 보인다.
2. 특정 사례의 유일한 문법/뜻 연결을 그래프에서 제거하면 해당 해석이 실패하거나 필요한 보류가 나와야 한다. 코드의 숨은 한국어/영어 처리나 정답 대응표로 계속 통과하면 실패다. 독립된 유효 규칙이 있는 사례는 제거 시험 대상으로 쓰지 않는다.
3. 뜻 연결·역할 대응·출력 규칙을 각각 바꿔 변경 영향이 해당 단계에 나타나는지 검사한다. 특히 행위자/상대 역할이 뒤바뀐 잘못된 그래프는 검증에서 거절되거나 평가에서 의미 오답으로 검출돼야 한다.
4. 그래프 규칙을 바꾼 뒤 이전 캐시가 남아도 새 의미가 적용되는지, 팩 A→B→A 선택에서 원래 결과로 복귀하는지 검사한다. 재시작에만 기대어 캐시 오류를 숨기지 않는다.
5. 엔진 코드를 바꾸지 않고 기존 두 언어와 다른 어순/역할 표시를 가진 작은 검증용 언어 그래프를 추가한다. 같은 사건·질의가 공통 경로에서 실행됨을 보인다. 이것을 제3의 자연언어 전체 지원이라고 보고하지 않는다.
6. 원래 언어 파일 접근과 금지된 언어 모델 호출을 격리 시험에서 실패하게 만들어도 선택된 그래프 팩만으로 필수 시나리오가 작동해야 한다. 다운로드나 외부 서비스를 끈 실제 실행 결과도 남긴다.
7. 오류 주입은 격리된 테스트/팩 사본에서 수행한다. 제품 코드에 오류 주입용 문장·동사 분기를 추가하지 않는다.

## G. 평가 신뢰성·회귀·비용

1. 기존 의미 검증 평가기를 보완해 재사용한다. 준비 입력, 사용자 질문, 내부 검사, 이관 검사, 오류 주입 검사를 구별한다. 준비/내부 검사 개수를 해결한 문제 수로 보고하지 않는다.
2. `solved`, `safe_hold`, `wrong`, `execution_error`, `unverifiable`와 답 가능한 문항의 미해결 보류를 구별한다. 질문별 정답 의미·수량·대상·역할·양태·필수/금지 근거를 검사한다. 응답 단계, 키 존재, ID 출력, 답 문자열 일부 일치를 성공으로 쓰지 않는다.
3. 전달에서 준 사람 감소를 없애는 기존 오류 주입 회귀를 유지한다. 정상 실행은 통과하고 오류 주입은 실제 상태 검증에 실패하여 비정상 종료해야 한다. 문법·역할 오류 주입도 같은 평가기가 잡아야 한다.
4. 후반 단계에서 예외가 나도 앞선 결과와 실패 단계·입력·원인을 보고서에 남기고 비정상 종료한다. 평가기 자체가 결과를 잃거나 예외를 보류로 바꾸지 않는다.
5. 개발/회귀/평가 자료를 구별하고 구현 전 필수 평가를 고정한다. 구현에 사용한 문항을 독립 평가라고 부르지 않는다. 기대 의미·정답·금지 근거를 런타임 팩이나 학습 입력에 전달하지 않는다.
6. 규칙 적용, 재귀/순환, 후보·proof·문장 길이·컴파일 비용에 상한을 유지한다. 상한 때문에 탐색을 중단하면 불완전 상태를 표시하고 완전한 판단처럼 확정하지 않는다. 빈 입력을 소비하는 순환 규칙과 과도한 후보 발생도 검사한다.
7. 이관/컴파일/첫 로딩 비용, 반복 질의 비용, 재현 전체 비용, 최대 메모리를 분리해 변경 전후 측정한다. 같은 장비·입력·반복 횟수·캐시 조건을 기록한다. 저장 비용과 전체 실행 시간을 특정 내부 연산 횟수로 대체하지 않는다.
8. 개발 중 관련 시험을 실행하고, 최종 코드·팩 상태에서 전체 시험, 팩 무결성, 필요한 통합 재현과 diff 검사를 수행한다. 이관 관련 실패·기존 지원 기능 퇴행·필수 조건 실패가 남으면 완료하지 않는다. 이미 있던 실패는 재현 증거와 원인을 구별하되 필수 조건을 기존 실패로 면제하지 않는다.
9. 코드·팩·학습/평가 자료·이관 표본·실행 환경의 식별값을 기록한다. 미커밋 변경이 있으면 HEAD만을 검증한 코드 식별값으로 쓰지 않는다. 실행 중 다른 작업의 변경이 들어오면 영향받은 검증을 최종 상태에서 다시 한다.

## H. 완료 판정과 최종 산출물

아래 표는 모두 충족해야 한다. `부분`, `미검증`, `다음 작업`을 완료로 세지 않는다.

최종 보고와 저장할 산출물:

1. 바뀐 구조, 재사용한 기존 코드, 제거한 언어 의존성, 아직 코드에 남긴 범용 연산과 그 이유.
2. 언어 그래프와 팩 작성/검증/이관/선택 방법. 코드 수정 없이 규칙 하나와 뜻 연결 하나를 추가하는 실제 예시.
3. 한국어·영어·교차 언어의 실제 입력 대화, 예상/실제 의미·상태·답·필수 근거 비교. 사용자의 핵심 시나리오는 요약 점수만 남기지 않는다.
4. 기존 팩·학습·기억의 이관 전후 비교와 별도 프로세스 복원 명령. 사용자의 원본 데이터는 보존한다.
5. H1~H11 각각에 대응하는 시험 경로, 재현 명령, 원시 결과 파일. 아직 만들지 않은 명령을 실행 완료처럼 적지 않는다.
6. 해결/정당한 보류/미해결 보류/오답/오류/검증 불가 집계와 내부 검사 수, 오류 주입 결과, 비용·상한.
7. 검증한 코드·그래프·팩·자료의 해시와 버전, 남은 제한. 일반 다국어 이해·무제한 문법 학습·MARCO 전체 완성으로 확대해 선언하지 않는다.

## 진행·종료 규칙

- A의 그래프 정의부터 B~D 구현, E~G 검증까지 이어서 수행한다. 설계 검토나 단일 언어 성공 후 다음 할 일만 적고 끝내지 않는다.
- 기존 구조에서 가능한 가장 작은 변경으로 시작하되, 이 목표의 필수 범위는 축소하지 않는다. 실패한 조건을 미지원 목록으로 옮겨 완료 처리하지 않는다.
- 다른 작업의 변경을 보존하고 최신 해결분을 재사용한다. 사용자 동의 없이 다른 작업을 중단하거나 저장 상태를 초기화하지 않는다. 되돌릴 수 있는 저장소 내부 구현·시험은 계속 진행한다.
- 새로운 핵심 의미 계약의 충돌이나 안전하게 이관할 수 없는 실제 데이터가 발견되면 구체적 사례와 선택지를 제시한다. 일반적인 구현 선택을 매번 사용자에게 넘기지 않는다. 해결되지 않은 조건은 미완료로 정확히 남긴다.
- 사용자가 요청하지 않은 커밋·푸시·배포·외부 메시지는 수행하지 않는다. 이 목표는 로컬 구현·검증·문서화다.
- 완료의 뜻은 **실행 가능한 언어 그래프와 공통 의미를 통해, 지원 범위에서 언어팩을 바꾸어도 기존 추론·학습·기억이 유지되는 것**이다.
