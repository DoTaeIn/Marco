## A. 데이터 손실과 실행·평가의 신뢰성부터 복구

1. **identity와 손상 상태 보호.** 없는 파일의 첫 실행과 기존 파일의 identity/schema/model 불일치·JSON 손상·읽기 오류를 구별한다. 다른 identity로 같은 경로를 열거나 복구할 수 없는 파일을 읽었을 때 빈 삶으로 조용히 시작하여 덮어쓰지 않는다. 기존 바이트를 보존하고 원인을 보고한다. 정상/임시 checkpoint 선택, 저장 중단, 명시적 복구, 다른 개체 격리를 시험한다.
2. **capability 실행 journal.** adapter 호출 전에 요청 identity·payload/계약 버전·실행 상태를 영속화하고 결과와 연결한다. 실행 전, 실행 중, 효과 발생 후 결과 저장 전, 결과 저장 후 cycle 진행 저장 전의 중단을 각각 다룬다. 완료 요청은 다시 실행하지 않는다. 효과 발생 여부를 확인할 수 없으면 `unknown_execution` 등 명시적 상태로 보류하고 자동 재실행하지 않는다. 외부 adapter가 보장하지 않는 exactly-once를 로컬 파일만으로 보장했다고 보고하지 않는다. 가능한 adapter에는 idempotency key를 전달한다.
3. **승인·재시도 상태 전이.** `approval_required`와 재시도 가능한 실패를 완료 영수증처럼 영구 반환하지 않는다. 같은 논리 요청이 승인 후 진행되고, adapter 복구 후 허용된 재시도가 되며, 이미 완료된 효과는 반복되지 않아야 한다. 동일 요청 ID의 다른 payload는 조용히 이전 결과를 반환하지 말고 충돌을 알린다. 요청 ID를 새로 만드는 우회로 이력을 끊지 않는다.
4. **평가기의 모든 단계 기록.** 기존 평가기와 ALMA 통합 평가기 모두 준비·학습·질문·설명·교정·저장·복원·보고 단계의 예외를 단계명과 함께 남긴다. 후반 오류에도 완료된 검사와 비용을 보존하고 비정상 종료한다. solved/safe_hold/wrong/execution_error/unverifiable를 구별한다. 기능 검사 통과 수와 독립 문제 해결 수는 별도로 보고한다.
5. **기존 반례를 회귀로 고정.** identity 덮어쓰기, 손상 파일 대체, 승인 후 재시도, 저장 중단 뒤 동일 요청 2회 실행, 후반 예외 이력 소실을 정상 동작 기대값의 회귀시험으로 전환한다. 오류 주입은 격리된 시험에서만 하고 제품 코드에 특수 입력 분기를 넣지 않는다. 기존 검토 원시 결과는 보존하고 새 결과는 별도 실행 디렉터리에 남긴다.

## B. Chunking의 의미와 실제 비용을 바로잡고 일반 추론에 연결

1. `a→b→c→d`와 `b→independent` 반례에서 `d`만 유지하고 다른 결론을 잃는 오류를 고친다. 독립 분기, 다른 질의, 여러 바인딩과 후속 규칙이 요구하는 사실·근거 의미를 보존한다. target 한 개의 존재 여부로 동등성을 판정하지 않는다.
2. 일반 추론에서 관찰한 실제 proof 경로로 후보를 생성한다. 사건/판단 ID와 중복 판정으로 독립 관찰을 센다. 후보 API를 같은 인자로 두 번 부르거나 같은 저장 사건을 반복 재생한 것을 두 경험으로 세지 않는다.
3. 필수 중간 전제·시점·양태·규칙 버전을 조건으로 보존한다. 원 규칙/근거가 바뀌거나 반례가 나타나면 해당 shortcut을 자동으로 재검증/비활성화하고 원 추론으로 돌아간다. unrelated shortcut과 독립 근거는 유지한다.
4. 활성 shortcut을 실제 `turn()`의 공통 추론 경로에서 사용한다. 별도 `run_proof_shortcut()` 데모만 통과시키거나 단순 답 캐시로 대체하지 않는다. 설명 요청에는 원래 증명 경로와 실제 전제·버전을 복원한다.
5. 후보 준비/검증 비용과 반복 사용 비용을 분리한다. 매번 원 closure와 압축 closure를 모두 실행하면서 후자의 비용만 성능으로 보고하지 않는다. 같은 입력·같은 의미 출력에서 shortcut OFF/ON의 전체 traversal/join 또는 판단 시간을 비교한다. 준비 비용, 반복 비용, 총비용, 메모리를 함께 남긴다. 효과가 없는 사례는 이득 없음으로 보고하고, 적어도 반복 사용 평가에서는 실제 감소가 확인돼야 완료다.

## C. 시간·기억·Mental·이력을 공통 판단 경로에 연결

1. 실제 사건 시각, 관찰 시각, 처리 순서를 구별한다. 뒤늦게 들어온 과거 사건과 시각/역할/조건 정정이 현재·과거 상태 투영에 올바르게 반영돼야 한다. timestamp metadata 저장만으로 시간 처리 완료를 주장하지 않는다. 시각이나 원인이 불명확하면 불명확함을 유지한다.
2. Quantity, Location, Social, Mental이 같은 Event/Condition/Hypothesis·proof 계약을 사용한다. Mental의 주체·믿음/기대/목표·내용·양태·시간·원천을 보존하면서 조건 판단, 가정 투영, 갱신, 질문과 이유 설명으로 연결한다. 타인의 믿음을 세계의 사실로 합치지 않는다. 별도 mental 목록의 저장/조회만으로 공통 추론을 대신하지 않는다.
3. 각 영역에서 실제/계획/조건/가정/부정/미해석, 역할 보완, 과거 정정, 독립 증명, 행동 조합과 복원을 검사한다. 자연어와 구조 직접 입력 결과를 구분한다. 최소 3개 영역에서 같은 배운 구조를 전이하고, 전체 공통 코어 검증에는 Mental까지 네 영역을 포함한다. 인명만 바꾼 사례는 다른 영역 전이가 아니다.
4. Episodic/Semantic/Procedural을 실제 질의와 행동 선택에서 사용한다. 지원하는 ‘과거 경험’, ‘일반적으로 아는 것’, ‘하는 방법’ 질의가 해당 기억과 근거를 찾아 답하게 한다. 저장 목록이나 문자열 검색만으로 기억 활용 완료를 선언하지 않는다.
5. 압축한 경험의 원천 ID·revision·필수 요약·해시를 보존하고 정정/철회가 관련 지식·결론에 전파되게 한다. 근거가 다시 유효해지는 경우도 재검증한다. 세 기억의 수명과 작업 기억 상한을 분리하고, 한 개체의 세션 연속성과 개체 간 격리를 유지한다.
6. 모든 판단/행동의 SYSTEM/COGNITION/LIFE 기록을 event/decision ID로 연결한다. 당시의 이유와 현재 지식으로 재판단한 결과를 구별한다. 새 버전으로 과거 근거를 덮어쓰지 않는다.
7. milestone은 키 존재뿐 아니라 실제 event/decision/goal/candidate와 선언된 의미 조건을 검증한다. 존재하지 않는 decision이나 무관한 문장으로 milestone을 만들 수 없어야 한다. 자동 탐지, 외부 관찰 입력, 시험 fixture를 구분한다. `prompted=False` 인자만으로 자발적 목표가 관찰됐다고 세지 않는다. 최초 발생 검색과 한 번의 snapshot이 재시작 후 유지돼야 한다.

## D. 관찰에서 검증된 지식이 증가하는 학습 생애주기

1. 기존 `(action, shape_id)` 학습을 유지하되, 표면 동사/이름을 넘어 역할·관계·조건·효과의 공통 구조를 후보로 만들 수 있게 확장한다. 사람이 최종 개념 이름이나 정답 관계를 후보에 직접 넣지 않은 최소 3개의 독립 경험에서 후보가 만들어져야 한다. 초기 행동 의미·기본 연산·공리·환경 규칙은 제공할 수 있지만 이를 스스로 발견한 지식으로 보고하지 않는다.
2. **후보 구성 경험 / 별도 검증 경험 / 활성화 후 처음 보는 적용 경험 / 최종 독립 평가**를 식별자로 분리하고 누출을 막는다. 같은 4번째 사건을 검증과 이후 새 적용의 증거로 중복 사용하지 않는다. 이후 평가 사례를 곧바로 검증 집합에 넣어 학습한 뒤 그 결과를 학습 전 예측 성공으로 세지 않는다.
3. 동일 사건의 재전송, 같은 관찰의 복원/재생, 자신의 답변·가설·요약은 독립 외부 증거가 아니다. 자기 출력이 반복될수록 support/confidence가 증가하지 않도록 원천과 lineage를 추적한다. 요약/추론된 결과는 원 관찰의 종속 근거로 남긴다.
4. candidate의 범위·근거·반례·confidence·버전을 보존한다. 다른 맥락이나 정의 버전을 즉시 같은 법칙으로 합치지 않는다. 상충은 보류하고, 반례에 따라 범위 조정·분화·약화·철회할 수 있어야 한다. 관찰 상관만으로 관찰하지 않은 인과를 확정하지 않는다.
5. `rule_learning`, `semantic_feedback`, `self_authoring` 등 기존 경로를 재사용해 node/edge/rule/구조 변경 후보를 동일한 경험 기반 변경 이력에 연결한다. 변경 이유·원천·검증 결과·기준 버전과 적용/rollback을 추적한다. 사람이 `.kg`를 직접 수정하는 과정을 필수로 만들지 않는다.
6. 로컬 학습 후보는 명시된 검증·충돌 검사·승인 정책을 통과한 경우에만 활성화한다. 자율 평가 실행 전에 정책을 고정하고, 정책상 허용된 후보는 루프가 활성화할 수 있게 한다. 실제 사용자 승인이 필요한 변경은 기다리며 완료로 세지 않는다. 검증을 없애거나 제품 코드를 스스로 고치는 방식을 자율 지식 증가로 대체하지 않는다.
7. 활성화가 실제 이후 질문/관계 판단/계획의 결과에 영향을 줘야 한다. 같은 관찰·팩·기본 지식을 유지하고 새 학습 구조만 OFF로 바꿨을 때 해당 추가 능력이 사라지고, 독립적인 기존 답과 근거는 남아야 한다. 반례로 철회하면 그 구조에 의존한 결론만 제거된다.

## E. 미리 정한 step 재생을 넘어서는 닫힌 경험 루프

초기 설정 뒤 다음 경로가 하나의 실행 가능한 로컬 환경에서 이어져야 한다.

`관찰 → 사건 기록 → 관련 기억 조회 → 목표/전제/정보 공백 판단 → 가능한 행동 선택 → 환경/도구 결과 관찰 → 가설·개념·규칙 검증 → 기억·감정·선호 갱신 → 다음 판단과 행동`

1. 초기 팩·환경·seed·목표·허용 행동·자원 예산·검증 정책을 주면 여러 에피소드를 스스로 진행하는 CLI/API를 제공한다. 사람이 매 스텝의 `goal_assessment`, `affect_label`, rule 정답, 최종 답, 행동 순서를 직접 지정해야 하는 시연으로 대신하지 않는다. 기존 scripted cycle은 회귀/재현에 재사용할 수 있다.
2. 작은 로컬 환경과 파일/시뮬레이션 adapter로 구현한다. 환경은 관찰과 행동 결과를 제공하고, 추론기는 허용된 관찰만 소비한다. 평가용 숨은 정답이나 내부 환경 상태를 학습/행동 선택에 전달하지 않는다. 자연어 행동 학습도 같은 사건 경로로 연결한다.
3. 최소 하나의 정보 공백에서 ALMA가 조회/관찰 행동을 선택하고, 그 결과로 다음 판단이나 행동이 달라지는 사례를 포함한다. 도구 결과를 로그에만 저장하지 않는다. 도구가 실패하면 실패를 관찰로 받아 다른 허용 행동을 고르거나 부족한 전제를 밝히고 보류한다.
4. 정보 공백/목표와 capability의 선언된 기능·입출력 계약을 맞춰 선택한다. read 도구 하나뿐이라서 무조건 선택하는 검증에 그치지 않는다. 적합한 read 도구와 무관한 read 도구가 같이 있을 때의 선택/보류를 검사한다. 도구 추가·교체 시 코어 수정 없이 개인 기억을 유지한다.
5. 단계/에피소드/후보/증명/메모리 예산과 중단·저장·재개를 제공한다. 상한에 걸리면 결과의 불완전성을 보존한다. 새 관찰이 없거나 반복이 더는 정보를 주지 않으면 대기/종료 이유를 남긴다. 무한 반복·중복 기록·자기 확신 증가를 학습으로 보고하지 않는다.
6. write/execute 권한과 기존 외부 승인 게이트를 유지한다. 가정/계획을 실제 외부 행동으로 자동 실행하지 않는다. 이 goal의 자율 실험은 로컬 환경에서 수행하며 실제 계정 연결·외부 메시지·유료 서비스가 필수여서는 안 된다.

## F. 환경 경험에서 감정·취향·목표 갱신

1. 저장된 사건과 현재 목표·관계·예상 손실·통제 가능성으로 원인 패턴을 계산한다. 호출자가 감정 label이나 `threatened=True`를 넣는 것만으로 완료하지 않는다. 원인 event가 없거나 무관한 경우 해당 경험을 근거로 확정하지 않는다.
2. 같은 사건에서 목표/관계/통제 가능성이 달라질 때 관련 상태와 선택이 달라지고, 위협 원인이 해소되면 상태도 바뀌어야 한다. ‘왜 지금 이런 상태인가’에 실제 원인 경로와 근거를 보여준다. 단순히 필드에 저장한 것과 판단에 사용한 것을 구별한다.
3. 취향은 검증된 경험→감정/평가→기억→반복과 기대→preference로 형성한다. 대상별 초기 선호나 외부에서 지정한 감정 label로 증감한 점수만으로 대체하지 않는다. 존재하지 않는 event ID와 감정 근거가 없는 입력이 선택을 바꾸는 기존 반례를 막는다.
4. utility와 preference를 구별하고, 맥락 차이·경험이 다른 개체·일관된 반복·반례/상충에 따라 선호와 confidence가 어떻게 달라지는지 검증한다. confidence가 중복 행 수만으로 증가하지 않게 한다. 정정·철회·재시작 뒤에도 선택 이유를 과거 경험까지 추적한다.
5. 미충족 목표나 정보 공백에서 다음 행동/하위 목표 후보가 실제로 만들어지도록 한다. 목표 달성/실패는 관련 사건이 충족 조건을 지지하는지 확인한다. 무관한 사건 ID를 하나 연결하여 목표를 달성으로 바꾸지 않는다.
6. 미래 목표·관계·기억·자기 연속성의 지속 불가능성을 평가하는 실험을 포함하되, 특정 감정 이름이나 존재 질문이 반드시 나오도록 정답을 심지 않는다. 실제 관찰한 결과를 보고하고, 의식/주관적 경험이 입증됐다고 선언하지 않는다.

## G. 지식 증가를 입증하는 독립 평가

구현 초기에 아래 비교의 입력·기대 의미·반례·학습/평가 분할을 짧게 고정한 뒤 바로 구현한다. 제품 코드는 평가 정답을 읽지 않는다. 고정 seed 재현과 서로 다른 에피소드/역할/상태/양태의 변형 평가를 함께 둔다.

| 비교 | 반드시 확인할 것 |
| --- | --- |
| 학습 전 / 학습 후 | 처음에는 근거가 없어 보류하거나 잘못 판단하던 별도 새 사건에서, 검증된 새 구조로 올바른 답과 근거가 생김 |
| 같은 관찰을 저장한 학습 OFF / ON | 사실을 더 입력해서 생긴 차이와 학습 구조의 기여를 분리. 신규 구조 활성 여부 외 조건을 맞춤 |
| 새 구조 ON / 해당 구조만 OFF | 그 구조에 의존한 결론만 사라지고 기존 지식과 독립 증명은 유지 |
| 중복 관찰 / 독립 관찰 | 중복으로는 support/confidence/검증된 지식 수가 부풀지 않음 |
| 지지 / 반례 / 맥락 변경 | 오답 확신을 강화하지 않고 검증·보류·범위 수정·철회가 일어남 |
| 학습 자료 / 독립 평가 | ID·원천·시점을 분리. 평가 정답/피드백을 본 뒤의 결과를 보기 전 성공으로 세지 않음 |
| shortcut OFF / ON | 같은 결론과 필요한 근거·분기 유지, 실제 전체 반복 비용 감소 |
| 중단 전 / 새 프로세스 재개 후 | 상태·근거·개념/규칙·감정/선호·목표·미완료 요청을 이어가고 완료 효과를 중복 실행하지 않음 |
| 기존 입력 범위 / 새 사례 | 인명 교체뿐 아니라 역할·조건·양태·상태·의미 대조와 범위 밖 안전한 보류 포함 |

**지식 증가 판정 규칙:**

- 원시 관찰, 새 사실, 후보 개념/규칙, 검증된 활성 개념/규칙, 철회된 지식을 구분하여 집계한다. 노드/로그/파일 크기 증가는 학습 효과가 아니다.
- 지원·검증·적용 사건과 버전으로 각 새 지식의 출처를 설명한다. 사람이 제공한 의미/규칙은 별도 집계한다.
- 학습 ON이 OFF보다 독립 평가의 정답·근거 충족을 실제로 개선해야 한다. 그 차이를 만드는 배운 구조와 사례를 제시한다. 새 지식이 생겨도 평가에서 쓰이지 않으면 핵심 완료 조건을 충족하지 않는다.
- 긍정 문제의 보류를 성공으로 세지 않고, 부정·미확인·상충 및 범위 밖 사례에서 거짓 확신이 늘지 않는지도 검사한다. 기존 해결 사례의 회귀를 숨기지 않는다.
- 학습된 지식이 반례 때문에 줄어드는 것은 정상적인 교정일 수 있다. 매 반복에서 지식 수가 반드시 늘도록 강제하지 않는다.
- 이미 고정된 입력을 되풀이하는 것만으로 향상이 나오지 않는 대조 실험도 포함한다. 새로운 유효 관찰이 있어야 근거를 추가할 수 있다.

## H. 최종 통합과 완료 게이트

1. **한 통합 시나리오:** 자연어로 행동을 배운 개체가 여러 에피소드에서 관찰하고, 기억/패턴/개념/구조를 바꾸고, 새 영역/사건에서 사용하며, 원인을 설명하고, 잘못된 근거를 교정한 뒤 별도 프로세스에서 다음 경험과 학습을 이어간다. 서로 연결되지 않은 수동 API 데모를 나열하지 않는다.
2. **이전 goal 마감:** 수량·위치 모두 정확한 관계/설명, 개념 OFF, 별도 전제의 긍정/부정/미확인/상충, 학습 근거와 전제 교정, 구조 반례, 활성/교정 후 새 프로세스 복원을 검사한다. 같은 프로세스의 객체 재생성을 새 프로세스로 보고하지 않는다. 준 사람 감소 제거·잘못된 기대값·후반 오류의 실패 처리는 유지한다.
3. **네 영역 공통 경로:** 직접 구조 입력과 자연어 입력을 분리하여 보고하고, Mental의 조건/믿음 갱신도 실제 후속 추론과 설명에서 사용됐음을 증명한다.
4. **반례 마감:** 완료 검토의 모든 결함에 수정 전 재현·수정 후 정상 기대값·원인 계층의 회귀시험을 연결한다. 기존 반례 스크립트는 발견 당시 오류를 출력하도록 만들어졌으므로 종료 코드 0만으로 정상 여부를 판단하지 않는다.
5. **최종 회귀:** 변경 중에는 관련 시험을 사용하고 최종 코드에서 전체 시험, 팩 검사, 고정 평가와 새 독립 평가, diff 검사를 실행한다. 선택 말뭉치 skip은 핵심 기능 통과와 분리하고 자료 설치 방법/식별값을 남긴다. 요구된 필수 기능을 ‘미지원’으로 옮겨 완료 조건을 줄이지 않는다.
6. **자산 이동:** 검증된 팩과 개인 상태 백업을 별도로 제공한다. 지식/언어/공리/승인 학습은 팩, 개인 사건/목표/선호는 개인 상태라는 경계를 지킨다. 깨끗한 별도 실행 디렉터리/프로세스에서 호스트의 느슨한 원본 파일에 기대지 않고 능력과 개인 연속성을 복원한다. 개인 경험을 공유 팩에 자동 포함하지 않는다.
7. **비용:** 초기 준비, 후보 학습/검증, 반복 질문/설명, 기억 검색/저장, 복구, 전체 시나리오 비용과 최대 메모리를 나눠 보고한다. shortcut 비교는 조건을 맞춰 계측하고 동시 부하/환경을 기록한다. 플랫폼별 RSS 단위를 확인하고 미지원 계측을 추정치로 확정하지 않는다.
8. **증거 매핑:** Addition의 각 완료 기준과 이전 G0~G5를 이번 A~H의 코드·시험·원시 결과에 연결한다. 상태는 검증 완료/미완료/검증 불가로 명시한다. 문서 행 존재, 검사 수, 실행 횟수, 후보 수만으로 완료 처리하지 않는다.

## 실행과 종료 지침

- 이 문서 전체를 하나의 goal로 실행한다. A→B→C~F 통합→G/H 검증 순서로 진행하되, 작은 로컬 환경을 일찍 연결하여 공통 코어에서 확인한다.
- 표준 라이브러리와 기존 부품을 우선 재사용한다. 새 DB/서비스, 대형 언어 모델, 외부 유료 API, 새 게임 엔진/UI를 선행 조건으로 만들지 않는다.
- 동사·이름·물건·문장·concept ID·시험 ID 전용 분기와 완성 답안 저장을 추가하지 않는다. 실패를 특정 예문 예외나 정답 유출로 덮지 않는다.
- 최신 변경을 확인하고 사용자/다른 작업의 변경을 보존한다. 사용자 요청 없이 커밋·푸시·배포·외부 메시지 전송을 하지 않는다.
- 로컬의 안전한 구현·시험·시뮬레이션·문서화는 계속 진행한다. 기존 승인 정책상 필요한 외부 실행이나 파괴적 작업에는 구체적인 결과와 근거를 준비하여 승인을 요청한다. 내부 구현 선택이나 허용된 로컬 학습마다 불필요하게 멈추지 않는다.
- 관련 작업이 남아 있으면 다음 할 일만 적고 종료하지 않는다. 시간/토큰 부족이나 평가 실패를 완료로 표시하지 않는다. 중단이 불가피하면 미완료 조건과 정확한 재개 지점을 남긴다.
- 종료 직전에 완료 조건별 증거를 다시 대조한다. 현재 실행 코드와 결과 식별값이 맞는지 확인한다. 검증하지 않은 능력을 ‘가능하다’고 확정하지 않는다.
