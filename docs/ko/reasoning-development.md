## 구현 및 제한

`expression_graph.py`는 허용된 수식 구문을 연산 노드와 의존 관계로 바꾸고,
분수로 중간 값을 계산한다. 괄호, 우선순위, 다른 미지수 이름, 양변에 미지수가
있는 일차방정식을 처리한다. 상태 엔진은 원문의 수식과 노드를 다시 대조한다.
이는 형식 언어의 구조 해석 개선이며 자연어 의미 학습의 완성을 뜻하지 않는다.

## 남은 완료 조건

1. 평가: 개발 세트와 분리된 새 표현·관계 조합으로 최종 평가하고, 실제 UI/대화 경로와 자원 사용을 측정한다.
2. 의미 해석: 자연어의 개체·관계·수량·질문 대상을 구조로 만들고 표현 변화에 대한 전이를 증명한다. 언어 교체 작업과 구분한다.
3. 다단계 추론: 입력 사실과 KG 규칙을 결합하여 중간 사실을 유도하고, 목표까지 이어지는 근거를 남긴다. 수학 밖의 비교·조건·상태 변화도 검증한다.
4. 실패 학습: 실패와 교정으로부터 재사용 가능한 해석/추론 선택을 갱신하고, 학습하지 않은 문제에서 개선됨을 전후 비교한다. 답 문자열 저장이나 규칙을 사람이 추가한 것만으로 완료하지 않는다.

다음 작업은 자연어 의미 후보와 그래프 추론에 공유할 개체·관계·변수 표현 및
학습 인터페이스를 정하는 것이다. 현재의 숫자·표현별 패턴 증가를 최종 구조로 삼지 않는다.

## 관계 해석·다단계 추론 연결

- `relational_semantics.py`는 주석된 개체 슬롯과 관계 예시에서 문장 틀을 유도한다.
  언어별 사례는 `data/semantic/relations.json`에 있으며 기존 언어 교체 계층은 수정하지 않았다.
- `graph_inference.py`는 변수 결합과 여러 전제의 조인으로 새 사실을 유도한다.
  비교의 추이성, 분류의 상속, 분류에 속한 개체의 행위 적용은 데이터의 규칙이다.
  중간 사실은 입력 근거나 규칙 ID·부모 사실을 기록한다.
- 엔진과 UI의 상태 추론 경로에 연결했다. 실제 UI 테스트에서도 연구 호출 없이
  세 개체의 비교를 처리한다. 알려지지 않은 관계와 상충하는 비교는 유일한 답으로 승격하지 않는다.
- 동일 SHA-256 진단 세트에서 8/16 (`reasoning_transfer_after_relations.json`).
  새 이름을 사용한 세 단계 추론과 위조된 관계 기각을 포함한 전체 테스트는 101 passed.

## 교정 학습의 검증 범위

`python bench/relational_learning.py`는 기본 모델을 임시 경로에 복사하고,
해석에 실패하는 문장 틀에 대해 주석된 관계 예시 하나를 학습시킨다.
저장한 모델을 다시 읽는 실제 `engine.안내`에서 새로운 이름과 사슬 길이를 가진
3문항이 0/3에서 3/3으로 개선된다. 정답 문장이나 시험 개체는 학습 모델에 넣지 않는다.
교정은 기존 예시와 모순되면 반영하지 않으며, 추론 규칙 자체는 바꾸지 않는다.
모델 경로는 `NAI_RELATIONAL_MODEL`로 지정할 수 있다. 기본 시드 파일은 저장 대상으로 거부한다.

이는 명시적 감독을 받는 문장 틀 학습이다. 자동 실패 원인 발견, 관계 규칙의 학습,
일상 수량 변화·문맥 갱신·일반 독해, UI에서 교정을 받는 흐름은 아직 구현하지 않았다.
3/3은 다른 개체로의 전이 측정이며 완전히 새로운 표현에 대한 블라인드 성능이 아니다.
전체 목표는 진행 중이며 다음에는 관계 표현을 사건·수량과 연결하고 교정 인터페이스를 확장한다.

## 사건 순서에 따른 위치 갱신

- `current_facts`는 데이터에 선언된 단일값 속성(`mutable_predicates`)을 문장 순서로
  갱신한다. 개체와 속성별로 마지막 값만 후속 규칙 추론에 전달하고 이전 값·새 값·원문은
  상태 전이 기록에 보존한다. 위치 이름이나 질문별 정답은 실행 코드에 넣지 않았다.
- 질문의 변수와 사실을 결합해 현재 위치를 찾는다. 위치 외의 정적 관계 추론도 같은
  질의 결합을 사용하며, 답이 여럿이면 임의로 하나를 선택하지 않는다.
- 조사 경계가 겹치는 문장 틀은 고정된 원문 부분이 더 긴 후보를 우선한다.
  예: `가방으로`를 `가방으` + `로`로 잘못 분해하는 현상을 방지한다.
- 동일 개발 진단은 9/16 (`reasoning_transfer_after_temporal.json`), 전체 회귀는
  105 passed. 반복 이동, 다른 개체의 위치 분리, 이전 상태로부터 잘못된 결론을
  만들지 않는 검사와 실제 UI에서 웹 검색 없이 답하는 검사를 포함한다.

범위 제한: 명시된 문장의 순서만 시간 순서로 사용한다. 회상·조건부 사건·부정·
대명사 해소·여러 대화 턴의 상태 유지와 수량 변화는 아직 남아 있다.
완료되지 않은 나머지 요구사항(새 표현 평가, 자동 실패 분석, 추론 규칙 학습 및
사용자 교정 흐름)은 그대로 유지한다.

## 교정된 추론 예시에서 규칙 학습

`rule_learning.py`는 여러 개의 정렬된 전제·결론 사례를 받아 공통된 관계와
개체의 대응을 유지한 변수 규칙을 유도한다. 후보 생성에는 검증 사례의 정답을
사용하지 않는다. 별도 개체로 구성된 긍정·부정 검증을 모두 통과하고 기존 오류를
개선할 때 `RelationalParser.learn_rule`이 후보와 검증 기록을 모델에 반영한다.
검증 실패 시 모델을 변경하지 않는다. 본문에 없는 변수가 결론에 나타나는 후보도 거부한다.

`semantic_feedback.py`로 실제 진단·교정을 실행할 수 있다.

```sh
python semantic_feedback.py diagnose '질문'
python semantic_feedback.py expression correction.json --output /private/tmp/nai-semantic-model.json
python semantic_feedback.py rule corrected-proofs.json --model /private/tmp/nai-semantic-model.json --output /private/tmp/nai-semantic-model.json
```

`expression` 입력은 `text`, `slots`, `meaning.triple`을 가진 주석 사례다.
`rule` 입력은 `corrections`와 `validation` 배열이며 각 항목은 `id`,
`premises`(삼중항 배열), `conclusion`(삼중항)을 갖는다. 검증 항목은
`expected` 불리언도 필요하다. 학습과 검증 사이의 개체 중복을 거부한다.
`NAI_RELATIONAL_MODEL`로 저장 모델을 지정하면 엔진과 UI가 같은 모델을 읽는다.

진단은 문장 해석 실패와 추론 근거 부족/비유일성을 구분한다. 실패 원인을 완전히
자동으로 특정하거나 교정 정답을 발견하는 것은 아니며, 교정된 관계/증명을 사람이
제공해야 한다. 유한한 검증 사례 통과가 규칙의 보편적 진실을 증명하지는 않는다.

검증: 비교의 추이 규칙을 의도적으로 제거한 모델에서 실패를 재현하고, 규칙을
직접 제공하지 않은 두 교정 증명으로 복원했다. 저장 후 재시작한 실제 엔진이
교정에 없던 이름의 사슬을 풀고 학습된 규칙 ID를 근거로 남겼다. 이는 규칙 누락
복구 실험이며 기존 기본 모델의 개발 진단 점수가 올랐다는 뜻은 아니다.
서로 다른 관계(p, q → r)의 변수 유지, 끊긴 사슬, 역방향 부정 사례, 과잉 일반화
거부, 검증 실패 시 CLI의 저장 방지 및 성공 시 재로딩을 포함해 전체 113 passed.

남은 범위는 수량 변화, 문맥/독해 일반화, 더 폭넓은 독립 평가와 사용자 UI 교정,
자동 실패 분석 및 감독 의존도를 줄이는 학습이다. 전체 목표는 완료되지 않았다.

## 수량 사건과 표현 교정 연결

`numeric_updates` 데이터가 증감 관계의 대상 속성과 계수를 선언한다. 상태 전이는
초기 수량에 각 사건을 순서대로 적용하고, 최종 수량만 그래프 질의에 전달한다.
초기값 부재, 음수가 되는 개수, 생략된 대상의 모호성, 같은 대상이 서로 다른 장소에
있는 범위 충돌은 추정하지 않고 실패 이유를 남긴다. 정수 개수만 지원하며 한글 수사,
여러 단위의 환산, 복수 장소를 명시적으로 지정하는 질의는 남아 있다.

고정 개발 진단은 10/16 (`reasoning_transfer_after_quantity.json`)이다. 전체
테스트 122 passed에는 실제 UI의 연구 호출 없는 수량 답변과 교정 전후 전이가 포함된다.
`구슬 4개를 덜어냈다`라는 주석 교정 하나를 저장한 뒤, 새로운 대상과 숫자의 두
문제가 실제 엔진에서 미지에서 정답으로 바뀐다. 이는 새 문장 틀의 감독 학습이지
새 연산 자체를 발견한 것은 아니다.

실패 진단은 수량/추론 전제 오류도 구분한다. 예를 들어 초기값 없이 꺼낸 사건만
있으면 `missing_initial_quantity`를 반환한다. UI 교정 연결, 한글 수사·다양한
표현과 일반 독해, 다턴 문맥, 폭넓은 독립 평가와 자동 교정 발견은 계속 남아 있다.

## 대화별 상태 문맥

`reasoning_context.py`를 `engine.대화`와 UI의 대화/세션별 경로에 연결했다.
완전히 해석된 사용자 관찰 문장만 원문으로 보관하고 매번 재해석·재계산한다.
따라서 질문을 반복할 때 증감 사건이 다시 누적되지 않으며, 모델을 교체하면 이전
문장의 해석도 새 모델로 확인한다. 답변 문장은 사실로 저장하지 않는다.
전제 오류가 난 사건은 기록에 반영하지 않으며 대화별 기록도 분리한다.
근거의 `turn`은 보관된 관찰 입력의 순번이며 전체 채팅 메시지 번호는 아니다.

실제 UI에서 관찰 → 이동 → 위치 질문, 엔진 대화에서 초기 수량 → 감소 → 반복 질문,
두 턴의 비교 사실 연결, 세션 분리, 잘못된 사건의 미반영을 검증했다.
전체 테스트는 127 passed. 기존 16문항 진단은 단일 턴이므로 다턴 능력을 대표하지 않는다.

현재 문맥은 프로세스 메모리 안에서만 유지하며 관찰 입력 128개 한도다. 재시작 시
복구, 모호한 지시어 해소, 실패 교정 UI는 남아 있다. 이해한 질문이 조건 부족이면
그 사실을 답하며 무조건 웹 연구로 내려가지 않는다. 입력 자체를 해석하지 못하면
기존 처리 경로를 사용한다. 전체 목표는 계속 진행 중이다.
