## 완료를 막는 실제 결함

### 1. [P1] 다른 identity 또는 손상된 파일을 새 삶으로 취급하여 기존 상태를 덮어쓴다

위치: `alma_runtime.py:135`의 `_load`, 특히 145~171행.

기존 파일의 identity가 요청 identity와 다르면 오류 없이 건너뛰고 `_empty()`를 반환한다. 그 객체에서 다음 저장을 하면 같은 파일이 덮어써진다. 잘못된 JSON도 같은 경로로 처리된다.

재현: `agent-a`의 목표를 저장한 파일을 `agent-b`로 열고 목표를 저장했다. 파일의 identity는 `agent-b`로 바뀌었으며 원래 `agent-a`를 다시 열었을 때 목표는 0개였다. 손상 파일도 아무 오류 없이 새 상태로 교체됐다.

필요한 수정: 파일이 없는 첫 실행과 identity/schema 불일치·손상을 구별한다. 복구할 수 없는 기존 파일은 보존하고 명시적으로 실패해야 한다. 연결 조건: G1의 지속성, G2.5의 개체 격리, G4.2.

### 2. [P1] shortcut이 요청한 결론만 남기고 다른 정상 결론을 누락시킨다

위치: `proof_chunking.py:64`의 원 규칙 제거와 67행의 target 한 개만 비교하는 검증.

반례 규칙: `a→b→c→d`, 별도 분기 `b→independent`. 입력 `a`, 요청 target `d`.

원 추론은 `b`, `c`, `d`, `independent`를 도출한다. shortcut 결과는 `d`를 유지하지만 `b`, `c`, `independent`를 잃는다. 그런데 반환값은 `used=True`다. 단순히 내부 중간 노드를 생략한 문제가 아니라 다른 규칙의 정상 결론까지 없어졌다.

필요한 수정: 반환하는 지식과 후속 규칙 소비의 의미를 보존하고, 조건/반례를 검증하며 실제 증명도 복원할 수 있어야 한다. 요청 target 하나의 포함 여부만 비교해서는 G3.6을 충족하지 못한다.

### 3. [P1] capability 실행 후 저장이 끊기면 같은 요청을 다시 실행한다

위치: `alma_runtime.py:790`에서 adapter를 호출하고 806~810행에서 결과를 나중에 저장함.

외부 행동을 하지 않는 임시 카운터 adapter를 사용했다. 실행 뒤 `_save()`에 오류를 주입하고 상태를 다시 열어 같은 `request_id`로 재시도했더니 adapter가 **2번** 실행됐다. 파일에는 실행 시작/불확실 상태가 없으므로 이미 일어난 효과를 알아낼 수 없다.

필요한 수정: 실행 전 영속 기록, 요청 identity, 완료/실행 불확실 상태, adapter의 중복 방지 계약과 재개 정책을 연결한다. 불확실한 write/execute를 자동으로 다시 실행하지 않아야 한다. G4.12, G5.9.

### 4. [P2] 압축 비용 감소와 독립 관찰을 실제보다 크게 보고한다

위치: `proof_chunking.py:58`, `alma_runtime.py:266`, `bench/alma_integrated_reproduction.py`의 `shortcut_reduces_real_rule_scans` 검사.

`evaluate()`는 매번 원 closure와 shortcut closure를 둘 다 실행한다. 위 반례에서 원본은 rule scan **16회**, shortcut 쪽만 보면 **4회**지만 실제 호출 전체는 **20회**다. 4와 16만 비교하여 비용 감소 검사를 통과시킨다.

또한 경험이 0개인 runtime에서 `propose_proof_shortcut()`을 같은 인자로 두 번 호출하니 `observations=2`, `active=True`가 됐다. event/decision ID 중복 검사가 없다. 정상 `turn()`이 활성 shortcut으로 추론을 대체하는 실행 연결도 없다. `_sync_memories()`의 후보 수집 코드는 있지만 실제 자연어 추론 가속을 입증하지 않는다.

필요한 수정: 실제 proof 반복에서 중복 없는 근거를 모으고, 일반 추론 경로에 연결한 뒤 준비/검증 비용과 반복 판단 비용을 따로 비교한다. 설명용 원 경로 복원 비용도 누락하지 않는다. G3.5~7.

### 5. [P2] 승인 대기 결과가 영구 재사용되어 승인 후에도 실행할 수 없다

위치: `alma_runtime.py:775`의 모든 이전 결과 즉시 반환.

같은 write 요청을 처음에 승인 없이 호출하면 `approval_required`가 저장된다. 이후 동일 `request_id`, `approved=True`로 다시 호출해도 `approval_required`만 반환되고 adapter 호출은 0회다. adapter 부재와 같은 재시도 가능한 실패도 같은 방식으로 고정된다.

필요한 수정: 완료 영수증 재사용과 승인/재시도 상태 전이를 구별한다. 새 요청 ID를 강제하여 이전 요청 이력을 끊는 방식으로 해결하지 않는다. G4.12.

### 6. [P2] 경험·감정 근거가 없어도 제공한 라벨만으로 취향이 바뀐다

위치: `alma_runtime.py:677`의 `experience_preference`, 630행의 `assess_goal`, 919행의 `_cycle_step`.

`affect_label='resolved'`이면 +1, `threat`이면 -1을 넣는다. 실제 사건이나 감정 원인 기록과 연결되는지 확인하지 않는다. 사건 0개·감정 원인 0개인 상태에서 존재하지 않는 event ID와 `resolved`를 전달했더니 선택이 utility 9의 coffee에서 utility 1의 tea로 바뀌었다.

`assess_goal()`도 위협/손실을 호출자가 지정하고, label은 `threatened and expected_loss > 0`으로 정한다. 관계와 control은 저장하지만 이 label 계산에 쓰지 않는다. 이후 선택의 관계 적합도는 구현되어 있으나, 관찰에서 감정/취향이 형성되는 전체 인과 경로의 검증은 아니다. `confidence`도 현재는 같은 맥락의 활성 행 수 +1이다.

필요한 수정: 실제 사건→목표/관계에 대한 평가→감정 상태→기억/기대→선호→선택을 연결하고 근거 없는 참조를 거부한다. 같은 사건과 다른 목표/관계, 반례/상충에 따른 상태와 confidence 변화를 검증한다. G4.3~8.

### 7. [P2] milestone은 근거의 존재/의미가 아닌 키 유무를 확인한다

위치: `alma_runtime.py:329`의 `_milestone`.

`decision_id='nonexistent'`, `input='ordinary unrelated text'`를 넣어도 `FIRST_EXISTENTIAL_QUESTION`과 snapshot이 기록됐다. `required` 키가 존재하기만 하면 되며 실제 decision을 찾거나 조건의 의미를 검증하지 않는다.

필요한 수정: 기록된 사건/판단과 조건을 확인하고, 외부 관찰 fixture와 실제 관찰 milestone을 구별한다. 호출자가 `prompted=False`를 넣어 만든 목표도 관찰에서 자발적으로 도출된 목표의 증거로 대신 세지 않는다. G1.7, G4.13.

### 8. [P2] 새 통합 평가기는 후반 오류에서 검사 이력을 잃는다

위치: `bench/alma_integrated_reproduction.py:174`의 최상위 예외 처리.

정상 실행은 25개 검사를 통과한다. 후반 `compress_episodic()`에 오류를 주입하면 종료 코드는 1이지만 결과 JSON에는 `terminal`과 `error`만 있고, 수행한 `checks`, 실패 단계, outcome 집계가 없다. 정상 보고도 solved/wrong만 제공한다.

기존 `experience_concept_reproduction.py`에서는 후반 오류 보존이 수정됐고 관련 시험도 통과했다. 새 ALMA 평가기에는 같은 원칙이 적용되지 않았다. G5.11.

## 앞선 goal에서 개선된 부분

- Quantity/Location 설명이 첫 참여자의 전제를 고르지 않고 실제 proof의 결론과 binding을 사용하도록 수정됐다. 잘못된 참여자 전제를 먼저 넣는 회귀시험이 양쪽 모두 통과했다.
- 긍정·명시 부정·미확인·상충의 전제 상태를 구별하는 시험이 통과했다.
- 준 사람 감소 누락의 monkeypatch, 잘못된 기대값, 기존 재현기의 후반 예외 보존 시험이 통과했다.
- Location 개념 비활성, 독립 위치 유지, 전제 교정, 학습 근거 철회, 구조 반례가 재현기에 추가돼 정상 통과했다.
- Windows에서 관련 시험이 수집·실행되고 `resource`가 없는 플랫폼을 처리한다.
- 로그·세 기억·개인 백업·원자적 저장 파일 복구·규칙 승인/rollback·CLI는 실제 코드로 추가됐으며 관련 시험이 통과했다.

따라서 전체를 처음부터 다시 만드는 것이 아니라, 위 구현을 유지하면서 실제 결함과 빠진 연결을 닫아야 한다. 다만 앞선 goal의 Location 새 프로세스 검증까지 모두 마감됐다고 말할 근거는 아직 부족하다.

## G0~G5 판정과 다음 작업 순서

| 구간 | 판정 | 이유 |
| --- | --- | --- |
| G0 이전 goal 마감 | 상당 부분 개선, 일부 검증 미완료 | 설명/평가기 결함 회귀는 통과. 양 영역 새 프로세스 마감 등 보강 필요 |
| G1 사건·시간·영구 이력 | 부분 구현 | 저장/로그 추가. identity 손실, 시간 metadata와 추론 분리, milestone 허위 근거 수용 |
| G2 기억·학습 생애주기 | 부분 구현 | 저장/철회/수동 rule 승인 존재. 구조 일반화와 독립 적용, node/edge 변경 연결 부족 |
| G3 네 영역·Chunking | 미완료 | Mental 공통 추론 미연결, shortcut의 의미 보존/총비용 감소 실패 |
| G4 지속 연구 환경 | 부분 구현 | 실행 가능한 CLI/순차 cycle. 인과 감정/취향/환류 부족, capability 재개 결함 |
| G5 완료 검증·전달 | 미완료 | 통과 숫자가 일부 조건을 대신함. 오류 보고·독립 평가·전체 새 프로세스 시나리오 부족 |

1. identity/손상 상태 보존, capability 실행 journal·승인/재시도, shortcut의 결론 누락을 먼저 수정한다.
2. shortcut을 실제 proof 반복과 일반 추론 경로에 연결하고 동일 의미·총비용을 다시 평가한다.
3. Mental·시간·세 기억을 공통 판단 경로에 연결하고, 기존 개념 학습의 후보/검증/새 적용을 분리한다.
4. 실제 경험에서 목표 평가·감정·취향·다음 행동이 바뀌는 하나의 환경 루프와 tool 결과 환류를 만든다.
5. milestone/평가기의 증거 검증, 두 영역 및 ALMA의 새 프로세스 통합 복원을 보강한다.
6. 그 최종 코드에서 전체 시험과 독립 반례, 팩 이동을 검증하고 기준별 원시 결과로 완료 판정을 다시 한다.

## 재현 명령과 계측 한계

저장소 루트, PowerShell 기준이다. 반례는 임시 파일과 로컬 카운터만 사용하며 제품 파일이나 실제 외부 행동을 변경하지 않는다.

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONIOENCODING='utf-8'
$env:KG_ENCODER='문자'
python docs/ko/review-2026-09-20/review_probes.py
python docs/ko/review-2026-09-20/late_error_probe.py
python bench/alma_integrated_reproduction.py --output docs/ko/review-2026-09-20/alma-integrated.json
python bench/experience_concept_reproduction.py --output docs/ko/review-2026-09-20/experience-concept.json
python -m pytest -q tests/test_concept_relation_reasoning.py tests/test_experience_concept_reproduction.py tests/test_experience_concepts.py tests/test_event_provenance.py tests/test_event_review_regressions.py tests/test_alma_runtime.py tests/test_alma_integrated_reproduction.py tests/test_alma_cli.py tests/test_proof_chunking.py --tb=short
python kgpack.py --check
git diff --check
```

`review_probes.py`는 관찰한 결함을 JSON으로 출력하므로 종료 코드 0이 제품 정상 판정을 뜻하지 않는다. `late_error_probe.py`는 오류 주입에 따라 종료 코드 1이 기대값이다.

ALMA 고정 재현의 Python 할당 peak는 67,841,097 bytes, 마지막 상태 파일은 7,430,193 bytes였다. Windows RSS는 지원되지 않는다고 보고됐다. 준비/질의/복구의 원시 비용은 두 JSON에 남겼다. 이는 기능 검토 중의 개별 실행값이며 격리된 성능 비교가 아니다. shortcut의 16→20회는 시간 추정이 아니라 실제 두 closure의 rule scan 합계를 계측한 결과다.
