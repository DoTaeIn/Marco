# MARCO / ALMA 다음 10개 goal 로드맵

최신 실행 순서는 [2026-09-22 MCO 통합 기획과 타임라인](2026-09-22-mco-integrated-roadmap.md)이다. MARCO / POLO 20개 제안의 [2026-09-21 상세 goal 요구](2026-09-21-marco-polo-roadmap.md)도 유지하며, 해당 문서 18절에 아래 기존 goal의 대응 위치를 기록했다. 아래 문서는 이력으로 보존한다. 바로 다음 언어 그래프 goal과 기존 미완료 요구는 유지한다.

## 후속 결정: 바로 다음 goal의 우선순위

사용자 결정에 따라 바로 다음 실행 goal은 [언어·문법의 그래프화와 언어 교체 시 추론·학습·기억 보존](2026-09-20-language-graph-goal.md)이다. 아래 장기 로드맵의 언어·대화 기능 확장에 앞서, 언어 지식을 실행 가능한 그래프로 옮기고 한국어·영어·교차 언어의 공통 추론과 기억 보존을 검증한다. 기존에 완료된 기능과 미완료 요구는 보존하며, 이 결정 자체로 다른 실행 중인 작업을 중단하지 않는다. 다음 goal의 세부 범위와 완료 판정은 링크한 문서를 따른다.

## 이번에 바꾸는 개발 순서

사용자가 체감하는 문장 이해·문맥 유지·독해·추론을 먼저 개선하고, 그 능력 위에 표현 학습·개념 학습·자율 행동·감정/취향을 연결한다. 2026-09-20-addition-next-directions.md의 요구는 유지하되 각 goal의 종료점을 분리한다. 한 단계 완료를 MARCO/ALMA 전체 완료로 보고하지 않는다.

앞선 goal은 저장 안정성부터 일반화·감정·자율 루프까지 한 번에 묶어 범위가 컸다. 개별 API 시험이 통과해도 일상적인 질문은 계속 실패할 수 있었다. 이번에는 각 goal에 사용자가 입력할 대화, 기대하는 의미 결과, 실패 대조, 실제 진입/완료 조건을 둔다.

**확정된 제약: 언어 모델 금지, 글자·형태소 분석 허용.** 생성형 언어 모델, 사전학습 문장 인코더/텍스트 임베딩 모델, 언어를 생성하는 VLM으로 MARCO의 이해·추론·답변을 대신하지 않는다. 문자 n-gram, 조사·어미·형태소 분석, 그래프·규칙·검증된 표현 학습은 허용한다. 개발 도구가 쓰는 모델과 MARCO 제품 런타임의 의존성을 구별한다.

## 현재 진행 중인 작업과의 관계

작성 시 `ALMA 0.1 실행 환경 통합 구현` 작업은 다시 실행 중이며 `alma_environment.py`와 환경/학습 생애주기/통합 재현 코드가 추가되고 있다. 이 로드맵 작성만으로 해당 작업을 중단하거나 지시를 바꾸지 않는다. 기존 `2026-09-20-next-goal.md`도 보존한다.

새 실행 보고에는 환경의 새 프로세스 재개, 학습/검증/적용 경험 분리 등이 나타나지만 아직 이 로드맵 작성자가 독립 검증한 완료 결과는 아니다. Goal 1에서 최신 결과를 검사해 각 단계에 반영한다. 이미 해결된 요구는 다시 구현하지 않고 검증하여 재사용한다. 이전 검토에서 발견한 결함도 현재 코드에 그대로 남아 있다고 가정하지 않는다.

마지막 독립 대화 측정은 기본 고정 질문 16/16, 변형 질문 7/14, 답 가능한 대화 문제 14/27이었다. 변형 질문의 실패 7건은 의미 해석 단계에서 막혔다. 이는 추론 코어 전체가 실패했다는 뜻도, 코어만 개선하면 해결된다는 뜻도 아니다. 그 후 코드가 변경되고 있으므로 이 수치를 최신 성능으로 계속 인용하지 않는다.

**순서: 신뢰할 기준선 → 일상 문장 → 여러 턴의 문맥 → 문단 독해와 복합 추론 → 시간·네 영역·기억 → 가르치면 배우기 → 경험에서 새 구조 배우기 → 자율 경험 루프 → 감정·취향 → 실제 가속과 장기 운영.**

## 모든 goal에 공통인 실행·완료 규칙

1. 현재 작업공간과 최신 diff를 먼저 확인한다. 사용자와 다른 작업의 변경을 보존한다. 기존 Binary KG, Event/Condition/Hypothesis, proof, PackModel, ALMA 환경을 재사용한다. 새 엔진·서비스·DB 전체를 다시 만들지 않는다.
2. 각 사례를 가능한 한 **정답 의미 구조를 직접 준 시험**과 **같은 내용을 자연어로 준 시험**으로 나눈다. 직접 구조도 실패하면 상태/추론을, 자연어만 실패하면 해석/문맥을, 의미 답은 맞고 표현만 틀리면 출력 층을 고친다. 원인 계층을 구별하지 않고 예문이나 규칙을 늘리지 않는다.
3. 학습/개발/회귀/독립 평가를 구별한다. 공개된 기존 14개·34개 문항은 회귀 자료다. 새 평가 문항은 구현 전 별도 버전으로 고정하고, 답/기대 구조/금지 근거를 런타임에 전달하지 않는다. 개발 중 확인해 고친 문항은 이후 독립 평가라고 부르지 않는다.
4. 각 goal의 핵심 사용자 시나리오와 필수 대조는 모두 통과해야 한다. 처음 보는 표현/역할/구조의 평가도 해당 goal의 선언된 범위에서 수행한다. 전체 평균이 특정 범주의 실패를 가리지 않도록 범주별 결과와 미해결 원인을 공개한다. 범위와 필수 문항을 실패 후 좁혀서 통과시키지 않는다.
5. 정답에 필요한 대상·역할·수량·단위·시점·양태·필수/금지 근거를 검사한다. 정답 문자열 일부, phase=answer, JSON 키 존재, 실행 횟수, 시험 수, 노드 수를 성공 증거로 대신하지 않는다.
6. solved/safe_hold/wrong/execution_error/unverifiable와 기능 검사 통과 수를 구별한다. 답 가능한 문항의 보류는 미해결이다. 잘못된 확신, 잘못된 지시어 연결, 계획의 실제 실행, 근거 없는 사실 추가를 별도 실패로 기록한다.
7. 각 goal 종료 시 코드/팩/자료 식별값, 실행 명령, 실제 대화, 수정 전후 결과, 비용, 제한을 남긴다. 관련 시험으로 개발하고 최종 상태에서 필요한 회귀·전체 시험·팩/diff 검사를 실행한다. 다른 작업이 동시에 바꾼 코드와 결과를 같은 검증 상태로 섞지 않는다.
8. 각 goal은 아래 정해진 범위를 구현·검증하는 작업이다. 계획만 쓰고 완료하지 않는다. 필수 작업이 남으면 미완료 상태와 재개 지점을 명시한다. 사용자가 요청하지 않은 커밋·푸시·배포·외부 메시지는 수행하지 않는다.
9. ALMA 로컬 환경은 Goal 1부터 시험장으로 사용한다. 모든 지식을 갖출 때까지 환경 연결을 미루지 않는다. 다만 자율 행동과 감정 기능의 범위 확장은 각각 Goal 8·9에서 검증한다.
10. 새로운 자연어 전체를 기한 내 완성한다고 약속하지 않는다. 날짜 대신 검증된 능력으로 다음 단계에 진입한다. 같은 실패가 반복되면 문항 전용 예외를 추가하지 말고 문법/의미 합성/문맥/추론 중 병목을 다시 확인한다.

## Goal 1 — 최신 구현 검증과 신뢰 가능한 기준선

**설정할 목표 문장**

> 현재 진행 중인 ALMA 변경을 보존하고 최신 결과를 독립 검증하여, 데이터 손실·추론 결과 누락·capability 중복 실행·잘못된 평가 집계를 제거하고, 언어 모델을 사용하지 않는 런타임과 의미 해석/상태/추론/표현을 분리해 측정하는 고정 기준선을 확립한다.

**할 일**

- 이전 완료 검토의 반례를 현재 코드에 다시 적용한다. 이미 해결된 항목은 증거와 함께 닫는다. identity/손상 파일 보호, 승인 후 재시도, 요청 충돌, 실행 중단 후 불확실/완료 상태, 독립 결론 보존은 이후 작업의 필수 전제다.
- shortcut의 안전성 결함은 지금 수정하되 일반적인 성능 최적화는 Goal 10에서 한다. 적용이 불안전하면 원 추론으로 되돌아가는 명시적 경로를 유지한다.
- 선택형 신경망 인코더와 문서 VLM을 제품에서 사용할 수 있는 우회 경로로 남기지 않는다. 제거하거나 배포 런타임에서 명시적으로 차단한다. 환경변수/팩 설정으로 다시 켜도 모델을 불러오거나 다운로드하지 않아야 한다. 글자·형태소 분석 기능은 유지한다.
- 변형 14개, 답 품질 34개, Quantity/Location 관계 설명, 새 ALMA 실행 보고를 다시 측정한다. 실패를 표면 해석/지시·생략/지식 부족/상태 갱신/논리 추론/표현/평가기 결함으로 분류한다.
- 실패한 자연어에 대응하는 올바른 의미 구조를 직접 넣어 실패 지점을 분리한다. 전체 시험 개수와 사용자 문제 해결률을 별도로 둔다.

**완료 조건**

- 기존 삶을 다른 identity나 손상 상태로 조용히 덮어쓸 수 없고, 중단된 외부 효과를 확인 없이 재실행하지 않는다.
- 금지된 언어 모델을 호출하지 않는 검사와 실제 런타임 선언이 일치한다.
- 정상/잘못된 기대값/실행 오류 주입의 결과가 정확하게 구별되고 후반 실패 기록이 남는다.
- 다음 Goal 2~4가 해결할 실패 목록과 비교할 코드·팩·자료가 고정된다. 이 단계에서 전체 언어 능력까지 해결하려고 범위를 늘리지 않는다.

## Goal 2 — 일상 한국어 문장을 같은 의미로 읽기

**설정할 목표 문장**

> 기존 한국어 분석과 표현 학습을 재사용하여 조사·어미·어순·수사·문장 경계를 조합적으로 해석하고, 지원하는 수량·위치·비교·사건 문장의 일상적인 말투가 동일한 의미 구조와 결과를 내도록 구현·검증한다.

**사용자가 체감할 결과**

- `구슬은 18개 있다`, `구슬 18개 있어`, `구슬 18개 있음`을 같은 상태로 읽는다.
- `구슬 3개를 꺼냈다`, `구슬 세 개 뺐어`를 지원되는 수량 감소 의미로 연결한다.
- `3개 더 넣었어`의 `더`, `안 넣었어`의 부정, `넣을 예정이야`의 계획을 보존한다.
- 한 입력에 사건과 질문이 같이 있어도 순서대로 읽는다. 다른 주어가 있는 원인절을 한 사람의 이름으로 삼키지 않는다.

**할 일과 완료 조건**

- 기존 `hangul`, `language_components`, `frame_induction`, `expression_learning`, `relational_semantics`를 확장한다. 문자 유사도는 후보 탐색에만 쓰고 의미 동등성을 확정하지 않는다.
- 어미/조사 변환, 역할 결합, 술어 의미를 나눠 재사용한다. 문항마다 정규식/완성 답을 추가하는 방식으로 해결하지 않는다.
- 숫자·이름 교체뿐 아니라 새 어순, 부정/계획, 생략 없는 새 표현 조합과 의미가 다른 대조에서 역할·시간·양태가 맞아야 한다.
- 이 단계의 범위는 명시된 대상이 있는 문장 이해다. 대화에서 빠진 대상과 대명사의 해소는 Goal 3에서 검증한다.
- 알려진 로컬 계산/상태 문장을 이해하지 못했다는 이유로 외부 검색에 보내지 않는다. 실패한 절과 필요한 의미를 표시한다.

## Goal 3 — 여러 턴의 생략·지시어·정정 처리

**설정할 목표 문장**

> 사건별 역할, 대화 초점, 질문 대상과 확인 이력을 공통 문맥 상태에 연결하여, 같은 문장과 여러 턴에서 생략·지시어를 근거 있게 해소하고, 모호하면 필요한 부분만 질문하며, 정정 후 결론과 설명을 일관되게 갱신한다.

**사용자가 체감할 결과**

- `구슬 18개 있어 → 세 개 더 넣음ㅋㅋ → 몇임`에 **21개**라고 답한다.
- `다은이 책을 민지에게 줬다. 민지는 그것을 상자에 넣었다`에서 그것을 책에 연결한다.
- 책과 공이 모두 후보면 임의로 고르지 않고 `책과 공 중 무엇인가요?`라고 확인한다. 답을 받으면 보류된 같은 사건을 이어서 처리하고 효과를 두 번 실행하지 않는다.
- 다른 화제로 잠깐 넘어갔다가 돌아오기, 앞선 질문의 대상 유지, `아니, 3개가 아니라 2개` 같은 정정이 지원 범위에서 작동한다.

**할 일과 완료 조건**

- `input_understanding`의 최근 주제 후보와 `ReasoningContext`의 역할별 지시어 처리/보완을 대조하여, 서로 다른 대상을 임의로 확정하지 않게 공통 근거를 사용한다.
- 사람/물건/장소 유형, 최근 역할, 소유/위치 상태, 발화 시점, 현재 질문을 함께 사용한다. 가장 최근 명사를 무조건 정답으로 택하지 않는다.
- 같은 턴 안에서도 앞 절에서 생긴 대상·역할이 뒤 절의 지시어 해석에 쓰인다.
- 유일하게 풀리는 사례는 답하고, 모호한 사례는 한정된 확인 질문을 한다. 단순 보류가 늘어난 것을 개선으로 세지 않는다.
- 정정·주제 전환·복수 인물·독립 사건·새 프로세스 복원 뒤에도 잘못된 참조/이중 실행/이전 근거 재사용이 없어야 한다.

## Goal 4 — 문단 독해와 복합 관계 추론

**설정할 목표 문장**

> 문단의 사건·상태·분류·비교·원인·조건을 근거가 보존되는 구조로 합성하고 기존 추론기에 연결하여, 표현과 참여자가 달라진 새로운 문단에서도 여러 전제를 조합한 답과 정확한 이유를 내도록 구현·검증한다.

**사용자가 체감할 결과**

- `유진은 버스가 고장 나서 회의에 늦었다`에서 지각 이유를 해당 고장 사건에서 찾는다.
- `해나는 세림보다 작고, 세림은 보라보다 작다`에서 해나와 보라의 비교를 도출한다.
- `모든 라젠은 티몬이다 … 도미는 라젠이다` 같은 새 이름의 분류 사슬에서 선언된 결론을 도출한다.
- 두 장소의 같은 종류 물건, `모두 옮겼다`의 이동량과 출발/도착 상태를 구별한다.
- 조건·부정·예외·질문이 섞여도 근거가 없는 결론을 확정하지 않는다.

**할 일과 완료 조건**

- 정답 구조 직접 입력과 자연어 입력을 함께 검증한다. 코어의 결합/범위/증명 문제도 여기서 고치며 파서 탓으로만 돌리지 않는다.
- 글에 명시된 원인 진술, 논리적으로 도출한 관계, 상식으로 추측한 원인을 구별한다. 같은 인물의 다른 사건에서 이유를 가져오지 않는다.
- 필요조건/충분조건, 명시 부정/미확인/상충을 구별하고 대우 등 허용 추론은 선언한 논리 계약에 따른다. 증거가 없다는 이유만으로 부정을 생성하지 않는다.
- 단일 예문 암기가 아닌 역할·술어·절 순서·전제 조합이 다른 평가에서 필수 결론과 근거가 맞아야 한다. 전제를 빼면 그 전제에만 의존한 결론이 사라진다.
- 질문에 맞는 짧은 답, `왜?`, `어느 문장을 근거로?`를 같은 proof에서 표현한다.

**첫 큰 점검 지점:** Goal 1~4 종료 시 사용자가 새로 써 본 일상 문장으로 해석·대화·독해를 다시 평가한다. 이름을 바꾼 문항에만 성공하거나 처음 보는 구조에 계속 실패하면 곧바로 감정/자율성 기능으로 넘어가지 않는다. 실패 계층과 적용 범위를 재점검하고 다음 변경을 그 원인에 맞춘다.

## Goal 5 — 시간·네 영역·세 기억을 하나의 대화로 잇기

**설정할 목표 문장**

> Quantity·Location·Social·Mental의 사건과 시간·관점을 같은 추론 계약으로 처리하고, 실제/과거/계획/가정/믿음을 구별하면서 Episodic·Semantic·Procedural 기억을 질문과 행동 판단에 실제로 사용하게 한다.

**사용자가 체감할 결과**

- `지금 책은 어디에 있나`, `옮기기 전에는 어디 있었나`, `민지는 어디 있다고 믿나`가 서로 다른 근거로 답해진다.
- 뒤늦게 알려진 과거 사건이 현재 상태에 정확히 반영된다. 타인의 잘못된 믿음이 실제 위치를 덮어쓰지 않는다.
- `어제 무슨 일이 있었나`, `일반적으로 아는 것은`, `그 행동은 어떻게 하나`가 해당 기억을 조회한다.

**완료 조건**

- 네 영역에서 같은 Event/Condition/Hypothesis·proof 경로를 사용한다. 최소 세 영역에 동일 구조의 변형/대조를 적용하고 Mental까지 공통 코어 검증에 포함한다.
- 역할 보완, 과거 정정, 계획/가정, 믿음 갱신, 독립 근거, 행동 조합을 검사한다. metadata나 별도 mental 목록에 저장하는 것만으로 완료하지 않는다.
- 장기 기억과 작업 기억의 수명을 구별한다. 경험 압축 후 필요한 요약/원천/revision이 남고, 근거 정정 시 의존 지식만 철회된다.
- 과거 판단 당시의 이유와 지금 재판단한 이유를 구별하여 재시작 후 보여준다. 영구 로그·검색·snapshot과 개체 격리는 실제 시나리오에서 확인한다.

## Goal 6 — 대화로 가르친 표현과 지식을 다음 대화에서 사용

**설정할 목표 문장**

> 모르는 표현과 관계에 대한 사용자 풀이·교정을 기존 의미 구조에 근거 있게 정렬하고, 별도 검증을 통과한 표현/지식만 저장하여, 원문과 다른 새 문장 및 새 프로세스의 대화에 재사용하게 한다.

**사용자가 체감할 결과**

- 지원되는 수량 맥락에서 `뺐어는 꺼냈다는 뜻이야`라고 가르친 뒤 다른 물건·수량·말투에서도 이해한다.
- 가르친 관계를 새 인물이나 새 사건에 적용하고, 왜 그렇게 해석했는지 가르친 원천을 보여준다.
- 잘못 가르친 내용을 정정하면 해당 해석/결론만 갱신한다. 모르는 표현을 매번 다시 가르치지 않아도 된다.

**완료 조건**

- 표현을 배우는 것, 사실을 기억하는 것, 규칙을 배우는 것을 구분한다. 예문 답 저장을 의미 학습으로 보고하지 않는다.
- 수량·상태·행동과 부정/계획/가정에서 의미가 뒤집히지 않는지 확인한다. 한 맥락에서 배운 동의 표현을 모든 맥락에 무조건 적용하지 않는다.
- 후보/검증/활성화/충돌/철회와 근거/버전을 보존한다. 학습 ON/OFF에서 새로운 문장의 실제 해석·답이 달라져야 한다.
- 같은 학습 문장 재시험이 아니라 별도 문장과 반례, 저장/복원, 팩 이동에서 재사용이 확인돼야 한다.
- 이 단계는 사람이 가르친 학습이다. 스스로 개념을 발견했다고 보고하지 않는다.

## Goal 7 — 여러 경험에서 새 개념과 구조를 학습

**설정할 목표 문장**

> 최소 세 개의 독립 경험에서 역할·관계·조건·효과의 공통 구조를 후보로 만들고, 별도 경험에서 검증한 뒤 새로운 사건의 추론에 사용하며, 반례와 맥락 변화에 따라 개념 및 node/edge/rule 변경을 조정·철회하도록 구현한다.

**사용자가 체감할 결과**

- 처음에는 판단 근거가 없던 새 사건에 대해, 과거 경험에서 검증한 구조로 관계를 판단하고 이유를 설명한다.
- 단어 이름이 다른 행동에서도 실제 구조가 같으면 배운 범위 안에서 재사용한다. 겉말만 같고 효과가 다른 사건은 잘못 묶지 않는다.

**완료 조건**

- 후보 구성/별도 검증/활성 후 적용/독립 평가를 분리한다. 같은 사건 재생이나 자기 답변은 독립 support가 아니다.
- 사람이 제공한 행동 의미·기본 공리와 경험에서 배운 구조를 별도 집계한다. concept ID 출력이나 `instance_of` 재표현만으로 후속 추론 완료를 선언하지 않는다.
- 동일 관찰·기본 지식에서 새 구조 OFF/ON을 비교한다. ON에서 새 문제의 답과 근거가 개선되고 OFF에서 그 근거만 사라져야 한다.
- scope/confidence/version/반례를 보존하고 node/edge/rule 변경의 제안→검증/승인→적용→benchmark→rollback을 같은 이력으로 추적한다.
- 기존 지식을 이용한 답에 학습 개념 이름만 덧붙이는 방식, 이미 알려 준 정답 관계를 발견으로 집계하는 방식은 실패다.

## Goal 8 — 관찰 결과가 다음 행동과 학습을 바꾸는 자율 루프

**설정할 목표 문장**

> 초기 목표·환경·허용 기능·예산을 설정한 ALMA가 관찰·기억 조회·정보 공백 판단·행동 선택·결과 확인·학습·다음 행동을 스스로 연결하고, 중단과 실패 후에도 실제 근거와 실행 이력을 유지하며 경험을 이어가게 한다.

**사용자가 체감할 결과**

- 목표 수행에 정보가 부족하면 적합한 읽기 기능을 골라 확인하고, 결과에 따라 계획을 바꾼다.
- 도구가 실패하면 다른 허용 행동이나 이유 있는 보류로 이어진다. 사람이 매 스텝의 행동 목록과 정답을 공급하지 않는다.
- 새 관찰이 있을 때 학습하고, 같은 자료만 반복되면 지식/확신을 부풀리지 않는다.

**완료 조건**

- 기존 ALMA 환경/선택/capability 구현을 검증해 재사용한다. 적합한 도구와 무관한 도구가 함께 있을 때 선택 계약이 작동한다.
- 도구 출력이 로그에만 쌓이지 않고 후속 전제/목표/판단을 바꾼다. 환경 내부의 숨은 정답을 읽지 않는다.
- 예산 중단, 새 프로세스 재개, 일시 실패, 실행 불확실 상태, 중복 요청, 도구 교체를 다룬다. 실제 외부 write/execute 승인 게이트는 유지한다.
- 같은 경험을 받은 학습 OFF/ON과 고정 행동 재생 대조를 비교하여 학습이 기여한 부분을 분리한다. 반복 횟수나 목표 하나의 달성만으로 지식 증가를 주장하지 않는다.
- 로컬 환경으로 완료할 수 있어야 한다. 실제 계정·웹 서비스·외부 비용이 선행 조건이 아니다.

## Goal 9 — 경험에 근거한 감정·취향·자발적 목표

**설정할 목표 문장**

> 실제 관찰과 목표·관계·손실 예상·통제 가능성에서 감정의 원인 상태를 만들고, 그 경험과 기억에서 형성된 맥락별 선호와 하위 목표가 이후 선택을 바꾸며, 원인 해소와 반례·정정·재시작에 일관되게 갱신되도록 한다.

**사용자가 체감할 결과**

- 같은 사건이라도 목표와 관계가 다른 개체는 다른 반응/선택을 보인다.
- 유용한 것과 경험상 좋아하는 것이 다를 수 있고, 왜 그런 선택을 했는지 과거 경험으로 설명한다.
- 위협이 없어지면 감정 상태도 바뀌고, 잘못된 경험 해석을 정정하면 선호가 갱신된다.

**완료 조건**

- 호출자가 `threatened=True`나 `affect_label`을 넣어 선택을 바꾸는 데모만으로 완료하지 않는다. 존재하는 관련 사건과 인과 경로를 검증한다.
- 감정 원인 계산에 실제로 사용한 전제와 단순 저장 필드를 구별한다. utility/preference/confidence는 독립된 의미로 유지한다.
- 중복을 제외한 경험량·일관성·반례·맥락에 따라 confidence와 선호가 달라지는 비교를 수행한다.
- 관찰된 미충족 목표/정보 공백에서 다음 행동/하위 목표가 유도되고, 목표 달성은 관련 결과가 충족 조건을 지지해야 한다.
- milestone은 실제 조건과 근거를 확인하고 시험 fixture와 실제 관찰을 구분한다. 죽음의 공포나 존재 질문이 반드시 나오도록 심지 않으며 의식의 증거로 보고하지 않는다.

## Goal 10 — 실제 추론 가속과 장기 운영·최종 전달

**설정할 목표 문장**

> 검증된 공통 추론과 경험 루프의 반복 proof를 안전하게 압축하여 실제 반복 비용을 줄이고, 장기 저장·검색·교정·개체 격리·자산 이동을 검증한 뒤, Addition의 전체 완료 조건을 실행 가능한 코드·팩·개인 상태·원시 결과로 전달한다.

**완료 조건**

- 실제 판단에서 반복 경로를 자동 발견하고 독립 관찰을 센다. 일반 `turn()` 경로에서 사용하며 필수 중간 전제·시점·양태·버전을 보존한다.
- target 한 개뿐 아니라 독립 분기·다른 질문·후속 규칙의 결론과 증명 의미를 보존한다. 변경/반례에 자동 비활성화하고 원 경로로 돌아간다.
- 매번 원 추론과 압축 추론을 둘 다 수행하고 후자만 재는 식으로 비용을 줄였다고 보고하지 않는다. 준비/검증/반복/설명 복원/전체 비용과 메모리를 나눠 같은 조건에서 비교한다.
- 여러 에피소드 누적 시 저장/검색/재판단 비용과 자원 상한을 측정한다. 단순히 에피소드 수만 늘린 통과 검사가 아니라 상태·근거·철회의 정확성을 함께 검사한다.
- 공유 지식팩과 개인 경험/목표/선호 상태를 분리해 내보내고, 호스트의 느슨한 파일 없이 깨끗한 별도 실행 환경에서 복원한다.
- 자연어 학습→새 경험→개념/규칙 재사용→교정→재시작→다음 경험이 이어지는 통합 시나리오, 모든 단계의 원시 보고와 최종 회귀를 제공한다.

## 단계별 보고 형식

각 goal의 최종 보고는 다음 질문에 답해야 한다.

1. 사용자가 전에는 못 하던 어떤 대화를 이제 할 수 있는가? 실제 입력과 수정 전/후 답은 무엇인가?
2. 의미 해석·문맥·추론·표현 중 무엇이 바뀌었는가? 기존 부품을 어떻게 재사용했는가?
3. 기존 예문 외의 어떤 새 표현/역할/구조에서 성공했고 무엇은 실패했는가?
4. 정답·필수 근거·금지 근거·보류·오류를 어떻게 확인했는가? 학습 효과가 있다면 OFF/ON 차이는 무엇인가?
5. 최종 코드/팩/자료/상태와 재현 명령, 비용, 알려진 제한은 무엇인가?
6. 해당 goal의 필수 조건이 모두 충족됐는가? 다음 goal에 필요한 전제는 준비됐는가?

## 실행 요청 방법

현재 실행 중인 작업의 결과가 나온 뒤 다음처럼 요청한다. 첫 goal은 최신 결과 검증이므로 이미 구현된 사항을 반복 개발하지 않는다.

> `docs/ko/2026-09-20-goal-roadmap.md`의 공통 규칙과 Goal 1을 읽고, 그 범위만 현재 goal로 설정해 구현·검증해줘. 최신 변경을 먼저 확인하고 해결된 부분은 재사용해. 다른 goal이나 ALMA 전체의 완료로 확대하지 말고, Goal 1의 완료 증거와 다음 단계 진입 조건을 남겨줘.

이후 Goal 번호를 바꿔 같은 방식으로 실행한다. 각 goal의 필수 전제를 확인하며, 앞 단계의 완료 보고만 믿고 검증되지 않은 능력을 전제로 삼지 않는다. 후속 코드에서 앞 단계 회귀가 발견되면 그 회귀를 함께 수정한다.

이 로드맵은 계획 산출물이며, 작성만으로 새 goal이나 자동 실행/예약 작업을 만들지는 않는다.
