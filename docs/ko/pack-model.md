# 팩 모델 — kgpack v3의 언어팩·공리팩

2026-09-11. `kgpack` 형식을 3으로 올리고 manifest에 `model` 선언을 추가했다.
팩 하나가 자기 추론에 필요한 언어와 공리를 스스로 들고 있게 만드는 변경이다.
얼린 잣대는 한 줄도 움직이지 않았다.

## 무엇이 문제였나

추론에 필요한 자료가 팩 밖과 지식 그래프 안에 흩어져 있었다.

| 자료 | 있던 곳 | 문제 |
|---|---|---|
| 관계 추론 예시·수사·답말끝 | `data/semantic/relations.json` | 팩에 안 들어간다. 팩만 받은 쪽은 못 쓴다 |
| 연산 허가·추론 규칙 | `graphs/graph_일상추론.kg`의 `[공리]` | 지식팩 하나에 공리가 숨어 있다. 파일 이름이 코드에 박혀 있다 |
| 문장 나누기·말수식·출력 꼴 | 파이썬 코드 | 언어를 바꾸려면 코드를 고쳐야 한다 |

`relations.json` 한 파일 안에 언어(수사, 답말끝, 예시)와 공리(규칙, 셈 갱신)가
같이 들어 있었다. 언어를 바꾸면 공리가 따라오고, 공리를 바꾸면 언어가 따라왔다.

## 세 겹으로 갈랐다

```
kgpack
├─ graphs/*.kg          지식팩    — 한 분야의 지식
├─ graphs/*.학습.jsonl  지식팩    — 대화하며 늘어난 지식
├─ styles/*.json        언어팩    — 그 언어로 어떻게 알아듣고 어떻게 말하나
└─ axioms/*.json        공리팩    — 무엇을 계산해도 되고 무엇이 무엇을 함의하나
```

manifest는 이 중 어느 것을 쓸지 한 번만 고른다.

```json
"model": {"format": "nai-model", "version": 1,
          "language": "styles/한국어.json",
          "axioms": ["axioms/core.json"]}
```

언어팩이 여럿이면 `default_model_language: true`가 붙은 것을 고르고, 그것도
없으면 팩을 만들 때 `select_model_language_explicitly`로 거절한다. 고르지 않은
언어팩도 팩 안에는 그대로 들어간다 — 쓰지 않을 뿐 버리지 않는다.

`relations.json`은 해체됐다. 언어 쪽은 `styles/한국어.json`의 `관계해석`으로,
공리 쪽은 `axioms/core.json`으로 갔다. `data/semantic/`은 비었다.

### 겹침 금지는 코드가 지킨다

언어팩에 공리 이름(`rules`, `operators`, `mutable_predicates`, `numeric_updates`)이
들어 있으면 팩을 만들 때 `axioms_must_not_be_in_language_component`로 터진다.
두 겹이 다시 섞이는 것을 사람의 주의력에 맡기지 않는다.

## 팩 밖에서 빌려오지 않는다

`PackModel`은 선택된 자산만 본다. 선언에 없는 것은 **빈 것**이지,
다른 데서 찾아오라는 요청이 아니다.

- 작업 폴더의 느슨한 파일을 읽지 않는다
- 환경변수의 언어 설정을 따르지 않는다
- 같이 돌고 있는 다른 팩의 것을 쓰지 않는다

`tests/test_pack_model.py`는 `development_model`을 `AssertionError("host fallback")`으로
바꿔놓고 네 군데에서 확인한다. 팩 밖에서 몰래 읽으면 시험이 깨진다.

느슨한 소스 트리로 작업할 때 쓰는 `development_model()`은 따로 있다. 이것은
**선택된 팩이 쓰는 대비책이 아니라** 저작 도구다. 팩 만들기가 포함하는 바로 그
파일들을 같은 방식으로 읽고, 파일 수정 시각을 따라 캐시를 갱신한다.

## 근거에 모델이 따라 붙는다

답에는 어느 자산으로 계산했는지가 같이 나온다.

```json
"verification": {
  "checks": [{"operator": "arithmetic", "ok": true}],
  "sources": [{"path": "styles/한국어.json", "sha256": "..."},
              {"path": "axioms/core.json",  "sha256": "..."}],
  "model": "68a88ced2fc5febf...",
  "model_assets": [...]
}
```

`model`은 자산 경로와 해시를 정렬해 만든 지문이다. 같은 답이라도 다른 언어팩이나
다른 공리팩으로 나온 것이면 지문이 다르다. 답이 어떻게 나왔는지를 팩 단위까지
되짚을 수 있다.

`arithmetic`과 `relational_graph`는 넘겨받은 구조를 믿지 않는다. 근거 문장을
다시 파싱해 같은 구조가 나오는지 맞춰보고, 다르면 `expression_not_grounded`
또는 `relations_not_grounded`로 거절한다.

## 공리팩이 없으면 옛 길로

v2 팩은 그대로 읽힌다. 읽을 때 `model` 선언이 없으면 빈 모델로 본다.

```
language = None,  axioms = []
permits("arithmetic") → False
```

`permits`가 거짓이면 새 추론 경로를 타지 않는다. 새 길이 없던 때처럼
그래프 고르기로 답한다. 옛 팩은 새 계산을 잘못 하는 대신 안 한다.

`graphs/graph_일상추론.kg`의 `[공리]` 절을 읽던 경로도 남아 있다. 모델이 없을
때만 쓴다. 새로 만드는 팩은 이 경로를 타지 않는다.

## 그 밖에 함께 바뀐 것

- `graphs/*.학습.jsonl`이 팩에 들어간다. 대화하며 늘어난 지식이 팩과 함께 옮겨진다.
- overlay에 이미 있는 `.학습.jsonl`은 팩의 것으로 덮어쓰지 않는다. 팩을 다시 열어도
  그 사이 늘어난 지식이 지워지지 않는다.
- manifest에 같은 경로가 두 번 나오면 읽기를 거절한다.
- UI는 `AppState`에서 `PackModel`을 만들어 파서·언어팩·출력 꼴에 넘긴다.
  이름이 정해진 특정 그래프를 찾아가지 않는다.

## 아직 아닌 것

- `대화이해.phrases`는 여전히 네 개짜리 대응표다. 팩 안에 있게 됐을 뿐,
  인사말을 계산해 만들지는 않는다. `graph_대화예절.kg`와 겹치는 것도 그대로다.
- `axioms/core.json`의 규칙은 세 개다. 연산 이름 아홉 개는 허가 목록이고,
  실제 계산은 코드에 있다. 공리팩이 규칙을 늘려도 새 연산을 만들지는 못한다.
- 영어 언어팩에는 `관계해석`이 없다. 새 추론 경로는 아직 한국어에서만 돈다.
