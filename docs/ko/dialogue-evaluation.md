# 실제 대화 진입점 평가 — 2026-09-10

`KG_ENCODER=문자 python bench/dialogue_evaluation.py --output 결과.json`은 기존
`reasoning_transfer_v1.json` 16문항을 각각 독립된 대화에서 `AppState.turn`에 전달한다.
질문만 실행 경로에 제공하며 정답은 평가기에만 남는다. 결과는
`data/benchmarks/dialogue_evaluation_current.json`에 저장했다.

현재 8/16 통과다. 실패 8개 중 7개는 웹 조사로 넘어가며, 하나는 계산값 11을
맞히지만 '숫자만' 지시를 지키지 않고 '11입니다.'로 답한다. 주요 실패는 자연어
방정식, 한글 수사, 수식어가 붙은 복수 개체, 불충분한 비교, 역추론 및 원인 독해다.
이는 현재 상태가 여전히 제한적인 구조 추론 시스템임을 보여 준다.

측정 범위는 일상추론 KG 하나를 포함한 임시 팩과 오프라인 Python UI 처리 경로다.
브라우저 렌더링·전체 지식 팩·실제 웹 품질은 평가하지 않는다. 웹 조사 호출은
빈 결과로 대체하고 호출 수를 기록한다. 로컬 추론 문제를 웹으로 넘긴 경우는
통과시키지 않는다. 따라서 기존 `engine.answer` 점수와 직접 비교하면 안 된다.

이 실행의 문항별 중앙 시간은 4.712ms였다. import 이후 팩 생성·앱 초기화의
Python 할당 피크는 1,547,366B, 별도 세 턴 수량 대화의 할당 피크는 1,752,192B였다.
tracemalloc 측정이며 전체 RSS가 아니다. 초기화 시간은 추적 오버헤드를 포함한다.
시간과 저장량은 장비와 대화 기록 크기에 따라 달라진다.

## 승인 재실행 수정

검토 중 `GoalRuntime.approve`가 실행한 행동을 기억하지 않아 같은 계획을 재승인하면
성공·실패와 무관하게 작업을 다시 실행하는 문제가 확인됐다. 이제 세션·계획·행동별
결과를 기록하고 중복 승인에는 `executed`를 비우며 `already_executed`로 이전 결과를
돌려준다. 동시 승인은 잠금으로 직렬화한다. 실패한 작업을 다시 시도하려면 새 계획을
만들어야 한다. 직접 승인을 받지 못해 실행하지 않은 행동은 소비하지 않는다.

이 보장은 같은 런타임 인스턴스 안에서 적용된다. 계획 자체가 메모리에 있으므로
프로세스 종료 중 외부 효과와 결과 기록을 원자적으로 보장하는 영속 작업 큐는 아니다.
성공·실패·예외와 동시 승인, 직접 승인 보류를 포함한 테스트 4개가 통과했다.

전체 목표는 미완료다. 이번 종합 진단에서 드러난 표현·독해·지시 이행의 부족을
해결하고, 더 넓은 별도 평가 및 실제 지식 검색 경로 검증을 이어가야 한다.
