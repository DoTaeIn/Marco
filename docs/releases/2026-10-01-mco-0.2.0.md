# mco 0.2.0 (draft)

Draft release notes for the second `mco` release. Not published: 0.1.0 is the
version on PyPI. `mco/_version.py` says `0.2.0` on the branch that prepares the
MARCO 1 release. The files are built and uploaded by the repository's release
workflow (`.github/workflows/publish.yml`) when a GitHub release tagged
`mco-v0.2.0` is published; their names and sizes are added here then.

## What is new

0.2.0 is the package side of the MCO storage infrastructure that the owner
scoped into MARCO 1 ([freeze decision](../ko/2026-09-22-freeze-decision.md),
"MCO scope for MARCO 1"): the native binary file, the Persistent Overlay
Infrastructure and conversation snapshots. None of it makes MARCO change its
own knowledge.

| Part | What | Documents |
| --- | --- | --- |
| MCO Format 1.1 | `mco.compile(..., format="native")` and `mco compile --format native` write the binary file: header, checksummed table of contents, manifest with `content_sha256` and build id, stable ids, and every graph as node and edge tables and the rules as a rule table. The `mco-native` backend runs it. The engine still parses the graph source text kept in the file when the model opens; the tables are not on the running path | [format-1.md](../mco/format-1.md) |
| Overlays | `mco.create_overlay`, `mco.open_overlay`, `mco.overlay_status`, `mco.Overlay`, the delta builders in `mco.overlay`, `mco.load(..., overlay=)`, `mco.inspect(..., overlay=)`, and `mco overlay`. Graph and rule changes stated or approved from outside, each naming its approver, used from the next turn with no recompile; the model file is never written | [overlay.md](../architecture/overlay.md) |
| Snapshots | `Session.snapshot`, `Model.resume`, `mco.load(..., snapshot=)`, `mco.inspect_snapshot`, `mco.SnapshotInfo`, `mco snapshot`, `mco run --resume`, `mco inspect SNAPSHOT`. A conversation written to one file and continued in another process, bound to the model's content and build id | [snapshot.md](../architecture/snapshot.md) |

## API version 1, compared with 0.1.0

Compared against the tag `mco-v0.1.0` (`git show mco-v0.1.0:mco/__init__.py` and
the other modules): `mco.__all__`, the signature of every exported function and
the public methods of every exported class (`inspect.signature`), the `Result`
fields, the `Status` values, the `Capability` names, the error classes and
their bases, and the CLI subcommands, flags and exit codes (the argument
parser of `mco.cli`). `tests/test_mco_package.py::test_public_names_keep_every_0_1_0_name`
pins the 35 names of 0.1.0.

**Nothing in API version 1 was removed, and no stable name changed its
meaning.** All 35 names of 0.1.0 are exported. No parameter was removed or
reordered; every new parameter is keyword-only with a default. `mco/result.py`
is byte-identical to 0.1.0, so `Result`, `Status`, `Evidence`, `EvidenceList`,
`Trace`, `TraceStep`, `Fact` and `ReasoningInput` are unchanged. The eleven
0.1.0 error classes keep their bases. Every 0.1.0 subcommand and flag is still
accepted, with the same exit codes.

### Behaviour that differs, on native files only

0.1.0 wrote no native file and refused every one; its `mco-native` backend was a
placeholder whose docstring said a later release would replace it behind the
same contract. These differences follow from that replacement:

| Case | 0.1.0 | 0.2.0 |
| --- | --- | --- |
| `mco.load` on a valid MCO Format 1 file | `UnsupportedFormatError` | runs it on `mco-native` |
| A recognised native file of a newer major version, or with an unknown required chunk or feature | `inspect`: `runnable=False`; `load`: `UnsupportedFormatError` | the same |
| A file that starts with the native magic but is not a valid Format 1 file | `inspect` described it (`runnable=False`, `format_version=None`) | `inspect` raises `ModelFormatError` (`test_native_format_is_recognised_but_unsupported`) |
| `available_backends()["mco-native"]` | always `(False, ...)` | `(True, "")` when a MARCO checkout is found |
| `mco inspect` text output for a native file | the same rows as for a compat file, most of them empty | the format as `vMAJOR.MINOR`, the manifest, the table counts and every chunk; the output for a compat file is unchanged |

Two changes are in fields the contract marks not stable: `ModelInfo.manifest`
of a native file holds the Format 1 manifest, header and chunk list, and
`Evidence.detail` carries `origin` for an item that came from an overlay.

## What it needs

Unchanged from 0.1.0: Python 3.10 or newer, no dependencies for `import mco`,
`mco.inspect()`, `mco inspect` and `mco backends`; `pip install "mco[marco]"` and
a MARCO checkout for running a model, an overlay or a snapshot. A native file
carries the knowledge; the engine code still comes from the checkout.

## What it cannot do yet

- Run without MARCO: the engine is not on PyPI.
- Read the tables on the running path: the engine parses the graph source text
  kept in a Format 1.1 file when the model opens.
- Hold an overlay or a snapshot inside the model file; consolidate an overlay into
  a new model; compact an overlay; take more than one overlay writer at a time;
  add a whole graph through an overlay ([overlay.md](../architecture/overlay.md)).
- Change rules outside the base rule table through an overlay.
- Keep an unfinished knowledge-graph dialogue across a snapshot resume; the
  question is asked again ([snapshot.md](../architecture/snapshot.md)).
- Take structured facts in `reason()` with the MARCO backend
  (`UnsupportedInputError`), as in 0.1.0.
- Run on Windows: not run there.
