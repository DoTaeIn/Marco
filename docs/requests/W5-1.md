# W5-1: the meaning fields the plan for two questions in one turn reads (G5.6)

From: goal W5 (realizer round 5), branch `realizer-r5`.
For: goal G5 (understanding round 5), branch `understanding-r5`, which owns the reading of a
turn with several questions (Diairesis, G5.6) and the `meaning` block it returns. W5 changes
none of that; this names what the reply plan reads, so the two sides meet. If G5 records the
turn differently, a `G5-<n>.md` saying how is enough: the plan is a declaration in
`marco/language/realizer/meaning.json` (the first entry of `turn_plans`).

## What the realizer says

| Meaning | English | Korean |
| --- | --- | --- |
| two counts | Oda has 3 plums and Tove has 2 pears. | 오다는 3개, 토베는 2개입니다. |
| a zero and the user | Oda has no plums. You have 4 plums. | 오다는 하나도 없습니다. 4개 있으십니다. |
| an answer and a hold | Oda has 3 plums. This conversation never mentioned Tove's pears. So I did not answer. | 오다는 3개입니다. 이 대화에서 토베 배에 대한 말은 나온 적이 없습니다. 그래서 답하지 않았습니다. |
| an answer and a total | Oda has 3 plums. Oda and Tove have 7 plums together. | 오다는 3개입니다. 오다와 토베는 합쳐서 자두 7개입니다. |

Each answer is said by the plan it would have as a turn of its own, in the order asked, and
names whose it is (the answer ellipsis of a single question does not apply). Consecutive count
answers share one sentence. Every clause is read back by the pack as usual. If any one answer
has no plan (a reason nobody declared), the whole turn is the declared hold, never a part of it.

## Fields asked for

```json
{"act": "inform", "kind": "queries",
 "answers": [
   {"status": "answered", "act": "inform", "query": ["Oda plums", "count", "?n"],
    "asked": ["Oda plums", "count", "?n"], "fact": ["Oda plums", "count", "3"],
    "evidence": {"turn": 0, "start": 0, "end": 18, "text": "Oda has 3 plums", "source": "..."}},
   {"status": "unresolved", "act": "hold", "reason": "not_stated", "subject": "Tove pears"},
   {"status": "answered", "act": "inform", "kind": "total", "subjects": ["Oda plums", "Tove plums"], "value": 7}
 ],
 "holders": {"...": {"kind": "place"}}}
```

1. `kind: queries` and `answers`, one entry per question in the order the user asked them.
2. Each entry is the meaning block the question would carry as a turn of its own (every field
   the single-question plans read: `act`, `reason`, `kind`, `query`, `asked`, `render`,
   `subjects`, `value`, `values`, `winner`, `time`, `subject`, ...), plus its own `status`
   (`answered` / `unresolved`).
3. An answered triple carries `fact` (the triple the single turn has as its last
   `{"fact": ...}` transition) and `evidence` (the same row's evidence). These two are the
   answer's fact row (`answer_row` in the plan); its own evidence is kept per answer, so the
   ledger can record one conclusion per answer with its own sources (G5.6: "each with its own
   evidence"). The reply does not say the evidence.
4. `holders`, `conversation` and `conversation_language` stay on the turn's block; every answer
   shares them (`shared` in the plan).
5. The turn's `transitions` may carry every answer's fact: the plan for several answers is
   matched first, so the last fact is never said alone.
