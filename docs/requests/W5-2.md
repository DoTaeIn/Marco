# W5-2: the meaning fields the ask on ambiguous readings reads (G5 part B)

From: goal W5 (realizer round 5), branch `realizer-r5`.
For: goal G5 (understanding round 5), branch `understanding-r5`, which owns readings as
candidates (part B: every reading kept, checked against the conversation's state, ask when
several survive and differ in what they would record, hold when none does). W5 changes none
of that; this names what the reply plans read. If G5 records these turns differently, a
`G5-<n>.md` saying how is enough: the plans are declarations in
`marco/language/realizer/meaning.json` (`ambiguous_reading`, `no_reading`).

## What the realizer says

| Meaning | English | Korean |
| --- | --- | --- |
| two transfers | Did you mean that Wynn gave Pell 3 figs, or that Pell gave Wynn 3 figs? | 윤이 펠에게 무화과 3개를 줬다는 말씀인가요, 펠이 윤에게 무화과 3개를 줬다는 말씀인가요? |
| two counts | Did you mean that Wynn has 3 figs, or that Pell has 3 figs? | 민서는 무화과가 3개 있다는 말씀인가요, 도윤은 무화과가 3개 있다는 말씀인가요? |
| the user in one | Did you mean that Wynn gave you 3 figs, or that you have 3 figs? | 윤에게서 무화과 3개를 받으셨다는 말씀인가요, 무화과는 3개 있으시다는 말씀인가요? |
| readings not said one by one | "…" can be read in several ways. Please say which you mean. | "…"는 여러 가지로 읽힙니다. 어느 것인지 밝혀 주세요. |
| no reading fits | No interpretation of "…" fits this conversation. Please say it another way. | "…"는 이 대화와 맞는 읽기가 없습니다. 다른 말로 다시 말해 주세요. |

Each reading is said as one choice of a single question and read back by the pack before it
is asked (a reading the pack does not read back holds the reply); none is asserted and none
chosen. A reading is said only when it is one proposition: its one transfer, or its one stated
count or place. Fewer than two readings, a reading of several propositions, or two readings
that say the same: the question falls back to the second row above.

## Fields asked for

Several readings survive (the turn asks, status `unresolved`):

```json
{"act": "ask", "reason": "ambiguous_reading", "said": "<the user's sentence>",
 "readings": [
   {"changes": [<the rows this reading would record>]},
   {"changes": [<...>]}
 ]}
```

1. `readings`: one entry per surviving reading, in the order the constraints left them, each
   with `changes`: the state rows the reading would record, in the shape a record turn's
   `meaning.changes` has (`operation` `quantity_update` with `subject`, `predicate`, `before`,
   `after`, `delta`, `evidence`; or `state_update` with `after`). A transfer is the two rows of
   one event (same `evidence` span), one losing what the other gains.
2. `said`: the user's sentence, for the fallback.
3. Holders that are places or named keep the turn's `holders` field (W3-1).
4. What each reading was checked against and why the others were dropped belongs to the
   trace (G5.0 b), not to the meaning the reply is said from.

No reading survives (the turn holds, status `unresolved`):

```json
{"act": "hold", "reason": "no_reading", "said": "<the user's sentence>",
 "failed": [{"reading": 0, "constraint": "<declared constraint id>"}]}
```

`failed` is for the trace; the reply says only that no reading fits and asks again. If G5 wants
the reply to name the failing constraint, a request with the constraint ids is enough: each
needs one declared frame per language.
