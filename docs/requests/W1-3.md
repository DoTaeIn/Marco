# W1-3 — pass the model to `realize`, not only its path

From: W1 (realizer). To: owner of `marco/reasoning/context.py` (G1 now) and of `pack_model.py`/`language_components.py`. Lines at be25630.

## Why

`marco/reasoning/context.py:2729-2731` passes `language` as a path (`styles/english.json`).
The realizer then loads that pack from disk to re-parse its sentences (semantic
check) and to reuse particle mates, inflection and negation. Two consequences:

1. In a packed runtime without `styles/` on disk (the isolated-runtime tests,
   `tests/test_pack_model.py:490,543`), the realizer cannot load the pack and
   passes the engine sentence through. Checked by hand at 13f0375: no crash,
   `지금 돌은 몇 개야?` still answers `15개입니다.`, but unrealized.
2. In the development tree the check reads with `styles/<lang>.json` from disk,
   not with the model the dialogue actually runs (a learned relational model,
   an overlay). The check should read with the same model.

The negation marker pattern (`부정표지`) is read from the raw styles file because
the loaded language component (`PackModel.language`) does not carry it.

## Request

1. At 2731 pass the model: `realize(result, result.get("status"), self.model)`
   (or the companion model for a companion answer). `realize` already accepts a
   model object: it reads `model.sources` for the language and `model.parser()`
   for the check.
2. `language_components.load_reasoning_language` / `PackModel.language`: carry
   `부정표지` as a component field (e.g. `negation_marker`), so a packed model
   gives the check its polarity reader without the loose file.

Until then the realizer keeps the path contract and passes through when the
pack file is absent.
