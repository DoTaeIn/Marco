# W3-1: the meaning fields and pack readings the round-4 reply plans read

From: goal W3 (realizer round 3), branch `realizer-r3`.
For: goal G4 (understanding round 4), branch `understanding-r4`, which owns the
parsing side, the fields it puts in a result's `meaning` block, and `styles/*.json`.
W3 changes none of those; this names what its plans read, so the two sides meet.

No G4 request had landed in `docs/requests/` when these plans were written, so the
fields below are **assumed** from the round-4 goal file. If G4 records these
meanings differently, a `G4-<n>.md` saying how is enough: the plans are
declarations in `marco/language/realizer/meaning.json` and the two language files.

## What W3 composes (plans in `marco/language/realizer/`)

| Meaning (assumed) | English reply | Korean reply |
| --- | --- | --- |
| the user holds: key `I` / `나` (the pack's `임자자리말`) | You have 3 apples. · Now you have 3 apples and Ana has 3. · 3 apples. | 사과는 3개 있으십니다. · 이제 사과는 3개 있으시고, 아라는 3개입니다. · 3개 있으십니다. |

| a place: `holders[key] = {kind: place}` | The warehouse has 5 boxes. · Tove put 3 boxes in the warehouse. · Tove took 3 boxes from the warehouse. · 3 boxes were moved from the warehouse to the shed. | 북쪽 창고에는 5개 있습니다. · 토베가 북쪽 창고에 상자 3개를 뒀습니다. · …에서 …를 가져갔습니다. · 상자 3개가 …에서 …로 옮겨졌습니다. |

## Fields asked for in the `meaning` block

1. **`holders`**: `{<holder key>: {"kind": "speaker" | "place" | "named", "said": "<the user's words>"}}`
   for every holder key the turn's triples, changes, `subject`, `subjects` or `winner`
   use that is not a bare name.
   - `speaker`: the user. Not needed when the key is the pack's `임자자리말` (`I`, `나`):
     that key is the user by itself.
   - `named`: `said` is the user's own words for the holder (`Mr. Lind`, `Lind's cousin Ana`,
     `my roommate Ana`, `린드 씨`, `제 룸메이트 아나`). The key is whatever the triples use (`Lind`,
     `린드`). For an apposition (`the courier, Mr. Lind`) `said` is the short form a later turn
     uses (`Mr. Lind`), as the dev-v4 scenarios' `short` field has it. The user's own
     first-person words in it (my; 내, 제) are turned to the one addressed (your; not said).
   - `place`: `said` is optional (`the north warehouse`); without it English says `the <key>`.
   - A key of several words (`north warehouse`, `북쪽 창고`) is fine: the realizer splits a
     compound subject (`north warehouse boxes`) by the declared keys, longest first.
2. **Zero**: a count of zero is an ordinary count with the value `"0"` (a change's `after`,
   an answered fact `[… , "count", "0"]`). No new field.
3. **Vague counts**: a statement with no number, recorded: `{"act": "record", "reason":
   "vague_count", "subject": "<holder key> <item>"}` (status `observed`); a count question
   about it: `{"act": "hold", "reason": "vague_count", "subject": "<holder key> <item>"}`
   (status `unresolved`).
4. **Places in transfers**: the same `quantity_update` rows as between people; the place's
   key has `kind: place` in `holders`.

## Pack readings asked for (`styles/*.json`)

Every reply clause is parsed back with the pack before it is said, in a reading that
says each holder as the user would (the user in the first person, a named holder as
named). Until the pack reads a form below, the realizer says the plainer form where one
exists (a zero in digits: `0 plums.`, `0개입니다.`; a Korean place juxtaposed: `북쪽 창고
상자는 5개입니다.`) and otherwise holds the reply (the English first person, English
places, Korean titles). Read today: `I gave Ana 2 apples.`, `Ana gave me 2 apples.`
(`me` is accepted as the pack's first person), `나 사과는 3개 있다.`, `내가 아라에게 사과
2개를 줬다.`, `Mr. Lind has 4 pens.`

| Reading the check parses | Must give back | Today |
| --- | --- | --- |
| `I have 3 apples.` | `[I apples, count, 3]` | nothing (`I has` and `I had` are read) |
| `my` in the first-person group of `자리말` (with I, me, myself); `저`, `제` with 나, 내 | — | not declared |
| `The north warehouse has 5 boxes.` | `[north warehouse boxes, count, 5]` | nothing |
| `Tove put 3 boxes in the north warehouse.` | `count_remove` Tove, `count_add` north warehouse | nothing |
| `Tove took 3 boxes from the north warehouse.` | `count_remove` north warehouse, `count_add` Tove | nothing |
| `3 boxes were moved from the north warehouse to the south warehouse.` | both sides | nothing |
| `Tove has no plums.` | `[Tove plums, count, 0]`, not a denied count | nothing |
| `린드 씨 펜은 4개다.` | `[린드 펜, count, 4]` when the key is `린드` | `[린드 씨 펜, …]` |
| `북쪽 창고에는 상자가 5개 있다.` | `[북쪽 창고 상자, count, 5]` | `[북쪽 창고에 상자, …]` |
| `토베 자두는 하나도 없다.` | `[토베 자두, count, 0]` | nothing |
| `토베가 북쪽 창고에 상자 3개를 뒀다.` | both sides | nothing |
| `토베가 북쪽 창고에서 상자 3개를 가져갔다.` | `count_remove` 북쪽 창고 | `[창고에서 상자, …]` |
| `상자 3개가 북쪽 창고에서 남쪽 창고로 옮겨졌다.` | both sides | nothing |

No template string in `styles/*.json` has to change for these plans.

## Where the plans are tested

with the pack as it is (the plainer form or a hold, never an unchecked sentence) and
with a stand-in parser that reads the forms in the table as asked here.
