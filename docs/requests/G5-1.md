# G5-1: switch the engine sites' trace on from the recorder, and carry the gap into the turn's hold

From: goal G5 (understanding round 5), branch `understanding-r5`.
For: the owners of `views/kgpack_ui.py` (W5 this round) and of `marco/trace/` (the L1 line).
G5 changed neither; this names the two small edits that make G5.0's emission reach every recorded run.

## What G5 did (G5.0 a, b)

* `reasoning_context.ReasoningContext.trace` (class attribute, default `None`): the ledger the context
  writes its own events to. Each `turn` then writes one trace of its own (`source.type: engine_site`,
  `source.site: ReasoningContext.turn`, the input by digest): `routing_selected` (the path the turn took,
  with the readings it chose between), `rule_applied` per recorded state update (`operation.id` = the
  pack's rule, `count_add`, `count_remove`, ...; `payload.bindings` subject, before, after, delta,
  observation), `evidence_rejected` per statement it did not read (L1-1 B8), `hypothesis_rejected` per
  reading a constraint dropped, and on every hold of the context a `hold` with `payload.gap` in the seven
  classes (routing, lexical, concept, relation, parser, evidence, conflict), declared in
  `reasoning_context.GAP_CLASSES` (every reason the file gives; a test reads them).
* `engine.TRACE` (module attribute, default `None`): `pick_graph` writes `routing_selected` with the
  candidates and their scores and the threshold, and a `hold` (`below_threshold`, gap `routing`) when none
  passes (L1-1 B1); `judge` writes `rule_applied` (operator `judge`), `evidence_found` for the slots the
  verdict used, and `conclusion_created` or a `hold` with the verdict's gap (L1-1 B2). Node and graph
  names by digest.
* Request W4-1: `_explain_last` says the chain of `last_explainable(ledger, self.conversation_id)` when
  `trace` is set and the ledger has an explainable output of this conversation; otherwise unchanged.
* A recording error never changes a turn (a test).

## Asked

1. **`views/kgpack_ui.py`, `AppState.turn`** (or `marco/trace/drive.py` `record`, whichever records):
   when a ledger is on, set `context.trace = ledger` on the `ReasoningContext` the turn plays through
   (also a restored one) and `engine.TRACE = ledger` for the turn, and record the turn with
   `conversation=context.conversation_id` so `last_explainable` finds this conversation's outputs
   (W4-1 said the same). Today G5's measurements set `ReasoningContext.trace` and `engine.TRACE` from the
   measuring script around `drive.record`, so the context's why falls back to the engine's explanation
   there (the recorder's conversation name is the dialogue id).
2. **`AppState._said`**: the UI's own holds (`input_understanding_failed`, `no_graph_selected`, ...) have
   no engine event; `reasoning_context.gap_class(reason)` gives their class (`input_understanding_failed`
   and `no_graph_selected` are declared: parser, routing).
3. **`marco/trace/from_turn.py`, `record_turn`, step 8**: copy the gap into the turn's own hold, e.g.
   `payload["gap"] = reasoning_context.gap_class(reason)[0]` (or read it from the engine trace of the same
   input digest), so `python -m marco.trace stats` can count holds by gap class.
