# L1-1: emit trace events at the engine sites (round 5)

From: goal L1 (trace ledger core), branch `trace-ledger`.
For: the owners of the engine files after G4 and W3 merge (the second round of L1).
L1 does not own these files and changed none of them.

## Where things stand

`marco/trace/from_turn.py` builds each turn's events from the envelope that
`views.kgpack_ui.AppState.turn` returns, from outside. The driver
(`marco/trace/drive.py`) wraps `ReasoningContext.turn` and `AppState._said` to
keep the `meaning` block the envelope drops. What the envelope never carried
cannot be recovered that way: routing candidates and their scores, rejected
evidence, which rule fired with which bindings, and how a pointer was
resolved. Each line below names one site, the event it should emit, and what
the payload carries. Events go through `marco.trace.ledger.Ledger.append`, and
only when a ledger is on (`MARCO_TRACE_DIR` set or a ledger passed), so the
default run stays unchanged.

Every event keeps the rules the ledger already enforces: `parent_ids` name
earlier events of the same trace graph, a replaced value is a new event that
`supersedes` the old one, and nothing copies pack or graph text (ids, indexes
and digests only).

## Order

A1–A4 first: small, and they remove the two wrappers in `drive.py`. Then B3,
B6, B8 and B9: they carry most of what round 5 needs (rule bindings, pointer
resolution, and the unread statements that hold later answers).
