## What W4 provides

`marco/trace/explain.py`, no engine import at module level:

| Name | Does |
| --- | --- |
| `last_explainable(ledger_or_graph, conversation, before=None)` | the `output_created` id a bare "why" asks about: the conversation's last answer (a trace that concluded a fact) or correction (a trace with a `state_changed` on `observation:<k>`), before the event `before`; an engine explanation (check `explained_recorded_transitions`) and a hold are skipped; `None` when there is none |
| `chain_meaning(ledger_or_graph, output_id)` | the language-free meaning of that output's why chain: `act: explain`, `kind: chain` (or `chain_hold`), `statements`, `changes`, `rules`, `corrections`, `withdrawn`, `asked`, `facts`, `conversation_language` |
| `explain(ledger, event_id, language)` / `say_why(...)` | the same meaning composed by the default realizer (the CLI: `python -m marco.trace why <ledger> <event_id> --say ko\|en`) |

The realizer already plans `kind: chain` and `kind: chain_hold` (`meaning.json`, both
language files; `tests/language/test_w4_chain_plans.py`,
`tests/trace/test_trace_explain.py`). A result whose `meaning` is a chain meaning is
composed like any other reply: nothing else in the turn path changes.

## The change asked for

**File** `reasoning_context.py`, **function** `ReasoningContext._explain_last(self, parser, knowledge_path)`.
It is the one why site: `_follow_up` (bare 왜? / why), the `why_last` query rows in
`_turn_reply`, and `_explain_count` all end in it.

At its top, after `last = self.last_explanation` and the `explain_nothing` return:

```python
trace = getattr(self, "trace", None)          # the live ledger, set by the recorder (below)
if trace is not None:
    from marco.trace.explain import chain_meaning, last_explainable
    from marco.trace.why import Graph
    graph = Graph(trace)
    output = last_explainable(graph, self.conversation_id)
    if output is not None:
        result = <the result the method builds today>          # evidence, rules, changes, side effects
        result["meaning"] = {**chain_meaning(graph, output), "explains": last["kind"]}
        result["verification"]["checks"].append({"ok": True, "reason": "explained_trace_chain",
                                                 "output": output})
        return result
```

Keep everything the method does today (the evidence list, `rule_ids`, `last_mentioned`,
`salient`, `transitions`, the verification): only `meaning` is replaced, so the scorers,
the adapter (`from_turn`: `act: explain` still makes the conclusion an explanation) and
the pointer state behave as before. The realizer then says the chain; `result["answer"]`,
the engine's sentence, is never read while a plan matches.

**The recorder** (`views/kgpack_ui.py`, `AppState.turn`, wherever round 5 records a turn,
L1-1 A1–A4): when a ledger is on, set `context.trace = ledger` on the `ReasoningContext`
it plays the turn through (each `reasoning_contexts[context_id]`, also a restored one),
and record the turn with `conversation=context.conversation_id`, so that
`last_explainable` finds this conversation's outputs. The why turn itself is recorded
after `_explain_last` returns, so the output it explains is always an earlier one.

## Fallback when recording is off

`context.trace` is `None` (no ledger passed, `MARCO_TRACE_DIR` unset): `_explain_last`
runs exactly as today (`meaning.kind` `answer` or `correction`, the plans W1–W3 declared).
The same when the ledger holds no explainable output for this conversation (recording
turned on mid-conversation, a restored conversation whose earlier turns were never
recorded): today's meaning, unchanged. A ledger that cannot be read (`LedgerError`)
is the same fallback, never an error in the dialogue.
